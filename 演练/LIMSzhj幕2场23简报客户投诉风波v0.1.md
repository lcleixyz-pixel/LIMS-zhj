# LIMS-zhj 模拟试运行 · 幕2·场次2-3简报（客户投诉风波）

> 版本：v0.1　日期：2026-08-15（系统内）/ 2026-07-16（真实）　场次：2-3a（小张受理）、2-3b（赵姐调查处置）
> 承接：P1剧本"投诉风波"、《重要发现-核心检测出证业务模块缺失确认v0.1》

## 一句话结论

这场戏把"没有检测报告/样品模块"这条大发现，从"代码里查出来的事实"变成了"业务场景里活生生撞上的墙"：一位客户对检测结果提出异议，质量负责人赵姐认认真真按程序文件六项逐条去查，六项里四项直接查不到——因为压根没有原始检测数据能调。但这场戏最难得的地方是：**赵姐没有因为查不到证据就乱下结论**，该说"查不到"就说查不到，该排除嫌疑就排除嫌疑（她查出王小磊的设备授权生效日比争议检测日期还晚4天，合理排除了他），最后在证据不足的情况下做了一个站得住脚的决定——安排复检，而不是各打五十大板地"认栽"或者"甩锅"。这场戏也顺带把"客户投诉"和"CAPA"两个模块的编辑功能问题，做了第三个模块的独立确认。

## 1. 两场戏说了什么

**小张（2-3a）**：第一次接触"客户投诉"模块，成功登记了一条真实投诉（CP2026001，客户对检测结果的净度/成色异议）。过程很干净：一度以为系统拦了她的"新增"操作，查下来发现是自己脚本的选择器抓错了链接，不是系统问题——她如实排查清楚、诚实地没有把这条算成发现，这个自我纠错的动作本身值得记一笔。真正测出来的问题不少：投诉列表页三列失效、编号生成逻辑有拼接bug（"CP20262026002"这种）、"编辑"功能必然保存失败、最要命的一条——点"创建CAPA"按钮，界面显示"权限不足"操作失败，但数据库一查，CAPA其实已经真的建出来了，只是关联关系写错了，用户完全没法知道后台到底发生了什么。她全程用另建的测试记录做这些危险探测，确保交给赵姐的CP2026001完好无损。

**赵姐（2-3b）**：接手调查，按程序文件"六项核查"一条条来。设备、人员这两项能查到一些客观信息（三台设备当时的校准状态；全公司没有一个人对"净度/颜色分级"这项技术留有能力确认记录），但没法跟"这次具体检测"对上号；检测依据、方法、环境条件、数据处理这四项，因为系统里没有原始检测记录，直接查不到。最后的处置决定是"安排复检"——不是各打五十大板，而是精确引用了程序文件里"客户复检理由充分时应安排复检"这条独立表述，不需要先认定谁的错。她还主动放弃了"先开个不符合/CAPA保平安"这种取巧做法，理由是"责任没查实就先定性，等复检证明我们没错，还得撤销记录，这不负责任"。

## 2. 三个模块的编辑功能，现在是同一个病，查实了三次

之前在"不符合工作/CAPA"模块发现的问题（新增和编辑用两套不搭界的字段、编辑必然失败），这次在"客户投诉"模块原样复现了一遍——现在已经是**同一个架构缺陷，在三个不同模块（不符合工作、CAPA、客户投诉）里各自独立验证过一次**，说明这不是某个模块开发时手误，是搭这类"先登记、后处理"模块时反复踩的同一个坑，修的时候可能得一起修，不是挨个补。

这次还多了一个新变种，比之前更隐蔽：点"创建CAPA"按钮，界面告诉你"权限不足、操作失败"——**但实际上后台已经把数据写进去了，只是写错了**。这比"编辑保存失败"更麻烦：编辑失败至少界面如实告诉你失败了；这次是界面说失败、后台却真的动了数据，一般人根本没有办法知道系统骗了自己。

## 3. 新发现一览（不含印证）

**2-3a（小张，8条）**：A级2（编辑必然失败／创建CAPA显示失败实则写入错误数据）、B级4（列表页三列失效／编号拼接bug／删除未在详情页生效／全站无报告模块导致投诉调查缺基础数据）、C级1（责任人字段保存了但详情页不显示）、D级1（推进处理/创建CAPA这类应归质量负责人的操作，资料员账号未做权限区隔）。

**2-3b（赵姐，2条）**：B级1（两名员工邮箱字段完全相同，判断是陈思远的记录被误写成了张文静的邮箱）、D级1（《客户投诉处理通知单》XZTC/BG-14-02，记录模板库里连草稿都没有——这是继设备期间核查系列之后，第二条"连AI草稿都没排进补齐清单"的记录类型）。

## 4. 一处值得肯定的地方

赵姐这场的处置决定质量很高，值得专门说一句：证据不足的时候，她没有选"和稀泥"（各打五十大板），也没有选"死磕流程"（因为查不到证据就拒绝处理），而是找到了程序文件里一条不依赖"先定责任"的独立路径（客户复检理由充分即可安排复检），把决定立在了站得住脚的条款上，还把"这是低置信度的程序性决定，不是技术结论"这句话明明白白写进了系统记录里。这种"说得清楚自己判断的局限在哪"的表现，比单纯"流程走完了"更有价值。

## 5. 接下来怎么走

继续按你出发前的交代往下推进，不再逐场停下来问：

1. 客户投诉这条线暂时告一段落（复检结果需要等技术负责人重新安排人员，属于时间线上更靠后的事，先不快进去追这条尾巴，留着后续有机会再捡起来）。
2. 转向事件注入表里还没碰过的条目：人员离职交接、新法规发布。这两条能带出目前还没测过的模块（人事变更流程、法规监视模块——法规监视在幕0已经摸过底，这次可以真正走一遍"新法规进来后怎么处理"）。
3. 继续维持既定规矩不变。
