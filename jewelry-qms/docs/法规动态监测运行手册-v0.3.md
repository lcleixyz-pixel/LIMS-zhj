# 法规动态监测运行手册

| 项目 | 内容 |
|---|---|
| 文档版本 | v0.3 |
| 状态 | 现行实施验收版；待体验环境单独批准后启用 |
| 适用系统 | jewelry-qms 法规动态监测模块 |
| 业务时区 | Asia/Shanghai |

## 1. 用途与人工边界

本功能每月检查已批准的官方来源，将新发现或内容变化保存为隔离候选，按固定六类给出初步影响，再由质量负责人复核并决定是否建立正式外部变更事件。

这是“机器发现 + 确定性规则初判 + 人工决策”工具，不是自动合规结论或自动修订系统。候选、`no_match` 和晋升动作均不能代替适用性评价、文件修订、人员授权、设备校准、LIMS 规则调整、培训或最终批准。

本功能不自动备份或恢复数据库。体验、生产启用和真实数据迁移必须分别进入部署闸门；本文档本身不构成部署授权。

## 2. 已批准官方来源

| 来源 key | 官方来源 | 完整 HTTPS 入口 | 模式 |
|---|---|---|---|
| `samr_rkjcs_notice` | 国家市场监督管理总局认可检测司通知公告 | `https://www.samr.gov.cn/rkjcs/tzgg/index.html` | 官方 HTML 列表检查 |
| `cnas_lab_notice` | CNAS 实验室专门通知 | `https://www.cnas.org.cn/rkfw/sys/zxtz/index.html` | 官方 HTML 列表检查 |
| `cnas_lab_rules` | CNAS 实验室认可要求 | `https://www.cnas.org.cn/rkfw/sys/rkyq/rkzz/index.html` | 官方 HTML 列表检查 |
| `xinjiang_samr_notice` | 新疆维吾尔自治区市场监督管理局通知公告 | `https://scjgj.xinjiang.gov.cn/xjaic/tzgg/` | 官方 HTML 列表检查 |
| `cma_capability_query` | 检验检测机构资质认定证书查询 | `https://cma.caqit.org.cn/` | `manual_only` |

`manual_only` 表示系统只提醒人工查询，不发起 HTTP 抓取，也不绕过验证码、JavaScript 或官方访问控制。人工核查后，应保留查询时间、官方页面或结果、核查人和复核结论；未取得人工证据时，不得把提醒当作已完成核验。

页面不接受任意 URL；自动请求仅允许配置中的 HTTPS 官方主机。来源入口、主机或模式变更必须经过受控代码变更、复核和回归验证。

## 3. 角色权限

| 操作 | `admin` | `quality_manager` | 其他角色 |
|---|---:|---:|---:|
| 查看运行摘要、候选和官方证据 | 允许 | 允许 | 禁止 |
| 页面 DRY-RUN | 允许 | 允许 | 禁止 |
| 实际采集并保存候选 | 允许 | 禁止 | 禁止 |
| 保存人工复核 | 禁止 | 允许 | 禁止 |
| 晋升已确认相关候选 | 禁止 | 允许 | 禁止 |
| 导出单条脱敏 JSON | 允许 | 允许 | 禁止 |

晋升操作人只能取当前登录 Session，不能接受页面提交的人员、机构或事件编号。写操作受登录、RBAC、页面上下文和 CSRF 中间件保护；不得直改数据库绕过权限和审计。

## 4. 开关、调度与试运行

`REGULATORY_MONITOR_ENABLED` 默认是 `0`。关闭时月度任务不执行，法规监测页面返回 404，历史记录不会被删除。

启用后，容器定时任务每月 1 日 09:00 执行：

```sh
php /app/think qms:monitor-regulatory-changes --scheduled
```

日志位于容器 `/tmp/regulatory-monitor.log`；容器重建可能清空该文件，正式运行证据以 LIMS 中的 run、候选、通知和审计为准。

体验环境启用前至少完成：当次版本部署验证、数据库备份、恢复演练、迁移核对、权限核对和单来源 DRY-RUN。生产环境不得直接沿用体验环境批准。

页面 DRY-RUN 的建议顺序：

1. 管理员或质量负责人打开 `/planning/regulatory-monitor`。
2. 只选择一个健康来源，必要时填写起始日期。
3. 执行“DRY-RUN（不保存）”，核对解析、六类影响和运行提示。
4. DRY-RUN 回滚 run、候选和路由审计；确认无误后，才由管理员批准一次实际采集。

运维排查可使用：

```sh
php think qms:monitor-regulatory-changes \
  --source=samr_rkjcs_notice \
  --since=2026-01-01 \
  --dry-run
```

`--fixture-dir` 只允许在 `APP_ENV=test` 中使用，不是体验或生产数据导入方式。

## 5. 岗位操作链路

### 5.1 复核候选

1. 在候选清单按来源或复核状态筛选，进入详情。
2. 核对标题、文号、官方链接、发布/生效日期、内容指纹、版本链和六类影响。
3. 质量负责人选择“已确认相关”“已确认不相关”或“暂缓/待补证”，填写 2–1000 字理由。
4. 保存后核对复核状态、人员、时间和字段审计。

`no_match` 只表示当前规则未找到关联，不表示“不适用”。人工结论不得只复制机器初判。

### 5.2 晋升为外部变更事件

只有 `review_status=confirmed_applicable` 且尚未关联事件的候选，才向质量负责人显示“晋升为外部变更事件”按钮。管理员和其他角色看不到且不能调用该动作。

1. 质量负责人再次核对候选证据和复核理由。
2. 点击“晋升为外部变更事件”，在浏览器二次确认中确认。
3. 系统在单一事务内创建 `registered` 外部变更事件、更新候选关联并写一条原子成功审计。
4. 成功后跳转到关联事件；后续影响评估、修订和闭环仍须人工完成。

`pending`、`deferred`、`confirmed_not_applicable`、跨机构或不可见候选均必须拒绝。重复提交返回同一事件，不新增第二条事件或成功审计。失败时页面只显示统一安全提示，保留候选原状态，不留半成品。

已晋升详情页显示“查看关联变更事件”，不再显示晋升表单。

### 5.3 导出复核 JSON

候选详情页向 `admin` 和 `quality_manager` 显示“导出复核 JSON”：

```text
/planning/regulatory-monitor/export?id=<candidate-id>
```

文件名为 `candidate-<id>-review-packet-v1.0.json`。白名单数据包包含官方来源证据、固定六类影响、规则版本和复核状态，不整对象导出。

若候选字段包含密码、Cookie、Authorization、DSN、手机号、身份证号等敏感内容，导出整体阻断并返回 422。不得为完成导出而直接删改数据库证据。

## 6. 运行状态、通知和重试

| 状态 | 含义 | 处理 |
|---|---|---|
| `completed` | 自动来源完成；`manual_only` 只生成人工提示 | 进入候选复核 |
| `partial_failed` | 有成功结果，也有失败来源或条目 | 保留成功结果，按来源排查重试 |
| `failed` | 自动来源全部失败或命令失败 | 停止本次复核，由运维排查 |

失败通知只包含 run ID、状态和数量摘要，不包含异常原文、密码或连接串。重试时先记录 run ID 和来源，核对官网、DNS、TLS 和页面结构，再做单来源 DRY-RUN；通过后由管理员实际重试，并核对新增/既有候选数。不得删除旧 run 掩盖失败。

## 7. 来源漂移与紧急停用

v0.3 仍无运行时单来源自动停用开关。发现 HTML 来源改版时：

1. 将全局开关设回 `0` 并重建 app 容器，停止下一次自动月检；保留历史数据。
2. 在页面只勾选健康来源，或由运维用 `--source=<健康来源清单>` 做受控 DRY-RUN。
3. 如需临时恢复自动月检，只能通过受控代码修改定时命令的来源清单，重建并复验；不得在运行中容器临时改 crontab。
4. 修复适配器、代码复核、全量回归并部署新版本后，才恢复默认全来源调度。

不得放宽官方主机白名单，也不得改为抓取任意 URL。

## 8. HTTP 状态与排查

| 状态 | 常见含义 | 操作 |
|---|---|---|
| 403 | 当前角色无权执行 | 核对登录角色，不扩大普通员工权限 |
| 404 | 功能关闭，或记录不存在、跨机构或不可见 | 核对环境开关和记录 ID |
| 422 | 导出字段、链接或敏感扫描不通过 | 保留原候选，记录时间和 ID，查看安全错误码 |
| 500 | 未预期异常 | 停止重复提交，由运维看日志；不向体验人员发送堆栈 |

## 9. 技术验收链路与证据边界

离线“一单一库”端到端验收覆盖同一条业务链，但各阶段入口不同：

1. 监测阶段运行真实 `MonitorRegulatoryChanges` 命令对象，创建 run 和候选。
2. 复核阶段调用 `RegulatoryCandidateReviewService`，保存质量负责人结论。
3. 晋升阶段通过 `PlanningRegulatoryMonitor/promote` 正式控制器和审计中间件。
4. 导出阶段通过 `PlanningRegulatoryMonitor/export` 正式控制器。

因此可表述为“业务链完整”，不得表述为“全链都经控制器”。来源安全测试在 `--network none` 中执行。这些证据能证明本地代码链路，不证明当月官网可访问、页面结构未变、`manual_only` 已完成人工查询，也不证明云端部署或真实数据迁移完成。

## 10. 回退

1. 关闭 `REGULATORY_MONITOR_ENABLED` 并重建 app 容器。
2. 保留 run、候选、审计和已晋升事件，不直接删数据。
3. 应用版本按 `releases/current` 的既有发布回退流程切回已验证版本。
4. 数据库恢复必须进入独立闸门，使用已验证备份并先做恢复演练。
