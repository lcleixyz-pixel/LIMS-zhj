# 法规动态监测运行手册

| 项目 | 内容 |
|---|---|
| 文档版本 | v0.1 |
| 状态 | 已被 v0.2 取代，仅保留历史 |
| 适用系统 | jewelry-qms 法规动态监测模块 |
| 时区 | 业务调度固定为 Asia/Shanghai |

> 本版已作废。现行操作以同目录《法规动态监测运行手册-v0.2.md》为准；本文件不再更新。

## 1. 用途和边界

本功能每月检查已批准的官方来源，将新发现或内容变化记录为隔离候选，给出六类初步影响，再由人工复核。

这是“机器发现 + 规则初判 + 人工决策”工具，不是自动发布系统。候选不会自动成为现行外来依据，也不会自动修订质量手册、程序文件、授权表、校准计划或培训记录。

本功能不自动执行数据库备份和恢复演练。这两项属于部署/运维计划，在体验环境或生产启用前另行审批和验证。

## 2. 已批准来源

| 来源 key | 名称 | 官方入口 | 模式 |
|---|---|---|---|
| `samr_rkjcs_notice` | 国家市场监督管理总局认可检测司通知公告 | `https://www.samr.gov.cn/rkjcs/tzgg/index.html` | 官方 HTML 列表检查 |
| `cnas_lab_notice` | CNAS 实验室专门通知 | `https://www.cnas.org.cn/rkfw/sys/zxtz/index.html` | 官方 HTML 列表检查 |
| `cnas_lab_rules` | CNAS 实验室认可要求 | `https://www.cnas.org.cn/rkfw/sys/rkyq/rkzz/index.html` | 官方 HTML 列表检查 |
| `xinjiang_samr_notice` | 新疆维吾尔自治区市场监督管理局通知公告 | `https://scjgj.xinjiang.gov.cn/xjaic/tzgg/` | 官方 HTML 列表检查 |
| `cma_capability_query` | 检验检测机构资质认定证书查询 | `https://cma.caqit.org.cn/` | `manual_only` |

`manual_only` 表示系统只提醒人工查询，不会发起 HTTP 抓取，不会绕过验证码、JavaScript 或官方访问控制。人工核查后如需纳入 LIMS，应另行保留查询时间、官方页面/结果和复核人证据。

系统不允许在页面上临时输入任意 URL。只允许访问配置中的 HTTPS 官方主机。

## 3. 角色和权限

| 操作 | 系统管理员 `admin` | 质量负责人 `quality_manager` | 其他角色 |
|---|---:|---:|---:|
| 查看运行摘要、候选和证据 | 允许 | 允许 | 禁止 |
| 页面 DRY-RUN | 允许 | 允许 | 禁止 |
| 页面实际采集并保存 | 允许 | 禁止 | 禁止 |
| 人工复核候选 | 禁止 | 允许 | 禁止 |
| 晋升已确认相关候选 | 禁止 | 服务层允许，见第 7 节边界 | 禁止 |
| 导出单条脱敏 JSON | 允许 | 允许 | 禁止 |

复核人必须填写 2–1000 字符的理由。页面权限、服务层权限和审计记录同时生效；不得通过直接改数据库绕过它们。

## 4. 启用和停用

### 4.1 安全默认

`REGULATORY_MONITOR_ENABLED` 默认为 `0`。默认状态下：

- 月度调度不执行监测命令；
- 法规监测页面返回 404；
- 已有候选和变更事件不会被删除。

### 4.2 体验环境启用步骤

以下步骤只是操作基线，不是本文档对云端体验环境的上线授权：

1. 先完成当次版本的部署、迁移演练、数据库备份和恢复演练。
2. 在体验环境的 `.env` 中将 `REGULATORY_MONITOR_ENABLED=0` 改为 `REGULATORY_MONITOR_ENABLED=1`。密码不写入 Git、手册或聊天。
3. 从 `jewelry-qms/deploy/experience/` 按该环境的既有部署命令重建/`force-recreate` `app` 容器，不必为此暴露数据库端口。
4. 在容器内核对 `REGULATORY_MONITOR_ENABLED` 已为 `1`，然后以管理员先执行页面 DRY-RUN。
5. DRY-RUN 正常后，由管理员对单一来源执行一次实际采集，质量负责人只做候选复核；核对运行摘要、通知和审计记录后再保持月度开关。

生产环境不得直接照搬体验环境开关。生产启用须单独审批，并重新执行备份、迁移、权限、通知、回退和实际官网冒烟验证。

### 4.3 紧急停用

将体验环境的 `REGULATORY_MONITOR_ENABLED` 改回 `0` 并重建 `app` 容器，可停止月度任务并隐藏功能页。该操作不删除历史记录。

v0.1 尚无“运行时单来源停用”开关。如某个 HTML 来源页面改版导致结构漂移：

1. 立即把全局开关设为 `0`，阻止下一次自动全量运行；
2. 管理员可在页面只勾选其他健康来源，或由运维使用 `--source`显式列出健康来源，继续人工/临时调度：

   ```sh
   php think qms:monitor-regulatory-changes \
     --source=samr_rkjcs_notice,cnas_lab_notice,cnas_lab_rules
   ```

   上述清单只是格式示例，必须按当时真实故障来源调整，并先执行 DRY-RUN。
3. 如需在页面适配器尚未修复时恢复自动月检，只能经受控代码变更，在 `docker/crontab` 的月度命令中增加经批准的 `--source=<健康来源清单>`，然后重建容器并复跑 Compose、命令、通知和端到端验证。不得在运行中容器里临时改 crontab，也不得将该方式表述为现有的单来源开关。
4. 运维人员核对官方页面后修正适配器，经代码复核、回归测试和新版本部署后，再恢复默认全来源自动调度。

不得为了“让任务不报错”而放宽官方主机白名单或改为抓取任意 URL。

## 5. 月度调度、DRY-RUN 和手动执行

### 5.1 自动调度

启用后，容器定时任务每月 1 日 09:00（Asia/Shanghai）执行：

```sh
php /app/think qms:monitor-regulatory-changes --scheduled
```

日志写入容器的 `/tmp/regulatory-monitor.log`。容器重建后 `/tmp` 可能清空，业务结果应以 LIMS 中的运行摘要、候选和审计记录为准。

### 5.2 页面 DRY-RUN

1. 以系统管理员或质量负责人登录。
2. 打开 `/planning/regulatory-monitor`。
3. 选择一个或多个已批准来源，必要时填写起始日期。
4. 点击“DRY-RUN（不保存）”。

DRY-RUN 会运行真实解析和候选链路，然后回滚整个数据库事务。它不保留 run、候选或路由审计记录。

### 5.3 CLI 手动 DRY-RUN（运维排查）

```sh
php think qms:monitor-regulatory-changes \
  --source=samr_rkjcs_notice \
  --since=2026-01-01 \
  --dry-run
```

`--fixture-dir` 仅允许在 `APP_ENV=test` 中用于自动测试，不是体验或生产环境的数据导入方式。

实际采集会写入 run 和隔离候选，页面仅 `admin` 可操作。重试相同内容时会命中已有候选，不重复创建。

## 6. 运行状态、失败通知和重试

| 状态 | 含义 | 处理 |
|---|---|---|
| `completed` | 本次自动来源全部完成；`manual_only` 只生成人工核验提示 | 进入候选复核 |
| `partial_failed` | 至少一个来源/条目成功，同时有失败 | 保留成功结果，查明失败来源后按来源重试 |
| `failed` | 自动来源全部失败或命令系统失败 | 停止复核本次结果，由运维看日志和来源健康 |

`partial_failed` 和 `failed` 会向活动的 `admin` 和 `quality_manager` 生成一条去重通知，通知只包含运行 ID、状态和数量摘要，不包含原始异常、密码或连接串。

重试步骤：

1. 记录 run ID 和失败来源；
2. 核对官方入口是否可用、页面结构是否改版、容器 DNS/HTTPS 是否正常；
3. 先对该来源执行 DRY-RUN；
4. DRY-RUN 正常后再由 `admin` 对同一来源实际重试；
5. 核对新 run 的 `candidate_new_count` 和 `candidate_existing_count`。

不得在失败后盲目反复全量运行，也不得删除原 run 来“消除失败”。

## 7. 候选复核、晋升和 JSON 导出

### 7.1 候选复核

1. 进入 `/planning/regulatory-monitor`，按复核状态或来源筛选。
2. 打开“查看证据”，核对标题、文号、官方链接、发布/生效日期、内容指纹、版本链和六类影响。
3. 质量负责人选择“已确认相关”、“已确认不相关”或“暂缓/待补证”，填写理由并保存。
4. 确认字段变更已进入审计记录。

`no_match` 的严格含义是“现有确定性规则没有找到该类影响的关联”。它不表示“不适用”，不得代替质量负责人的实际影响评估。

### 7.2 晋升边界

只有 `confirmed_applicable` 候选可以晋升为 `registered` 外部变更事件。`pending`、`deferred` 和 `confirmed_not_applicable` 必须拒绝。晋升是单一事务，重复提交返回同一 event ID，不产生第二条事件或成功审计。

v0.1 已完成并验收晋升服务层，但尚未在法规候选页提供“晋升”按钮、HTTP 路由或专用 CLI 命令。因此：

- 体验岗位人员在本版只试运行到“候选复核 + JSON 导出”；
- 不得通过直改数据库或临时 PHP 脚本代替正式入口；
- 需让岗位人员完成晋升时，先增加受权限、CSRF 和审计保护的页面动作，再单独验收。

当前技术验收仅在隔离测试库中直接调用服务契约，用于证明事务、权限和幂等性，不是日常操作指南。

### 7.3 脱敏 JSON 导出

已登录的 `admin` 或 `quality_manager` 可访问：

```text
/planning/regulatory-monitor/export?id=<candidate-id>
```

成功时下载 `candidate-<id>-review-packet-v1.0.json`。数据包字段是白名单，包含官方来源证据、固定六类影响、规则版本和复核状态，不整对象序列化候选。

v0.1 详情页尚无导出按钮，需从详情页 URL 取得 candidate ID 后访问上述受保护路由。不得将 ID 放入未受信的外部页面。

如候选的可导出字段含密码、Cookie、Authorization、DSN、手机号或身份证号等敏感内容，系统会阻断整个导出并返回 422，不会静默删字段后继续下载。此时应交由运维和质量负责人核对来源证据，不得在数据库中直接删改证据。

## 8. HTTP 状态和排查

| 状态 | 常见含义 | 操作 |
|---|---|---|
| 403 | 当前角色无权查看/执行 | 核对登录账号角色，不要扩大普通员工权限 |
| 404 | 功能开关关闭，或候选不存在/不属于当前机构/不可见 | 先核对环境和 candidate ID，不要换机构或绕过权限查找 |
| 422 | 候选来源、JSON 格式、链接或敏感内容未通过安全导出检查 | 保留原候选，记录时间和 ID，查看服务日志中的安全错误码 |
| 500 | 未预期系统异常 | 停止重复提交，保留 run/candidate ID 和时间，由运维查看日志；不将原始堆栈发给体验人员 |

系统不在页面或通知中回显底层密码、令牌和连接串。

## 9. 本地夹具验收与真实月检的边界

`tests/regulatory_e2e_smoke.php` 使用仓库内的“一单一库” HTML 夹具，每次加入随机文号和官方路径，然后完整验证：

- 命令创建 run 和一条 `pending` 候选；
- 六类影响固定存在，CMA、体系文件、人员授权和 LIMS 规则四类命中；
- 质量负责人确认相关，幂等晋升为一条外部变更事件；
- 导出 schema 1.0；
- 第二次命令不重复建候选，第二次晋升不重复建事件。

该测试将 HTTP/HTTPS 代理指向不可用的本地端口，而命令只读本地 `--fixture-dir`，因此官方页面不可达时仍可验证业务链。由于端到端测试要访问隔离 MySQL 容器，它保留 Docker 内部数据库网络；来源注册与 HTTP 安全测试则在真实 `--network none` 容器中独立执行。

本地夹具验收不证明当月官方网站可访问、页面结构未变、官方内容完整，也不证明 `manual_only` 查询已由人完成。真实月检必须结合运行健康、官方链接和人工复核。
