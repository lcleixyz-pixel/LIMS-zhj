# docx 受控渲染接口规范 v1.0

> compiler 产出的发布版 md 是 docx 技能的**唯一输入**。本文档定义 md→docx 的映射契约，使任何 Word 文档技能都能据此生成受控打印稿。

---

## 1. 输入约定（compiler → docx）

### 1.1 文件格式要求

compiler 产出的发布版 md 必须满足以下条件才可交付 docx 技能：

| # | 条件 | 检查方式 |
|---|------|----------|
| 1 | 无残留参数标记 `{{...}}` | `assemble_strip --check` 已通过 |
| 2 | 无回链标记 `[K-xx]` / `[F-xx]` | `assemble_strip --check` 已通过 |
| 3 | 无条件块标记 `◇C` | `assemble_strip --check` 已通过 |
| 4 | 无 WV 块 `<!--WV-->...<!--/WV-->` | `assemble_strip --check` 已通过 |
| 5 | 无拒发词（工作版/占位/【虚构】/待拍板等） | `assemble_strip --check` 已通过 |
| 6 | 语义签字已完成 | 总台账登记为"语义已签" |

### 1.2 标题层级映射

| Markdown 标题 | Word 样式 | 说明 |
|---------------|----------|------|
| `# 标题` (一级) | 封面标题 | 仅封面使用，正文不从一级开始 |
| `## 标题` (二级) | 标题 1 | 对应 CL01 条款号（如 4.1 公正性） |
| `### 标题` (三级) | 标题 2 | 对应条款子项 |
| `#### 标题` (四级) | 标题 3 | 子子项（一般不超过四级） |

---

## 2. 受控章规格

### 2.1 页眉受控章

- **位置**: 每页右上角（封面除外）
- **文字**: `受控文件` 或 `非受控文件`（由发布版封面注明）
- **字体**: 黑体 12pt，红色 (#CC0000)
- **附加信息**: 分发号（由机构自行填入，compiler 在封面留 `分发号: ______` 占位）

### 2.2 版本信息

- **位置**: 每页页脚左侧
- **内容**: `版本 vX.Y | YYYY-MM-DD 发布`
- **字体**: 宋体 8pt，灰色

---

## 3. 页码规则

| 区域 | 页码格式 | 起始 |
|------|----------|------|
| 封面 | 无页码 | — |
| 目录 | 罗马数字 (i, ii, iii) | i |
| 正文 | 阿拉伯数字 (1, 2, 3) | 1 |
| 附录 | 续正文页码 | — |

---

## 4. 目录生成规则

| 规则 | 说明 |
|------|------|
| 入册标题级别 | 二级 (标题1) 和三级 (标题2) 进目录 |
| 不入册 | 四级及以下不进目录 |
| 格式 | 标题左对齐，页码右对齐，中间用点线填充 |
| 更新 | 每次生成 docx 时自动刷新目录域 |

---

## 5. 表格样式

| 元素 | 样式 |
|------|------|
| 表头行 | 加粗 + 浅灰底色 (#F0F0F0) |
| 表格边框 | 实线 0.5pt，黑色 |
| 列宽 | 自适应内容（长文本列可设固定宽度） |
| 表格标题 | 表格上方居左，格式 "表 N: 标题" |

---

## 6. 封面内容

封面由 compiler 在发布版 md 中以下格式给出：

```markdown
# <机构全称>
## 质量手册（发布版 vX.Y）
### （依据 CNAS-CL01:2018 + 检验检测机构资质认定评审准则）

| 项目 | 内容 |
|------|------|
| 文件编号 | <机构手册编号> |
| 版本 | vX.Y |
| 发布日期 | YYYY-MM-DD |
| 实施日期 | YYYY-MM-DD |
| 分发号 | ______ |
| 受控状态 | 受控 / 非受控 |
| 编制 | (签名) |
| 审核 | (签名) |
| 批准 | (签名) |
```

## 7. 验收检查清单（docx 技能产出后，engineer 逐项点收）

| # | 检查项 | 验收标准 | 不通过处置 |
|---|--------|----------|------------|
| 1 | 页眉受控章 | 每页（封面除外）有"受控文件"红色字样 | 退回 docx 技能重渲染 |
| 2 | 版本信息 | 每页页脚有版本号+日期 | 同上 |
| 3 | 页码 | 封面无码、目录罗马、正文阿拉伯 | 同上 |
| 4 | 目录 | 二三级标题入册、页码与正文一致 | 更新目录域后重检 |
| 5 | 表格 | 表头加粗灰底、边框完整 | 退回修复 |
| 6 | 内容一致性 | docx 与发布版 md 文本逐段一致（不含样式差异） | 不一致→查是否手改了 docx(禁止)→回编译器重来 |
| 7 | 封面信息 | 文件编号/版本/日期/分发号/受控状态/三签 齐全 | 缺项退回补全 |
| 8 | 无残留 | 全文无 `{{` `[K-` `◇` `<!--` 等编译器标记 | 属于编译器闸口缺陷→回 compiler 重剥离 |

---

## 8. 已知局限

- 本文档定义了 md→docx 的格式契约，但不包含 docx 技能的**实现**——docx 技能是本套装的**外部依赖**
- 若 docx 技能不可用，可以本规范为 Checklist 人工排版，验收项同上
- 双向同步（docx 被修改后回写 md）暂不支持，docx 永远是 md 的**单向投影**——任何对 docx 的修改都是临时的，以 md 为唯一事实源
