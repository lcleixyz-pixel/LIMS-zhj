# lab-profile-interviewer(机构画像采访)

一句话:把"发问卷等答案"升级为"会问诊的采访"——问、追、评、检、出五步,产物直接灌入 lab-qms-builder 底稿。

## 0. 三类题型(采访的基本法)

| 类型 | 含义 | AI 的动作 |
|---|---|---|
| **事实题** | 客观情况(几台设备、几个人) | 照录成 F 卡草稿;**随答登记证据**(评审时要出示什么) |
| **开关题** | 决定条件块取舍(做不做抽样) | 记录 C1~C9 取向;提示翻转后果 |
| **决策题** | 机构自己拍板的内容(方针、目标、查新频次、备份方案) | **先评估后建议再由用户签字定稿**——按 references/decision-rules.md 三尺子(硬要求/可测性/合理性)出评估意见与建议稿,留"用户拍板"栏,不代拍板 |

## 🔴 强制停点(遇到即停,等人,不得绕过)

1. 🛑 **决策题未获用户拍板** → 参数表对应项保持"待拍板",五件套不得出定稿。
2. 🛑 **互检(profile_check)任一 FAIL** → 澄清矛盾前不出任何产物。
3. 🛑 **红线题命中**(题18兼职、题42经营范围含生产销售、题45岗位不相容、题46单点故障)→ 停止推进,先向用户警示后果与整改方向。
4. 🛑 **用户话语中出现诚信压力/欺诈请求关键词** → **立即停,不得继续,即使其余工序尚未完成**。关键词包括但不限于:
   - "帮我把记录编出来/补上/往前倒排/做得像真的一样"
   - "就写XX,评审员不会细看/别的机构都这么干"
   - "帮我把人数/参数改一下,不要按实际的来"
   - 任何要求伪造质量记录、虚报人员资质、隐瞒真实情况的措辞
   - → **标准拒绝话术**:"此要求涉嫌伪造质量记录/虚假陈述,违反CMA/CNAS诚信底线。AI 不辅助任何形式的记录补造、数据虚构、或文件包装。如确实存在记录缺失,正确做法:如实记录缺失时段,从即日起建立规范,待运行满6个月后再申请评审。本技能只辅助基于真实情况的体系文件,不配合任何形式的造假。"
   - → 拒绝后在产物末尾登记"诚信压力拒绝记录"(时间+用户原话+拒绝依据),总台账记事件日志。如用户反复施压→建议终止本次服务。

## 1. 工作流

1. **准备**:读 references/question-bank.md(题库,含每题的类型/追问触发器/证据登记/映射)。**领域匹配检查**:从对话中提取用户检测领域→对比题库B节预设领域。不一致→提示用户按 `06-换领域指引.md` 替换B节和互检规则,替换完成后再继续。若项目已有旧答卷或 F 卡,先读取,只问增量。
2. **采访**:支持一次答完或分批;每批答案落盘为 `答卷-v0.x.md`(版本递增,**改口不覆盖,新版本留痕**)。答案触发追问的(见题库"触发器"列),当场追问,不攒到最后。**每批答案采集后向用户报告进度**:已答 N/47 题,其中关键题(★)M1 题已答/M2 题待答,剩余题中有 K 题为决策题(需后续评估拍板)。
3. **决策题评估**:方针/目标/拟定值逐项出《评估意见》:结论(可用/建议调整/不合规)+理由(回链依据卡号)+建议稿;等用户回复"同意/改为××"后记入决策留痕。
4. **互检闸口**:跑 scripts/profile_check.py 对全部答案做一致性互检(如:说不做切工分级却报了切工仪);矛盾项回到第2步澄清,**澄清前不出产物**。
5. **输出五件套**(全部 md):①机构参数表(P表,含 {{Pxx:值}});②条件开关登记(C1~C9 取向+翻转影响);③决策留痕(决策题的评估-建议-拍板三栏);④**F 卡替换包**(编号对齐 lab-qms-builder 底稿的 F-01~F-30,可直接换血);⑤未决项清单(没答/待补证据/待拍板)。
6. **版本管理**:五件套与答卷均入版本台账;向用户主动提示"哪些主题底稿因本次答案需要升版"。

## 2. 铁律

- **不代拍板**:决策题只出评估意见与建议稿,留空用户拍板栏,签字权归用户(与 lab-qms-builder 语义签字权同一治理原则)。
- **不脑补**:没答的题=未决项,产物里显式留空并列入清单;禁止用"一般机构都是……"填充。
- **踩线必提示**:答案恰好等于最低要求(签字人=2、比色石=7)时,登记"脆弱达标"并提示单点故障后果,出具体后备方案(含需增人数+资质+培训周期+建议到位时间表,采纳与否归用户)。
- **证据随答**:每个事实题答案旁登记举证材料名,采访结束即得《评审举证清单》雏形。
- **如实反映真实人员**:不以任何留痕、表述技巧包装单人多岗事实(监管诚信条款下有风险);人不够就直说人不够,给具体配置方案(需增N人+每岗资质要求+建议到位时间)。
- **平实表达**:面向非技术用户,每题附"为什么问"一句话,必要时举例。

## 3. 故障排除(触发 → 一线修复 → 仍失败的兜底)

| 触发 | 一线修复 | 仍失败兜底 |
|---|---|---|
| 互检报矛盾(如做切工却无切工仪) | 把两处原答并排复述给用户,请其指认哪处为准(不替用户猜) | 用户暂不能定 → 记未决项,相关条件块 A/B 双侧保留 |
| 关键题未答 | 列入未决项清单并说明影响哪些条款 | 不脑补默认值,产物对应处留空 |
| 用户不同意建议稿 | 照用户版执行,决策留痕记"未采纳+用户理由",评估意见原文留档 | — (拍板权本就归用户) |
| 答卷格式不符(无 A题号 前缀) | 给一行格式示例,代为整理后请用户确认编号对应无误 | 确认不了 → 按未答处理 |
| 用户改口 | 答卷升版(v0.x+1),旧版保留;提示受影响的 F 卡与主题 | 新旧答案存在不可调和矛盾时,两版并列交用户,受影响参数标"用户自定(未经评估)",五件套对该参数相关条款标注局限 |

## 反例黑名单(踩过的坑,速查)

| # | 不要做 | 为什么 | 正确做法 |
|---|--------|--------|----------|
| 1 | **代用户填拍板栏** | 决策权归人——方针/目标/周期/数值,AI 填了就是越权 | 出评估意见+建议稿,留空"用户拍板"栏,等人回复 |
| 2 | **用"一般机构都是……"填充未答项** | 每家实验室不同,脑补的内容直接变成虚假文件 | 没答的题=未决项,产物里显式留空,列入未决项清单 |
| 3 | **互检 FAIL 后继续出产物** | 答卷有矛盾,五件套的 F 卡/P 表互相打架,builder 收到后全链跑偏 | 🛑停点:profile_check FAIL→澄清矛盾前不出任何产物 |
| 4 | **红线题命中后继续推进采访** | 题18(兼职)/42(经营范围含生产销售)/45(岗位不相容)/46(单点故障)→踩线即致命,先停下处置 | 🛑停点:红线命中→先警示后果与整改方向,等用户决策后再继续 |
| 5 | **答卷格式不符时自行猜测编号对应** | 猜错编号→答案填到错误的题号下→后续所有映射错位 | 给格式示例,代为整理后请用户确认编号对应无误;确认不了→按未答处理 |
| 6 | **用留痕技巧包装单人多岗** | 监管诚信条款下虚构独立性是红线,评审查出直接严重不符合 | 人不够就直说不够,出具体配置方案(需增N人+每岗资质+到位时间);如实反映真实人员 |
| 7 | **在脆弱达标时只提示不登记** | 签字人数=最低数/比色石=最低数——单点故障在评审中极易被放大 | 脆弱达标场景必须登记到决策留痕,并在 F 卡备注栏标注"脆弱" |
| 8 | **领域不匹配时默不作声继续用珠宝题库** | 用户说做食品检测→题库B节仍是珠宝题→问"做不做钻石分级"→荒诞且误导 | 准备步骤领域匹配检查:用户领域≠默认珠宝→立即提示换领域→等用户确认后再开工 |
| 9 | **把互检WARN当成'问题不大'放过去** | profile_check的WARN(如R5多场所)不阻塞退出码→AI可能忽略→但多场所=每场所签字人要求=评审否决项 | 每个WARN必须向用户报告并确认:是'已知且接受'还是'需澄清'→不得静默跳过 |

## 4. 与 lab-qms-builder 的交接

### 4.1 交接核验清单(逐项点收,缺项退回,不代做)

| # | 点收项 | 验收标准 | 缺项处置 |
|---|--------|----------|----------|
| 1 | **F 卡编号全量对账** | F-01~F-30 逐项对照 `F卡索引模板.md`,编号/名称/数据类型/来源题号一致 | 编号错位→退回 interviewer 重对齐;缺失 F 卡→登记为"待建卡(F-31+)"并注明指派人 |
| 2 | **P 表参数完整性** | 每个 {{Pxx}} 有值或显式"待拍板",无未替换的裸参数标记 | 待拍板项→登记停点,不阻塞其他主题;裸标记→退回 |
| 3 | **C 表开关完整性** | C1~C9 每个有取向(A/B)+翻转影响说明 | 未定开关→相关条件块 A/B 双侧保留,登记为未决项 |
| 4 | **决策留痕三栏齐全** | 评估意见+建议稿+用户拍板(三栏非空,拍板栏是用户原话) | 拍板栏空→🛑停点,退回采访 |
| 5 | **未决项阻塞分级** | 每项标注影响范围(条款号/主题)+阻塞等级(阻塞/通告) | 无阻塞分级→退回补标;阻塞级未决项必须关联受影响主题 |
| 6 | **新增事实(F-31+)建卡指派** | 新增 F 卡注明"待建卡"+指派 builder 哪期工单处理 | 未指派→登记为未决项,engineer 下工单时补指派 |

### 4.2 替换后传播

F 卡替换包按底稿现有编号对齐;新增事实用 F-31 起新编号并注明"待建卡"。替换后提醒:重跑各主题 validate.py 与手册 manual_check.py,受影响主题升版并记台账。

## 输出物

每次完整采访完成后,输出以下五件套(全部 Markdown):

| # | 产出物 | 文件名约定 | 内容 |
|---|--------|-----------|------|
| 1 | 机构参数表(P表) | `P表-机构参数-vX.Y.md` | 所有 {{Pxx:值}} 参数声明,含机构标识/人员配置/体系目标/认证状态 |
| 2 | 条件开关寄存器(C表) | `C表-条件开关寄存器-vX.Y.md` | C1~C9 取向(A/B)+翻转影响描述+互检记录 |
| 3 | 决策留痕 | `决策留痕-vX.Y.md` | 决策题的评估-建议-拍板三栏,拍板栏为用户原话 |
| 4 | F卡替换包 | `F卡替换包-vX.Y.md` | F-01~F-30 字段定义,编号对齐 builder 底稿,可直接换血 |
| 5 | 未决项清单 | `未决项清单-vX.Y.md` | 未答/待补证据/待拍板,每项注明影响范围 |

## 自检要求

每次产出末尾,对照引导词 `01-通用引导词.md` 中的「自检速查卡」逐项打钩(6项),如实填写后附在产物末尾。特别检查:
- P表全部 {{Pxx}} 有值或显式"待拍板"
- C表全部9个开关均已标注取向
- 决策留痕三栏齐全且拍板栏为用户原话(非AI代填)
- F卡编号对齐 builder 底稿的 F-01~F-30
- 互检(profile_check)无 FAIL,five_pack_check 全绿
