# 术语词典(每个词:大白话+例子)

| 术语 | 大白话 | 例子 |
|---|---|---|
| K卡(要求原子) | 把官方标准拆成的"最小一条规矩",一卡只管一件事 | "人员能力要求要写成文件"是一张卡,"不得两处从业"是另一张 |
| 回链 [K-xx] | 正文每句话尾巴上挂的"出处小票",证明不是编的 | "……签署从业承诺 [K-02]"——查K-02就知道这句从哪条标准来 |
| F卡 | 你实验室的一条真实情况,做成可替换的卡片 | F-08=你家的人员岗位表;人走了换卡,文件跟着自动该改哪就提示改哪 |
| P表/{{Pxx}} | 需要你拍板的数字挖的"空",拍板后统一填入 | {{P03}}=授权签字人几名;你说2就全文自动是2 |
| 条件开关◇C | 按你机构情况二选一的段落开关 | C3=小机构开关:开了就带"双帽留痕"条款,大机构不需要 |
| 五级判定 | 体检打分:✅有 △有但不全 ✗没有 ⚠存疑待裁 ◇缺原文没法判 | 见样例4体检报告 |
| 机判 vs 语义签 | 机器查格式漏洞 vs 人确认内容属实,两码事,谁也不能替谁 | 脚本说"没漏项"≠这文件符合你家实际,后者必须人签字 |
| 遍历/窗证闭合 | 逐条数过=遍历(硬证据);抽查推定=窗证(软证据,要限期复核) | 迎审报告里两者必须分开写 |
| 世系分析 | 标准换版了,查老条款的要求是"死了、搬家了、还是被合并了" | 旧版5.4条废止,但要求搬进了新版6.2——文件里不能跟着删 |
| 频次槽空转 | 写了"定期""按计划"却没有具体数字——评审员最烦这个 | 错:"定期监督";对:"每年1次/人" |
| 双帽 | 一人兼两岗时,两顶帽子的活分开签字留痕 | 老李既当质量负责人又当监督员,两类记录分开签 |
| CAPA | 出了问题后的"改这单+防再犯"一套动作 | 纠正=重出这份报告;纠正措施=改流程让以后不再错 |
| 停点🛑 | AI必须停下等人的地方,进度再急也不能闯 | 两条标准打架、需要签字、需要拍板,都是停点 |
| 底稿/工作版/发布版 | 原料/带小票的自用版/撕掉小票对外的正式版 | 见样例3两版对照 |
| 台账 | 项目的"病历本",干到哪、卡在哪全在里面,只加页不撕页 | 新对话让AI先读台账就能续上进度 |
| 铅笔卡(G卡) | 指导性条款的原子卡——只参考,不入强制正文,永不进入对账✅ | GL008对不符合项怎么分级的建议→G卡,写文件参考但不强制 |
| P记录 | 指针解析记录:一条"详见X文件"的指针跳到了哪里,证据是什么 | CL01 6.5引"另有规定"→P记录登记跳转目标+截断判断 |
| I表 | 接口登记表:管你实验室自己干不了的活,外包/外校/采购的合同边界 | 设备外校→I表登记校准机构义务+你须提供的配合 |
| X登记 | 跨主题线索:一个条款关联两个以上要素,在哪处理谁负责 | "人员培训"既在人员(6.2)又在方法(7.2)→X登记关联 |
| 三闸 | compiler的三道机器闸口:manual_check(防幻觉)、coverage_check(防漏装)、assemble_strip(防带病发布) | 发布版必须三闸全绿 |
| 五件套 | interviewer输出的五份产物:参数表P、条件开关C、决策留痕、F卡替换包、未决项清单 | 采访结束→交五件套→engineer验收→builder开工 |
| 三读开工 | 弱模型规程一:读台账→读SKILL.md→读模板,读完才动手 | 新对话第一件事,没读完不回答业务问题 |
| 点名(点名册) | builder普查第一步:把依据相关章节全量逐条列出,一条不许漏 | 不是"找相关条款"——是整个章节从头到尾每条都数 |
| 书架 | 依据登记表的别名:登记代号/全名/版本/效力/获取渠道/核对状态 | 先建书架再点名,没登记的文件不能用作依据 |
| PDCA四槽 | builder程序骨架:每要素每环节P/D/C/A四个槽,槽内必挂记录名 | 人员培训:P=培训计划 D=培训记录 C=考核记录 A=再授权记录 |
| 受控文件 | 正式发布版,有受控章/分发号/版本状态,禁止手改 | 工作版可以改,发布版不能改——改了必须回工作版重新剥离 |
