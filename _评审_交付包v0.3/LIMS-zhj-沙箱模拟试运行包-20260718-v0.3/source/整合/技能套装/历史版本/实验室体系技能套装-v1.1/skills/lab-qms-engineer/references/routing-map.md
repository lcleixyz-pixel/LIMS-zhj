# 路由与交接协议(routing-map)

编排任何跨工序动作前必读本文件。三条原则:**交接必点收**(缺项退回,不代做)、**传播必追全**(一处变,查全链)、**转交必带状态**(工单不裸发)。

## 1. 工单格式(总工 → 子技能)

每张工单包含五要素,缺一不发:

```
【工单】W-<流水号>
主题:<要素/主题名>
当前状态:<状态机取值> + 已知阻塞
输入物:<路径清单,含版本号>
期望产物:<文件名与验收标准>
优先级依据:<为何现在做——清阻塞/补签字/推进度/变更响应>
```

## 2. 交接清单(子技能 → 总工,逐项点收)

### 2.1 interviewer → 本技能(五件套验收)

| 点收项 | 验收标准 | 缺项处置 |
|---|---|---|
| ①机构参数表 P 表 | 每个 {{Pxx}} 有值或显式"待拍板" | 待拍板项登记停点,不阻塞其他主题 |
| ②条件开关 C1~C9 | 每个开关有取向+翻转影响说明 | 未定开关 → 相关条件块 A/B 双侧保留,记未决 |
| ③决策留痕 | 评估-建议-拍板三栏齐全,拍板栏是用户原话 | 拍板栏空 → 🛑 停点,退回采访 |
| ④F 卡替换包 | 编号对齐 F-01~F-30（对照 `F卡索引模板.md`）,新增从 F-31 起 | 编号错位 → 退回 interviewer 重对齐 |
| ⑤未决项清单 | 每项注明影响哪些条款/主题 | 无清单不算交付完成 |

验收通过后的**必做传播**:F 卡替换 → 受影响主题在总台账退回"构建中" → 生成 builder 回跑工单(重跑各主题 validate.py)→ 若两册已存在,追加 compiler 回跑工单。

### 2.2 builder → 本技能(底稿验收)

| 点收项 | 验收标准 |
|---|---|
| 底稿文件 | `要素模板-<主题>-vX.Y.md`,版本号比台账现记录+0.1 或更高 |
| 机判结果 | validate.py 全绿的证据(输出粘贴或人工逐项核对记录) |
| 对账单 | 五级判定齐全;`遍历闭合`与`窗证闭合(待复核)`分开报告 |
| 世系与待办 | 待核项、X 线索、T 待办显式列出 |
| 语义签字状态 | 已签(签字人+日期)或显式"待签"——**机判✅≠语义签**,分列记账 |

未签主题在总台账最高只能标到"机判✅"。窗证闭合的主题标注"待复核",迎审就绪报告须单列。

### 2.3 compiler → 本技能(两册验收)

| 点收项 | 验收标准 |
|---|---|
| 工作版两册 | 版本号+所依据的底稿版本清单(逐主题) |
| 三闸结果 | manual_check / coverage_check / assemble_strip 全绿证据 |
| 发布版(如出) | 残留自检为零({{、[K-、◇、<!-- 均无);语义签字在先 |
| 版本台账更新 | 版/次记录与总台账事件日志互相印证 |

验收要点:逐主题核对"两册所依据的底稿版本"="总台账最新版"。任何一个主题落后 → 两册不得在台账标"最新",生成回跑工单(停点:底稿升版后两册未回跑)。

## 3. 变更传播矩阵(一处变,查全链)

| 变更源 | 第一跳 | 第二跳 | 第三跳 | 总台账动作 |
|---|---|---|---|---|
| 外部依据换版/废止 | builder 世系分析(消亡/迁移/被吸收) | 受影响主题底稿升版 | compiler 回跑受影响章节 | 命中即冻结相关主题"最新"声明,分析完成后按清单退状态 |
| 画像事实变(F 卡) | interviewer 答卷升版+新替换包 | builder 受影响主题回跑 validate | compiler 回跑 | 受影响主题退回"构建中" |
| 决策改拍(P 表/开关) | interviewer 决策留痕升版 | 参数点/条件块联动:compiler 重剥离 | 若涉正文措辞 → builder 先行 | 事件日志记"改拍",发布版必重生成 |
| 底稿内改(自纠) | builder 升版 | compiler 回跑 | — | 退回"构建中"再逐级前进 |
| 内审/管评发现文件缺陷 | 开 CAPA | 转 builder 升版 | compiler 回跑 | CAPA 台账与工单号互链 |

传播原则:**盯"要求的迁移",不只盯"文件的存废"**(builder 世系规则)。

### 3.1 传播穷举表（跳链场景速查）

| 变更源 | 场景 | 三级跳链 | 停点触发 |
|--------|------|----------|----------|
| 依据换版 | CNAS-CL01 某条款修订 | builder 世系分析→受影响底稿升版→compiler 回跑 | 🛑停点3:冻结"最新"声明 |
| 依据换版 | G001 某条款变更 | 同 CL01 流程，另查 A015 是否覆盖（A015 优先） | 同上 |
| 依据换版 | 领域 A 系列（如 A015）换版 | 优先于 G001 一致条款，逐条对照差异→builder 底稿受影响章 | 🛑此换版可能解冻此前"正交叠加"的 G001 条款 |
| 画像事实变 | 授权签字人变动（F-05） | interviewer 升版答卷→替换 F-05→人员底稿退回构建中→程序 CX-01 受影响→compiler 回跑 | 脆弱达标登记重新评估 |
| 画像事实变 | 设备清单变动（F-08~F-12） | 设备底稿退回→计量溯源章节受影响→期间核查程序受影响 | R1/R2 互检重跑 |
| 画像事实变 | 多场所新增（F-01） | C5 翻转→每场所签字人检查→结构章/人员章均受影响 | 所有已发布主题必须重新跑闸 |
| 决策改拍 | 查新频次变更（P31） | compiler 汇编中参数点 {{P31}} 重填→发布版重剥离 | 仅 compiler 回跑，不触发 builder |
| 决策改拍 | 方针/目标变更（P33/P34） | 手册概况章参数点重填→如影响正文措辞则 builder 先行→compiler 回跑 | 正文措辞变更属 builder 范围 |
| 底稿内改 | 自审查出悬空回链 | builder 升版→compiler 回跑受影响章 | 总台账退至"构建中" |
| 底稿内改 | 补漏采条款（点名册追加） | builder 升版→对账单更新→compiler coverage_check 重跑 | 闭合声明重新标注 |
| 运行期发现 | 内审发现程序未执行 | 开 CAPA→如属文件问题转 builder 升版→compiler 回跑 | CAPA+工单号双链 |
| 运行期发现 | 管理评审输出决议要求改文件 | 同 CAPA 路径，管评输出决议跟踪表链接工单号 | 决议未关闭前两册不得自称"现行有效" |

## 4. 路由细则(话术 → 去向)

| 用户话术特征 | 去向 | 备注 |
|---|---|---|
| "问卷/答卷/方针/目标/拍板/这题啥意思/签字人几个够" | interviewer | 转交时附旧答卷路径,只问增量 |
| "写/改条款、点名、普查、卡、对账、换版影响、覆盖了没" | builder | 附画像参数与该主题当前底稿 |
| "出手册/汇编/发布版/打印稿/漏装/两册同步" | compiler | 附各主题最新版清单 |
| "打印成 Word/受控章/页眉页码" | docx 技能 | 仅在 compiler 出发布版 md 之后 |
| "进度/下一步/卡在哪/还差什么/上次到哪" | 本技能 | 状态报告 |
| "内审/审核/管评/查新/换版了/不符合/整改/迎审/评审准备" | 本技能 | 进 ops-playbooks 对应作业卡 |
| 模糊请求("帮我弄一下体系") | 本技能 | 先读台账再问一个最小澄清问题 |

## 5. 用户绕过总工直接驱动子技能后的补账

允许(用户自由),但产物入两册前必须补验收:按 2.1~2.3 清单点收 → 补记事件日志(注明"补账")→ 状态按实况重标。点收不过的产物标"未入账",compiler 工单不得引用它。

**补充路由**:"审现有手册/老文件行不行/体检/缺什么" → 本技能 ops-playbooks 卡六(主持),对账作业转 builder,报告回本技能汇总。存量文件未经体检入册的,compiler 工单不得引用。
