## 三、三个病根（按严重程度）

### 病根一：治理套娃——为了"安全动手"准备了 142 份材料，手始终没动 🔴

**现象**：`.team/交接箱/2026-07-07-第五版候选修订准备/` 一个目录就有 **492 个 git 跟踪文件、142 项编号产物**。光"治理关闭"这一个动作，就衍生出 8 层套娃：

> 工作台 → 执行包 → 试点包 → 回填预览 → 源表补丁预演 → 人工执行工作簿 → 真实交回包 → 模拟完成包 → 意见预览 → 刷新预览……

每层都配一份 .md + 一份 .json 验证报告（117 份编号报告就是这么来的）。

**比喻**：你要钉一颗钉子，先造了量尺、画了图纸、做了样板、演练了挥锤姿势、又给演练写了复盘……但钉子始终没钉下去。

**证据**：进度.md 自己写了——"117-LIMS 全量 apply-rehearsal 跑通，findings=0，database_write_performed=0"。翻译成大白话：**整套链路证明它能跑通，但一次真实写库都没发生，一次真实人审都没完成。**

**为什么是病**：准备本身变成了主菜。每多生成一层治理包，你（非技术用户）的认知负担就翻倍，真实推进的动力反而越小。这正是总规划 v1.1 自己警告的——"阶段 2 的头号敌人是完美主义"。

---

### 病根二：双线脱节——总规划说"先落地用起来"，作战室在"演练到万无一失" 🔴

**现象**：项目同时存在两个方向，互相对不上：

| | 总规划 v1.1（阶段 2）说的 | 作战室实际在做的 |
|---|---|---|
| 头号任务 | 记录填报 + 可打印链路打通 | 第五版手册换版的治理演练 |
| 验收标准 | 系统进入日常真实使用（硬日期） | 392 条阻断清零、67 项人审通过 |
| 当前状态 | 【硬日期待拍板】，没动 | 142 份产物，0 项真实完成 |

**比喻**：你（总规划）说"先让车跑起来，哪怕只有一档"；作战室却在车间里把整辆车拆了，给每个螺丝都做了质检报告，说"等全部合格再上路"。车永远上不了路。

**证据**：总规划第九条"当前节拍"写了三件最重要的事——①记录填报可打印 ②拍硬日期 ③起草契约。作战室的上下文.md / 任务板.md / 进度.md **这三件事一件都没在做**，全在围绕"第五版候选手册"转。

**为什么是病**：两套语言、两个方向。你每次打开作战室，看到的都不是总规划让你干的事。时间一长，总规划变成废纸，项目被作战室的惯性拖着走。

### 病根三：机器替人准备——67 项人工评审一项没做，却生成了 6 层"预览" 🔴

**现象**：整个作战室真正卡住的，是 **67 项人工评审决策全部 pending**（条款 29 + 记录模板 26 + 归属 1 + 闸门 11）。这 67 项是必须由**人**（你或你的组织）来拍板的。

但机器没等你拍板，就围绕这 67 项衍生出了：第二阶段复核（154 项 pending）、治理总览（392 条阻断）、治理关闭（396 条）、闭环执行（60 批次/50 签核/60 交接）、试点（5 批次/55 字段）……**越衍生，pending 越多，人越不敢动。**

**比喻**：医生还没给你开诊断（67 项检查没出结果），医院已经把手术方案、术后康复、复诊安排、家属通知单全准备好了——还每样做了正副两份。你一进门就被这堆东西吓住，反而连第一项检查都不想做了。

**证据**：任务板.md 里"进行中"全是"待执行 / 等人工意见 / 等人工证据 / 等真实试点执行"——**所有任务都在等人，但人面对的是一张永远清不完的清单**。

**为什么是病**：superpowers 纪律讲的是"小步、可验证、人能跟上"。现在是"机器大步狂奔、人彻底掉队"。机器生成的任务量，已经远超一个非技术用户（甚至一个小型实验室）能消化的极限。

## 五、怎么理（用 superpowers 的 spec→plan→task 给三步建议）

> 这只是诊断里的建议，不是现在就执行。你认可后我们再分步做。

**第 1 步｜spec（定"做完是什么样"）**
把总规划阶段 2 的北极星，收窄成一句话验收标准。建议：
> "在【你拍板的某一天】，jewelry-qms 的记录填报 + 可打印链路，用机构真实数据跑起来——哪怕只上线这一个功能。"

只要这一个硬日期 + 一个功能，不要 392 条闸门。

**第 2 步｜冻结（止血）**
- 立刻停止生成新的 `governance_*` 套娃层。
- 把"第五版候选修订准备"那 492 个文件，**原样归档**（不删、不改正文），只在外面加一份 1 页纸的《治理演练结论备忘》，写明：这套东西证明了链路能跑通，但**暂停**，等自用落地后再回来。
- 作战室的 上下文.md / 任务板.md / 进度.md 三份文件，合并成**一份不超过 2 页的《当前战役》**，任务不超过 10 条。

**第 3 步｜task 重建（用 superpowers 的 checkbox 清单）**
按 superpowers 的 `- [ ]` 任务清单格式，把作战室任务板重写成一张人能看完、能动手的清单。建议结构：

```
当前战役：让记录填报+可打印在【硬日期】前跑起来
- [ ] 拍板"进入日常真实使用"的硬日期（只要一个日期）
- [ ] 确认 jewelry-qms 记录填报链路在本地能跑（谁、何时验证）
- [ ] 确认可打印/docx+pdf 导出能用
- [ ] 用机构 1-2 个真实记录模板试填（不是 26 个全量）
- [ ] 上线，跑一天真数据
- [ ] 第五版手册治理演练：归档暂停，备忘已留
```

砍到 ≤6 条，每条都能在一周内动起来。原来的 142 份产物，不在这张清单上——它们是"以后回来再说"的存档。
