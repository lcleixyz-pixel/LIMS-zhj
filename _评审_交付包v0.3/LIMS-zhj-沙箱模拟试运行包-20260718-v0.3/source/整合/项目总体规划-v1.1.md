# 实验室体系智能生态 · 项目总体规划 v1.1(2026-07-08)

> 本规划是全局纲领文件,建议两个仓库各存一份、同步升版。修订走版本行,不覆盖。

## 一、一句话愿景

给中小检验检测实验室一套"从建体系到过评审再到日常运行"的智能系统:**AI 写章程、平台管执行、机器守闸口、人只做拍板和签字**。

## 二、总体形态:三体一契

打个比方:这是一座衙门的完整班子。

| 部件 | 现状 | 角色(比喻) | 管什么 |
|---|---|---|---|
| **内容引擎**=技能套装 v1.21a | 4 技能+14 脚本+8 道金样,已实战 | 师爷 | 写文件、审文件、依据活水、方法论 |
| **运行平台**=jewelry-qms | ThinkPHP8,40+ 张表,治理闸门已建 | 衙门 | 受控发布、记录填报、内审/管评/CAPA 流转、设备提醒 |
| **测试工厂**=测试工装 v1.2+金样 | 5 画像+评分卡+归因台账,闭环已验证(R1→R2 涨分、P4 底线守住) | 考场 | 给两边的产出判卷,病根修回源头 |
| **接口契约**(待立,阶段1交付) | 早期工程包已验证通航,契约未成文 | 公文格式 | 两边怎么交接、谁记账、信号怎么传 |

外加一份**共有知识资产**:领域依据清单库(核实基准日制)、退场依据清单、领域包(现 5 个)、术语词典——这是抄不走的护城河,归内容引擎侧维护、平台侧消费。

## 三、全生命周期数据流(一个机构从进门到过评审)

```
画像采访 → 底稿构建 → 总装两册 → 【预导入闸】 → 平台受控发布 → 日常运行 → 迎审
(套装记账)………………………………↑事实源移交点↓………………(平台记账)…………
                                          运行证据回流:平台记录 → 内审核查/迎审举证
                                          变更信号双向:依据换版冻结 ⇄ 平台异常开CAPA
```

**唯一事实源移交规则(铁律)**:构建期以套装总台账为准;预导入 apply 过闸那一刻,记账权移交平台数据库;之后套装侧任何升版,必须重新过闸才能生效——**防止两本账各说各话**。

## 四、接口契约 v1.0(阶段 1 的头号交付物)

四块内容,纯 md,双仓同版:

1. **字段映射表**:K 卡↔qms_clauses、要素↔qms_elements、书架↔qms_sources、记录名 QR-xx↔record_form_templates、[K-xx] 回链↔block_links、P 表/F 卡↔配置项;
2. **预导入包格式规范**:以早期工程包实测格式为基线,升级到 v1.21a 产出格式,差异逐条列;
3. **事实源移交规则**(见上,写死);
4. **信号双向协议**:套装侧"依据换版冻结"→平台 qms_sources 状态;平台侧"记录异常/质控失败"→套装 CAPA 归因入口;intake_check --json 直接喂平台 ComplianceAssess。

契约治理:任何一侧改接口,契约先升版、双侧确认后实施——契约是第三条版本线。

## 五、路线图(五阶段,每阶段带验收标准)

| 阶段 | 干什么 | 验收标准(过了才进下一阶) |
|---|---|---|
| **0 现状盘点** | 已完成:套装成熟、平台闸门就绪、早期工程包通航验证 | ✅ 本规划发布即关闭 |
| **1 契约化**(近期) | 写契约 v1.0;用 v1.21a 的青禾产物重跑平台 dry-run(早期版本验证过,新版要复验);字段映射落库 | 契约双仓落库;新版产物 dry-run 发现项=0 |
| **2 自用落地**(当前重心) | 功能按使用频率上线:**记录填报+可打印(第一优先)**→运行控制(提醒/台账)→合规自查与内审管评;并行:弱模型量产 29 要素×判卷×预导入,清 392 条阻断 | **系统进入日常真实使用(硬日期【待拍板】)**;29 要素灌齐+语义签字齐;完成一次真实内审 |
| **3 运行闭环** | 运行证据回流(核查表直接吃平台数据);依据活水↔qms_sources 打通;**换版半自动链路**(哨兵报警→人取原文→AI候选修订包→人签→过闸)借下一次真实换版事件实战定型 | 一次内审零人工搬数;一次真实换版全链路走通 |
| **4 开源与外放** | 自用顺~1 个月后:生成部分开源(反馈通道先建);网页版走**邀请制+BYOK+不收费**(收数据迭代,规避公开经营性定性);自用 3 个月+一次真实内审后:LIMS 给熟识实验室(免费换反馈可先行) | 开源仓上线且首批外部反馈回流;≥1 家熟识实验室实际部署 |
| **5 公开收费**(远期,不设时限) | 前置齐备才启动:公司主体落地、生成式AI服务合规备案路径明确、试点验证付费意愿 | 首个付费客户走完"建体系→发布→真实运行 3 个月→过一次内审" |

**节奏铁律**:阶段 1 契约先行(卡脖子);阶段 2 的头号敌人是完美主义——"进入日常真实使用"的硬日期一旦拍板,到期必须上线跑真数据,哪怕只有记录填报一个功能;阶段 5 之前不做公开收费。

## 六、跨项目治理(把已验证的纪律升格为生态规矩)

1. **版本三线**:套装线(v1.x)、平台线(CHANGELOG/document_revisions)、契约线(v1.0 起)——各自记账,烧号必留行;测试工装挂套装线附属。
2. **金样制度推广**:套装 8 道金样已证明价值;平台侧建对应回归(预导入 dry-run 用固定夹具包),契约变更必跑双侧金样。
3. **红线全生态通行**:不代拍板、机判≠人签、模拟完成不得冒充真实执行(平台已内建 SIMULATED_COMPLETION 阻断,与套装停点同源)、诚信零容忍(P4 画像每三轮必考)。
4. **数据安全**:机构真实数据只进平台(本地部署);喂给公网 AI 的内容脱敏;弱模型生产线优先本地模型。
5. **知识资产维护**:依据清单库每季度对官方清单核对一次,核实基准日留痕——这条已写进 v1.21 规则,升格为生态级。

## 七、主要风险与对策

| 风险 | 对策 |
|---|---|
| 双账本漂移(历史上台账断档的放大版) | 事实源移交规则写死在契约;ledger_check 类机检扩到平台侧 |
| 契约失同步(一边改接口另一边不知道) | 契约第三版本线+双侧金样,改接口不升契约=金样红 |
| AI 幻觉内容入库 | 闸门链已四道:套装机判→语义签→预导入 dry-run→apply 人工评审;不减一道 |
| 一人项目单点风险 | 所有方法论已文档化+金样护栏,任何 AI/人可接手;建议关键拍板留痕习惯保持 |
| 版权合规 | 标准原文永不入分发包/开源仓;平台内机构自传,已由依据活水引导官方自取 |
| 完美主义(自用永远在打磨不落地) | 硬里程碑日期+节拍制监督;到期上线,用真实运行暴露问题 |
| 公开收费网页的合规暗礁(ICP备案/生成式AI服务管理办法/计费主体) | 近期只走开源自跑+邀请制BYOK不收费;公开收费押至阶段5,前置三条齐备才启动 |
