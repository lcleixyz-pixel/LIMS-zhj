# 活动级责任链与人员任命实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

- 版本：v0.1
- 日期：2026-07-14
- 对应设计：`docs/superpowers/specs/2026-07-14-活动级责任链与人员任命-design.md`
- 实施分支：`codex/activity-responsibility-chain`
- 实施边界：只在隔离 worktree 和隔离 MySQL 卷中开发验证；不迁移正式数据库、不建立真实人员任命、不部署。

**目标：** 在策划中心建立内审、管理评审、风险管理三条活动级责任链，允许未绑定人员时管理结构，完成资格校验与受控签批后生成正式任命证据，并沿第一阶段溯源链输出程序职责修订意见。

**架构：** 保留现有要素级责任总览，在其下新增“责任链版本—活动—职责项—人员草案—签批证据”五层数据。结构校验与生效校验分离；公司总经理身份来自公司治理证据，实验室主任由其签批，其他 QMS 任命由已生效的实验室主任签批。第一阶段手册—程序校验器通过适配服务读取有效责任链和确认别名，只输出差异，不写受控文件。

**技术栈：** PHP 8、ThinkPHP 8、ThinkORM、MySQL 8.4、ThinkPHP 模板、Bootstrap 5、现有 PHP smoke 测试、Docker Compose v5。

## 固定数据契约

首版只建立一个版本集合 `core_governance`，其中包含三个活动代码：

```php
[
    'internal_audit' => '内部审核',
    'management_review' => '管理评审',
    'risk_management' => '风险管理',
]
```

责任链版本状态固定为 `draft/pending_approval/effective/superseded/revoked`；人员绑定状态固定为 `draft/pending_approval/active/revoked/expired`；校验级别固定为 `pass/warning/blocker`；签批决定固定为 `pending/approved/rejected`。

责任槽必须明确 `slot_kind` 和 `assignment_mode`：

```php
[
    'slot_kind' => ['fixed_position', 'activity_role', 'dynamic_owner'],
    'assignment_mode' => ['named_person', 'activity_instance', 'derived_from_scope'],
]
```

`named_person` 在生效校验时必须绑定人员；`activity_instance` 和 `derived_from_scope` 在模板层显示“运行时指定”，不得误报为人员缺失。

```sql
CREATE TABLE IF NOT EXISTS `qms_responsibility_chain_versions` (
  `id` varchar(36) NOT NULL,
  `company_id` varchar(36) NOT NULL,
  `chain_code` varchar(100) NOT NULL,
  `version_no` int NOT NULL,
  `status` enum('draft','pending_approval','effective','superseded','revoked') NOT NULL DEFAULT 'draft',
  `content_hash` char(64) DEFAULT NULL,
  `replaces_version_id` varchar(36) DEFAULT NULL,
  `locked_at` datetime DEFAULT NULL,
  `effective_at` datetime DEFAULT NULL,
  `superseded_at` datetime DEFAULT NULL,
  `publish` tinyint(1) DEFAULT 1,
  `soft_delete` tinyint(1) DEFAULT 0,
  `created` datetime DEFAULT NULL,
  `modified` datetime DEFAULT NULL,
  `created_by` varchar(36) DEFAULT NULL,
  `modified_by` varchar(36) DEFAULT NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `company_chain_version` (`company_id`,`chain_code`,`version_no`),
  KEY `chain_status` (`chain_code`,`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

`site_scope_key` 在全实验室范围固定为 `*`，指定场所时等于 `site_id`，避免 MySQL 唯一索引对 `NULL` 允许重复而产生同一别名或同一人员绑定的重复记录。

`employee_appointments` 使用 `ADD COLUMN IF NOT EXISTS` 增加：

```sql
`source_kind` enum('legacy_document','corporate_evidence','responsibility_chain') NOT NULL DEFAULT 'legacy_document',
`source_chain_version_id` varchar(36) DEFAULT NULL,
`source_responsibility_id` varchar(36) DEFAULT NULL,
`source_approval_id` varchar(36) DEFAULT NULL
```

现有任命记录默认保留为 `legacy_document`，不得删除或批量改为责任链任命。`status` 枚举增加 `revoked`，保持原 `active/inactive/expired` 兼容。
