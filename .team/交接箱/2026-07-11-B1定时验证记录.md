# B1 验证记录：容器内定时 check:reminders

> 对应设计：`docs/superpowers/specs/2026-07-11-周期任务引擎B组-design.md` §B1  
> 验证日期：2026-07-11  
> 验证人：Cursor（代执行）

## 设计成功标准

> `docker compose up` 后，连续 3 天 `/tmp/reminders.log` 里有自动执行记录。

本次无法实等 3 天，改为：**接线验收 + 短周期自动触发证明 + 时区修正**。3 天连续观察作为上线后运营确认项。

## 验证前状态

| 项 | 结果 |
|---|---|
| 代码是否已实现 | 是（`docker/crontab` + `entrypoint.sh` 启 crond） |
| 运行中容器 | 已运行 35h，**未重建** → crond 未启动、crontab 未安装 |
| 容器时区 | UTC；`0 8 * * *` 实际等于北京时间 16:00 |

## 本次动作

1. `compose.yaml` 增加 `TZ: Asia/Shanghai`
2. `Dockerfile` 增加 `tzdata`、`/etc/localtime`、PHP `date.timezone`
3. `docker compose up -d --build app` 重建
4. 短周期注入下一分钟 cron，等待自动写入 `/tmp/reminders.log`（证明 crond 真会跑命令）
5. 再重建，恢复正式「每天 08:00」crontab

## 验证结果

| 检查项 | 结果 |
|---|---|
| entrypoint 日志含 `crond started` | ✅ |
| `crond -b` 进程在跑 | ✅ |
| `/etc/crontabs/root` = 每天 08:00 `check:reminders --type=all` | ✅ |
| 容器时间 | ✅ `CST` / `Asia/Shanghai`（例：2026-07-11 06:02:28） |
| 手动 `php think check:reminders --type=all` | ✅ 退出 0；calibration/capa/doc_review/competency 均返回 |
| 短周期 cron 自动写 `/tmp/reminders.log` | ✅ 约 75s 内出现 `QMS reminder check completed` |

## 结论

**B1 通过（接线 + 自动触发已证实）。**

- 设计方案（busybox crond、零新依赖）成立。
- 「连续 3 天日志」需从今日起观察：明天 08:00（上海时区）后执行  
  `docker compose exec app cat /tmp/reminders.log`  
  应有新记录；连续 3 天即完全满足原文成功标准。
- 注意：容器重建会清空 `/tmp/reminders.log`（tmpfs）；若要长期留痕，后续可改挂到 `runtime/reminders.log`（非 B1 必做）。

## 回滚

删 `docker/crontab`、还原 `entrypoint.sh` 中 crond 段、去掉 compose `TZ` / Dockerfile tzdata 后重建即可。
