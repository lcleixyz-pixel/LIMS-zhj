# LIMS-zhj 模拟试运行 · 幕2·场次2-5简报（模板复核扩大抽样）

> 版本：v0.1　日期：2026-08-15（系统内）/ 2026-07-17（真实）　场次：2-5（小张）
> 承接：2-1a场次（2026-08-01）模板复核工作的延续，把抽样范围从4条扩大到12条

## 一句话结论

这场戏做的事情，说白了就是"上次只抽查了4份文件，这次多抽12份，看看问题是不是真的普遍"。结果是：新抽的12条模板里，11条（92%）都能在系统里找到内容一模一样的"复制品"；把全部53条模板放在一起比对，47条（88.7%）都落在某个"重复分组"里。但比这个百分比更重要的是另一个数字——不管是上次抽的4条，还是这次抽的12条，"复核意见判定必须撤回重做"（也就是问题严重到不能靠改几个字段解决）的比例，两次都稳定卡在50%左右。这说明上次的"疑似"不是抽样运气不好蒙对的，这批AI生成的草稿模板，大概真的有一半左右带着没法简单修补的方向性错误。同时也有两个好消息：一是撞见了一份全库独一无二、明显被认真设计过的模板（不符合项报告），说明这批草稿不是无差别潦草；二是上次交出去的书面复核意见，其中2条已经被有权限的人按建议实际改了字段——证明"发现问题→反馈意见→有人处理"这条链路是真的在转，不是白提。

## 1. 这场戏说了什么

打个比方：这就像质检员上次抽查了一个批次里的4件产品，发现2件是同一个模具做出来的（不该一样却一样），写了报告说"建议扩大抽查范围"。这次任务就是照做——从51条待复核的AI生成模板里，专门挑了跟上次完全不沾边的12条：环境检查、消防安全检查、保密承诺书、泄密处理、公正性声明、利益冲突申报、投诉调查、不符合项报告、不符合跟踪表、管理评审通知、管理评审输入资料、样品流转单。

小张一开工就发现一个小插曲：列表里实际是53条，不是51条。多出来的2条都不在今天任务范围，如实记了一笔没有深挖——一条本来就不属于这批AI草稿（早就发布过了），另一条是今天才冒出来的一个空模板（字段一个都没有，不知道是谁、什么场景建的）。她也顺手回头看了上次抽查的那4条现状，发现了一个好消息：其中2条的字段已经被人按她当时的书面建议实际改过了，只是系统里"复核状态"那个标签还没有从"待复核"正式扭转成"已确认"——相当于活儿干完了，但没有盖上最后那个章。

核对过程中她撞上一个障碍：模板详情页只显示"这个字段叫什么、什么类型"，如果这个字段是一张"子表格"（比如"记录明细"里面还有好几列，像Excel里的一张小表），页面完全不会展开显示这张小表里到底有哪几列。想从"编辑"或"填写记录"两个入口绕进去看，一个被权限挡住，一个因为模板还是草稿状态点不动。最后只能改用直接查数据库这种更底层的办法去核实，并且如实记录"这不是我在页面上亲眼看到的，是查数据库查到的"，没有含糊其辞。

拿到12条的字段清单后，她没有因为"反正都是复制粘贴"就一刀切给结论，而是每一条都按"这份文件本该记录什么内容"重新判断了一遍——同样一套字段，套在"利益冲突申报表"上凑合能用（因为一个人确实可能同时申报好几件事），套在"保密承诺书"上就完全文不对题（承诺书是一次性声明，不是可以重复添加条目的检查表）。这种"字段一样、结论不一样"的判断方式，跟上次（2-1a场次）用的方法完全一致，这次在12条样本上又验证了一遍，站得住。

## 2. 两条最值得你注意的发现

**子表内部结构，复核人员在页面上完全看不到**：现在系统里凡是"记录明细"这种可以填好几行的表格字段，具体这张小表里有哪几列，复核页面根本不显示，也没有任何"展开"按钮之类的设计——不是加载慢，是页面代码压根没写这部分。想看，只有两条路：编辑（权限不够，进不去）或者试填一份记录（模板还在草稿状态，功能锁着，也进不去）。等于说，复核人员要判断一份模板设计得好不好，最关键的"细节列表"这部分内容，被结结实实地挡在页面外面。今晚只能靠直接查数据库这种复核人员本来不该需要的手段才绕过去，这个入口缺失本身就值得优先解决。

**"复制粘贴指纹"更普遍了，但"真出问题"的比例没有恶化，反而更确定了**：这次92%的新抽样都带复制粘贴痕迹，比上次的50%要高不少，乍一看像是"情况变严重了"。但仔细看"复核结论"这个更实质的指标——上次4条里2条判定要撤回重做（50%），这次12条里6条判定要撤回重做（还是50%）——两次抽样完全一致。这说明真实情况从一开始就是"这批草稿大概有一半左右存在没法简单修补的问题"，不是这次抽样运气差撞见了更烂的部分，也不是问题在扩散变多。两次独立抽样给出同一个比例，本身就是这批51条模板需要系统性返工、而不是零星小修的一个比较有力的证据。

## 3. 新发现一览（6条，另有3条正面观察）

| 编号 | 现象 | 严重度 |
|---|---|---|
| F-2-5-01 | 模板详情页看不到"子表"（可重复添加行的小表格）里具体有哪些列，"编辑"和"填写记录"两个本可能露出这部分内容的入口分别被权限和状态挡住，复核人员没有任何界面途径核实子表设计得合不合理 | B |
| F-2-5-02 | 环境检查、消防安全检查、保密承诺书、泄密处理、公正性声明、利益冲突申报——6份业务上毫不相关的记录，字段完全相同（全库这套字段共被用了15次），但同一套字段落到不同记录上后果差异很大：检查类的凑合能用，声明/事件类的（保密承诺书、泄密处理、公正性声明）结构性文不对题 | B |
| F-2-5-03 | "管理评审输入资料"套用的是"受控文件发放回收登记表"的专用字段（发放/回收/借阅/置换/作废/登记这几个选项），跟"评审要汇总哪些材料"这件事毫无关系，是本场匹配度最差的一组（还牵连另外3份完全不相关的记录） | B |
| F-2-5-04 | "不符合工作及纠正措施跟踪表"名字里带"跟踪"两个字，字段却一个跟踪功能都没有（没有责任人、没有期限、没有验证状态、没有关闭日期），实际套用的是"内部审核检查表"的字段，推测是"审核"这个词同时对应"内部审核"和"报告审核/批准"两种含义，生成时被搞混了 | B |
| F-2-5-05 | "管理评审通知"字段里包含"决议"和"跟踪验证"——这些内容按常理只该在开完会以后才有，但"通知"应该是开会前发的，时间线对不上；该有的"通知发放范围""签收确认"反而一个都没有 | B |
| F-2-5-06 | "样品流转单"及其3个变体（含2份"高价值样品"专用记录）子表里完全没有"签名/签收确认"这一列，样品从谁手上转到谁手上说不清楚，高价值样品场景风险更突出 | B |

正面观察：①"不符合项报告"字段结构全库独一无二，时间戳核对确认是生成后从未被人动过的原生设计，从发现到归责到纠正到验证关闭整条链路都齐全，是本场唯一一条不用改就能发布的模板；②"投诉调查记录"虽然字段也被复用了5次，但套在这份记录上恰好合适，证明"字段被复制粘贴"和"字段有问题"不能划等号；③本场在"管理评审通知"上做了一次编辑权限拦截的印证测试，结果与2-1a场次完全一致，未在其余11条上重复测试、没有浪费操作次数。

## 4. 12份模板逐一复核结论（本场核心交付物，建议直接转给有编辑权限的人处理）

| 模板 | 复核结论 | 为什么 |
|---|---|---|
| 环境检查记录 | 改字段后发布 | 骨架基本够用，建议加"检查区域/位置"、把结果拆成"标准要求+实测值" |
| 消防/安全检查记录 | 改字段后发布 | 跟环境检查记录问题相同，属于"检查类"记录，通用骨架凑合能用 |
| 保密承诺书 | 建议撤回重做 | 这是"一人一份声明"，不该套"可重复添加多行"的检查表结构，缺"保密期限""涉密范围"这些核心字段 |
| 泄密事件处理记录 | 建议撤回重做 | 该长得像"原因-措施-责任人-期限-状态"的处理跟踪结构，现在套的是检查类骨架，没地方记密级、责任认定、上报情况 |
| 公正性声明 | 建议撤回重做 | 跟保密承诺书同样的问题，个人声明文件被套上了检查表结构 |
| 利益冲突申报表 | 改字段后发布 | 字段跟前面3条一样，但这次凑巧合适（一人可能同时申报好几件事，正好用得上"可重复添加"的结构），只需把列名改精确 |
| 投诉调查记录 | 可发布 | 原因-措施-责任人-期限-状态-验证结论，链路完整，本场唯一无需大改的两条之一 |
| 不符合项报告 | 可发布 | 全库独一无二的认真设计，发现-归责-纠正-验证关闭全覆盖 |
| 不符合工作及纠正措施跟踪表 | 建议撤回重做 | 名字叫"跟踪表"但没有一个跟踪相关的字段，疑似"审核"一词歧义导致生成时张冠李戴 |
| 管理评审通知 | 建议撤回重做 | 字段是"会后决议"该有的内容，被安到"会前通知"这个环节，时间线矛盾 |
| 管理评审输入资料 | 建议撤回重做 | 本场错位最严重的一条，套用的是完全不相关的"文件发放登记"字段 |
| 样品流转单 | 改字段后发布 | 核心信息都在，只缺"移交人/接收人"和签名列，加上即可，不用推倒重来 |

小结：可发布2条、改字段后发布4条、建议撤回重做6条。这12条只是51条待复核草稿模板里的一部分，具体怎么记该以真实的程序文件为准——小张这次判断依据主要是"看名字、凭常识"，因为她手头没有这12类记录对应的专门程序文件原文，这一点她自己在台账里也如实标注了，供参考、不是最终定论。
