# P0 回归矩阵

> 版本：v0.1  
> 日期：2026-07-17  
> 环境：自动化在隔离 MySQL 8.4 测试库；页面验收在本机 8010 的专用测试数据集。  
> 数据前缀：`P0R13B-`；测试完成后按清单清理，不接触真实质量记录。

## 1. 结果规则

- `PASS`：期望结果和证据均齐全。
- `FAIL`：行为不符、数据计数异常、出现 500/调试栈或审计缺失。
- `BLOCKED`：业务矩阵未批准、云端预检阻断等外部条件；不得记作 PASS。
- 每个写入案例保存：请求前计数、请求响应、目标记录、关联记录、审计记录和清理结果。

## 3. RC-02 编号、关联与事务

| ID | 层级 | 场景 | 关键步骤 | 通过标准 | 证据 |
|---|---|---|---|---|---|
| L01 | 单元 | 编号从 001 到 002 | 预置 `CP2026001` 后生成 | 得到 `CP2026002`，不重复年份 | smoke 输出 |
| L02 | 单元 | 异常旧编号不参与计算 | 预置 `CP20262026002` 和合法 001 | 下一号仍按合法后缀生成 002 | smoke 输出 |
| L03 | DB | 编号唯一性 | 尝试写入重复投诉/CAPA/NC 编号 | 被明确拒绝，原数据不变 | 异常+计数 |
| L04 | 集成 | 投诉创建 CAPA | 由获权人员执行一次 | CAPA 和投诉 `capa_id` 为同一 UUID | 双表查询 |
| L05 | 集成 | 重复点击创建 CAPA | 同一来源执行两次 | 第二次返回既有记录；总数仍 1 | 计数+响应 |
| L06 | 集成 | 不符合创建 CAPA | 执行后从两端打开 | 双向链接均显示业务编号 | 两页截图 |
| L07 | 事务 | 来源回写失败 | 在隔离库制造约束失败 | CAPA 创建整体回滚，0 孤儿记录 | 事务查询 |
| L08 | 负向 | 无效来源 UUID | 直接调用不存在记录 | 4xx/领域错误；0 写入 | 响应+计数 |
| L09 | 页面 | 创建成功后的跳转 | 点击创建 CAPA | Location 使用真实 36 位 UUID，目标 200 | HTTP 头+截图 |
| L10 | 预检 | 本机/云端数据扫描 | 运行只读预检 | 输出重复、数字 ID、孤儿和反向不一致计数 | 预检报告 |

| A04 | 服务 | 场所协调人处理投诉 | 场所质量协调人 | 仅任命范围允许 |

| A06 | 服务 | 设备编辑 POST | 内审员 | HTTP 403；设备和字段审计均不变 |
| A07 | 服务 | 设备维护写入 | 乌鲁木齐设备管理员 | 乌鲁木齐允许、和田拒绝 |
| A08 | 服务 | 设备维护写入 | 和田设备管理员 | 和田允许、乌鲁木齐拒绝 |
| A09 | 服务 | 模板复核清单 | 资料管理员 | 允许查看 |
| A10 | 服务 | 模板发布 | 资料管理员 | 未具批准任命时拒绝 |
| A11 | 服务 | 模板发布 | 质量负责人/批准岗位 | 允许并记录批准岗位 |
| A12 | 服务 | CAPA 编辑 | 被指派责任人 | 可改措施，不可验证关闭 |
| A13 | 服务 | CAPA 关闭 | 未获验证权限的责任人 | HTTP 403；状态不变 |
| A14 | 服务 | 能力确认 | 技术负责人 | 仅任命场所人员允许 |
| A15 | HTTP | 越权直接 POST | 任一无权账号 | HTTP 403，不经重定向变成 200 |
| A16 | 失效 | 任命过期/作废 | 原获权账号 | 立即失去动作权限 |

> A04、A07、A08、A10～A14 在岗位动作矩阵人工批准前状态只能是 BLOCKED，不能由开发自行改成 PASS。

## 7. 总闸门

- 自动化案例：全部 PASS。
- 业务授权案例：人工批准后全部 PASS；未批准项保持 BLOCKED，禁止上线相关动作授权。
- 页面案例：0 个 500、0 个调试栈、0 个错误 UUID 跳转、0 个越权写入。
- 数据：0 个重复编号、0 个数字型关联、0 个孤儿 CAPA、0 个反向不一致。
- 证据：测试数据清单、截图目录、数据库摘要和执行日志齐全。
