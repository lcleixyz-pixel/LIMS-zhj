# P0 可信记录修复实现计划

> **面向 AI 代理的工作者：** 实施时使用 executing-plans，逐任务执行并在每批后审查。不得在当前脏工作区直接实现；先从批准的集成基线建立独立 worktree。

**目标：** 修复 RC-01～RC-04，使关键质量记录字段一致、关联可靠、动作授权准确、变更可追溯。

**架构：** 保留 ThinkPHP 8 和现有模型；用模块字段白名单收紧 CRUD，用事务化 WorkflowService 保证 CAPA 双向关联，用岗位任命驱动动作授权，用增强后的 FieldAuditService 覆盖关键模型。所有改动先写失败 smoke，再最小实现。

**技术栈：** PHP 8.4、ThinkPHP 8、MySQL 8.4、Docker Compose、现有 PHP smoke、Playwright 页面复验。

- [ ] 扩展审计字段白名单，新增等价值比较：

```php
private static function valuesEquivalent(string $field, mixed $old, mixed $new): bool
{
    if ($old === null || $old === '') {
        return $new === null || $new === '';
    }
    if (str_ends_with($field, '_date')) {
        return substr((string)$old, 0, 10) === substr((string)$new, 0, 10);
    }
    return (string)$old === (string)$new;
}
```

## 计划自检

- 规格覆盖：RC-01～RC-04 均有实现任务和回归案例。
- 数据边界：预检只读；修复须快照和人工映射。
- 权限边界：第 5 任务有业务批准停点。
- 环境边界：SQLite 仅可做轻量语法测试，最终结论必须来自 MySQL 8.4。
- 发布边界：计划结束只形成候选包，不自动部署云端。
