# 云服务器体验测试部署实施计划 v0.2

> **面向 AI 代理的工作者：** 必需子技能：使用 `executing-plans` 逐任务实施；每个涉及云服务器写入、软件安装、端口调整或域名配置的任务，必须先取得用户单独授权。步骤使用复选框（`- [ ]`）跟踪进度。

**目标：** 在不影响云服务器现有网页的前提下，将 `jewelry-qms` 部署为供实验室人员体验、熟悉和测试的临时环境。

**架构：** 云服务器上的宝塔 Nginx 继续承载现有网页，并通过独立测试子域名和站点级 BasicAuth 反向代理到仅监听 `127.0.0.1:18010` 的 Jewelry QMS 容器。数据库只挂封闭内网；应用同时挂数据库内网与普通边缘网络，使回环端口发布稳定可用。Mac 仍是开发环境，但必须以 `linux/amd64` 构建、运行验证并导出应用与 MySQL 镜像包；云端只加载这批已验证镜像，不再临时访问 Docker Hub 重建。

**技术栈：** 宝塔 Linux 面板 11.1.0、Nginx、BasicAuth、Docker Engine、Docker Compose、Buildx/QEMU、ThinkPHP 8、PHP 8、MySQL 8.4、Node.js/Chromium、HTTPS。

## v0.2 审核修订摘要

1. 数据库保留封闭内网，应用增加普通边缘网络，避免 `internal: true` 使回环发布端口失效。
2. 默认使用本机生成的 `linux/amd64` 应用与 MySQL 镜像包，云端 `docker load`，不依赖服务器直连 Docker Hub。
3. Mac 上以 QEMU 运行 amd64 候选环境，并在该架构下验证 Chromium/PDF。
4. 移除体验环境 `node_modules` 卷，依赖在镜像构建期固定；升级后只清框架缓存，不删除整个 runtime 卷。
5. 增加隔离 MySQL 容器恢复演练，快照不再只存不验。
6. 测试子域名在应用登录前增加 BasicAuth。
7. 优先使用现有已备案主域名的测试子域名；新域名须先确认备案。
8. 增加日志轮转与保守磁盘清理，明确禁止共享服务器执行全局破坏性 prune。

- 不作为正式生产系统，不录入检测报告、客户资料、人员身份证明或受控体系原件。

- 不将宝塔面板、SSH、MySQL、容器内部端口全面开放公网。
- 不把 Mac 本机的现用数据库或 `public/uploads/` 直接搬到云端。
- 不在云服务器目录内直接编辑业务代码。
- 不执行 QMS 正式受控发布、真实审批或生产库写入。

- [ ] **步骤 2：创建体验环境 Compose**

`jewelry-qms/deploy/experience/compose.yaml` 使用以下完整结构：

```yaml
name: jewelry-qms-experience

services:
  db:
    image: jewelry-qms-mysql:8.4-amd64
    platform: linux/amd64
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD:?MYSQL_ROOT_PASSWORD is required}
      MYSQL_DATABASE: ${MYSQL_DATABASE:-jewelry_qms_experience}
      MYSQL_USER: ${MYSQL_USER:-jewelry_qms}
      MYSQL_PASSWORD: ${MYSQL_PASSWORD:?MYSQL_PASSWORD is required}
      TZ: Asia/Shanghai
    volumes:
      - db_data:/var/lib/mysql
      - ../../database/jewelry_qms.sql:/docker-entrypoint-initdb.d/01-jewelry-qms.sql:ro
    healthcheck:
      test: ["CMD-SHELL", "mysqladmin ping -h 127.0.0.1 -uroot -p\"$${MYSQL_ROOT_PASSWORD}\" --silent"]
      interval: 10s
      timeout: 5s
      retries: 20
      start_period: 30s
    networks:
      - qms_db_internal
    logging:
      driver: json-file
      options:
        max-size: 10m
        max-file: "3"

  app:
    image: jewelry-qms-experience:${QMS_IMAGE_TAG:?QMS_IMAGE_TAG is required}
    platform: linux/amd64
    restart: unless-stopped
    depends_on:
      db:
        condition: service_healthy
    environment:
      APP_DEBUG: "false"
      TZ: Asia/Shanghai
      DB_TYPE: mysql
      DB_HOST: db
      DB_NAME: ${MYSQL_DATABASE:-jewelry_qms_experience}
      DB_USER: ${MYSQL_USER:-jewelry_qms}
      DB_PASS: ${MYSQL_PASSWORD:?MYSQL_PASSWORD is required}
      DB_PORT: "3306"
      DB_CHARSET: utf8mb4
      DEFAULT_LANG: zh-cn
      QMS_ENV_LABEL: 体验测试环境
      QMS_ENV_NOTICE: 禁止录入正式业务数据、客户资料或其他敏感信息
      PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD: "1"
      PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH: /usr/bin/chromium-browser
    ports:
      - "127.0.0.1:${QMS_HOST_PORT:-18010}:8000"
    shm_size: "256mb"
    volumes:
      - runtime_data:/app/runtime
      - uploads_data:/app/public/uploads
    networks:
      - qms_db_internal
      - qms_edge
    logging:
      driver: json-file
      options:
        max-size: 10m
        max-file: "3"

networks:
  qms_db_internal:
    internal: true
  qms_edge:

volumes:
  db_data:
  runtime_data:
  uploads_data:
```

关键检查：`db` 只挂 `qms_db_internal` 且不得出现 `ports`；`app` 同时挂 `qms_db_internal` 与 `qms_edge`，只能绑定 `127.0.0.1`；不得挂载云服务器源码目录或 `node_modules` 卷到 `/app`。

```bash
  -f current/jewelry-qms/deploy/experience/compose.yaml exec -T app php think list \
  | grep -qE '^[[:space:]]+clear([[:space:]]|$)'; then
  docker compose --env-file shared/.env \
    -f current/jewelry-qms/deploy/experience/compose.yaml exec -T app php think clear
fi
```

不得删除 `runtime_data` 卷。随后运行 `verify.sh`、登录页检查和三个核心 smoke；现有网页也要重新检查。

- [ ] **步骤 5：演练一次回退**

把 `current` 切回上一个 release 和该 release 对应的已加载镜像 tag，重新执行 Compose `up -d --pull never`，确认登录页和模拟数据可用；随后根据验收结果决定保持旧版还是重新切回新版。

- [ ] **步骤 6：执行保守的磁盘维护检查**

```bash
docker system df
df -h /
docker image prune -f
find /www/server/jewelry-qms-experience/releases \
  -mindepth 1 -maxdepth 1 -type d -print | sort
```

镜像命令只删除悬空层；release 目录只列出不自动删除。需要删除旧 release 时，先确认当前版、上一版和一个已验证版本已经保留，再单独取得用户授权。禁止执行 `docker system prune -a` 和 `docker volume prune`。

- [ ] **步骤 7：确定体验期复盘点**

体验运行 1–2 周后整理：人员反馈、内存峰值、磁盘增长、PDF 成功率、使用频率。届时再决定继续使用云服务器、迁移 NAS，或升级为正式生产方案；本计划不自动升级为生产部署。

## 计划自检结论

- **范围：** 仅覆盖体验测试部署，不扩展到正式生产、真实数据迁移、NAS 选型或高可用。
- **隔离：** 现有网页、BasicAuth、应用边缘网络、数据库封闭内网和运行数据边界已分别定义。
- **验证：** 包含本地 amd64 候选验证、镜像包校验、云端自动验证、浏览器验收、重启持久化、隔离数据库恢复及 release 回退演练。
- **敏感信息：** 密码只在服务器本地生成和保存，不进入 Git、聊天或交接文档。
- **停点：** G1 之前只读；G2 之前不执行任何云服务器写入。
