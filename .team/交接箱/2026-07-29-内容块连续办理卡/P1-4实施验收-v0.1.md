## 一、完成内容

- 文件治理工作台把同一内容块的追溯问题、既有关系和可办理候选聚合为一张连续办理卡。
- 每张卡保留一个“处理此内容块”主入口；卡片和既有关系入口只带 `block_id`，进入整块关系复核页，不携带无用途的 `link_id`。
- 候选入口保留与当前对象严格匹配的 `block_id + candidate_kind + candidate_id` 三元组；其它查询形状全部清空。
- 卡片模型使用单卡 `issue_count` 和 `review_url`；卡片显示章节编号、内容块标题、问题标签、动态办理步骤、关系或候选对象上下文，避免只看到内部标识。
- 办理步骤按实际问题生成并连续编号：关系混装、疑似错挂、可用候选、等待复核依次出现；`missing_primary` 由候选步骤承接，不虚构其它问题。
- 长问题和候选明细使用原生折叠区，首屏保留摘要、优先级和主入口。
- 移动端改为单列和全宽操作入口；键盘焦点、读屏名称和颜色对比按现有工作台样式补强。
- 页面只导航到既有关系复核页，不新增提交表单、写路由或自动办理动作。

## 四、已关闭审查问题摘要

| 审查问题 | 关闭结果 |
|---|---|
| URL 只读门禁 | 服务端只接受严格路径 `/planning/structures/links/review`、严格 `GET`，并拒绝 fragment、user、host、scheme、反斜杠、控制字符、未知键、重复键、数组键值、空值、对象错配和任意层编码歧义。 |
| 查询形状 | 仅允许两种完整查询形状：卡片和既有关系入口只带 `block_id`；候选入口带 `block_id + candidate_kind + candidate_id`，候选类型和 ID 必须与当前对象严格匹配。 |
| 动态步骤 | 每卡只按实际问题生成步骤，顺序固定为混装、错挂、候选、待复核，代码去重并连续编号；仅缺主链时只显示候选步骤。 |
| 模型字段 | 每卡使用 `issue_count` 和 `review_url`；模板不再自行计数，也不保留 `primary_url` 别名。 |
| 状态色 | 问题项保留文字状态和 `data-severity`；blocked 使用 `var(--qms-bad)`，review 使用高对比深警告色 `#7a4510`。 |
| 长卡折叠 | 详细问题和候选进入原生 `details` 折叠区，摘要和主要动作不被隐藏。 |
| 对象上下文 | 问题和候选显示章节、关系类型、对象编号或业务名称，不再只显示内部 ID。 |
| `aria` 无 UUID | 读屏名称使用可见动作、章节编号和内容块标题，不把 UUID 作为用户可听名称。 |
| 对比度 | 优先级、辅助文字、焦点和按钮颜色已按现有浅色背景调整；最终实页对比仍由主代理在 8021 浏览器验收。 |
