## 1. 使用边界

1. 本矩阵定义的是“岗位职责和目标权限边界”，不是对真实人员任命、能力或授权范围的确认。
2. 用户已确认总体质量负责人为张晓磊、总体技术负责人为刘恒春，乌鲁木齐和和田两场所负责人均为正式负责人；但本轮尚未取得对应任命文件，因此只能记为“机构确认、书面证据待核”。
3. 8011 演练只使用 `SIM-*` 人员、账号、岗位和业务数据。真实姓名不得用于沙箱登录、审批、签发或运行记录。
4. 系统权限由两层共同决定：
   - `users.role`：控制模块入口和一般页面访问；
   - `qms_positions` + 有效 `employee_appointments`：控制业务动作、场所范围和任命时效。
5. 登录成功、看见菜单、拥有 `admin` 或 `quality_manager` 软件角色，均不能单独证明具备业务批准、验证或报告签发资格。
6. 本文中的“允许”均附带前提：任命已批准、已生效、未到期/撤销，岗位处于 `published`，人员和账号有效，且场所、标准、项目、参数和设备范围均命中。

### 4.1 动作含义和限制

| 动作 | 控制含义 |
|---|---|
| 查看 | 仅查看业务所需最小范围；内审员可查看被指派场次证据，但不能因此取得编辑权 |
| 发起 | 创建草稿、登记投诉/不符合、提出修订或新建任务；不等于批准 |
| 编辑 | 只编辑本人职责范围内、未冻结或未批准的记录；所有更正应保留原值、时间、人员和原因 |
| 复核 | 检查技术、质量或形式完整性；复核人与原执行人应按风险分离 |
| 批准 | 使计划、决定或文件候选进入获准状态；须明确批准对象，不能用泛化“负责人” |
| 授权签发 | 对检测报告作最终技术授权；仅授权签字人在具体授权范围内执行 |
| 执行 | 实施检测、设备维护、样品流转、内审、整改或管理评审措施 |
| 验证 | 独立确认结果或措施有效性；不得由原执行人自验 |
| 关闭 | 在证据齐全、验证通过后改变最终状态；不是删除记录 |
| 权限授予 | 基于经批准任命/授权，把业务岗位映射到账号动作权限 |
| 权限回收 | 任命到期、撤销、离任、调岗或授权范围缩小时及时阻断后续动作，同时保留历史证据 |

## 6. 岗位任命、替代和离任回收

### 6.1 任命驱动规则

业务动作仅在下列条件同时满足时生效：

1. 人员、账号均有效且属于当前机构；
2. `qms_positions` 岗位为 `published`、未软删除；
3. `employee_appointments` 为 `active`、已发布、未软删除；
4. `appointed_at` 不晚于业务日期，`valid_until` 为空或不早于业务日期；
5. `site_id` 为空表示全机构范围；非空时只命中该场所；
6. 具体业务还应命中标准、项目、参数、设备、报告类型等专项授权；本机构 CNAS 处于初次认可申请筹备阶段，当前不存在 CNAS 认可标识使用或认可签发权限；
7. 无业务任命时应拒绝动作，即使 `users.role` 允许进入模块。

### 6.2 替代关系

| 原岗位 | 允许的替代方式 | 不允许的推定 |
|---|---|---|
| 实验室主任 | 仅由预先书面指定、具有明确起止日期和事项范围的代理人替代 | 质量负责人、技术负责人、场所负责人或公司总经理自动替代 |
| 总体质量负责人 | 预先任命的质量负责人代理；应明确全机构或特定事项范围 | 场所负责人或资料管理员自动上升为总体质量负责人 |
| 总体技术负责人 | 预先任命的技术负责人代理；应明确方法/项目/场所范围 | 授权签字人或检测室主任自动替代 |
| 场所负责人 | 仅由该场所正式指定代理人，在该场所和有效期内替代 | 两场所负责人相互当然替代 |
| 授权签字人 | 只能由另一名授权范围实际覆盖该场所、标准、项目、参数和标志的授权签字人替代 | 实验室主任、技术负责人或系统管理员凭岗位签发 |
| 内审员/验证人 | 可由另一个具备能力且无利益冲突的被指派人员替代 | 被审核活动执行人自审、自验 |

替代任命不得覆盖原记录；应形成新任命或代理记录，包含被替代岗位、人员、范围、原因、起止日期、批准人和回收状态。

### 6.3 离任和权限回收

触发条件包括离职、调岗、任命到期、撤销、暂停、能力不再满足、认可/资质范围变化和场所变化。回收应：

1. 将任命改为 `expired`、`revoked` 或 `inactive`，保留历史记录；
2. 阻断后续新增、修改、复核、批准、验证和签发动作；
3. 回收或调整 `users.role`、菜单和接口权限，但不得删除历史操作者身份；
4. 复核未完成任务、待签报告、在途样品、设备授权和 CAPA；
5. 记录回收原因、时间、执行人、复核人和受影响范围；
6. 对替代人员重新履行任命、能力和授权核验，不得复制原权限后默认有效。

| 实验室主任 | 责任链目录有 `lab_director`，管理评审最终批准和内审计划批准指向该岗位 | 8011 已铺设 `SIM-E-DIR`；管理评审主持/批准岗位与时序回归通过 |
| 场所负责人 | 冻结事实已明确两名正式场所负责人；8011 已铺设两场所 SIM 任命 | 场所隔离回归通过；当前使用 `site_quality_coordinator` 活动岗位映射，是否等同正式场所负责人职责仍须程序和任命文件确认 |
| 授权签字人 | 岗位目录和 SIM 身份存在 | 未见报告签发动作按场所—标准—项目—参数—标志的完整门禁，标为 `待实现` |
| 样品管理员 | 岗位目录和 SIM 身份存在 | 未见样品接收、流转、保存、处置的动作级门禁，标为 `待实现` |

| 系统管理员越权防护 | 基础 `RbacService` 允许 `admin` 访问全部模块；动作授权服务不以 `admin` 直接替代业务任命 | 必须确保所有高风险 POST 均接入动作授权，不能只依赖控制器级 RBAC |

## 8. 报告与 CMA/CNAS/非认可边界

### 8.1 授权签发的最小匹配字段

授权签字人在签发前至少应同时命中：

- 有效人员和账号；
- `authorized_signatory` 有效任命；
- 场所；
- 标准及其版本；
- 检测对象、项目和参数；
- 授权有效期；
- CMA、CNAS 或非认可报告类型；
- 适用时的设备、方法确认/验证状态和判定规则。

任何一个字段缺失、不匹配或证据状态为“待核”，系统均应拒绝认可标志签发；不得退化为“只要是授权签字人就可签全部报告”。

### 8.2 本轮方法和标志边界

| 方法范围 | CMA 报告 | CNAS 报告 | 非认可/不带标志报告 |
|---|---|---|---|
| 两场所共同开展的 GB/T 16552、16553、38821、GB 11887 + 修改单、GB/T 18043 | 只有能力附表和“一单一库”逐项命中后才可选择；本轮证据未齐不得宣称已获授权 | 初次认可申请筹备范围；当前尚未提交、未受理、未获认可，**不得使用 CNAS 标志或认可声明** | 在合同已明确、机构具备能力且满足其他法规要求时可按受控规则出具 |
| DB65/T 035-2010、DB65/T 3442-2013、DB65/T 4828-2024 | **不得使用 CMA 标志** | 初次认可拟申请准备范围；当前尚未提交、未受理、未获认可，**不得使用 CNAS 标志或认可声明** | 可作为本轮 SIM 正常分流场景，但必须明确非 CMA、CNAS 尚未认可 |
| GB/T 44914-2024 和田玉分级 | 本轮不体现 | 本轮不体现 | 本轮不体现 |
| 抽样、留样、分包、钻石分级 | 本轮不开展 | 本轮不开展 | 本轮不开展 |

### 8.3 报告职责分离

| 动作 | 目标岗位 |
|---|---|
| 原始检测及记录 | 获对应方法、项目、设备和场所授权的检测员 |
| 原始记录/结果复核 | 与检测执行人不同、具备对应能力并被指派的复核人 |
| 报告编制 | 被授权的报告编制岗位 |
| CMA/CNAS/非认可属性选择 | 合同评审结果驱动；由报告复核岗位复核；本轮不得选择 CNAS 认可报告 |
| 最终授权签发 | 授权范围实际命中的授权签字人 |
| 报告归档 | 资料管理员或报告档案责任岗位 |
| 报告修改/替换 | 原报告可追溯，重新履行复核和授权签发，不得覆盖原版 |

## 9. 完整演练前必须补齐的权限测试

1. 补做 `SIM-实验室主任` 对内审年度计划批准的页面级反向测试；管理评审主持/批准岗位与时序已经通过。
2. 将乌鲁木齐、和田场所负责人从活动岗位映射校准为经程序和任命文件确认的正式岗位代码，并保留已通过的场所隔离规则。
3. 统一 `testing_personnel` 与规范岗位 `testing_staff` 的代码，建立检测任务、方法、设备和场所授权。
4. 为 `training_manager` 明确规范岗位或活动角色，验证培训计划、记录维护、能力确认、授权批准相互分离。
5. 建立报告签发动作门禁，覆盖场所、标准、项目、参数、有效期和 CMA/CNAS/非认可属性；CNAS 在未获认可前应强制禁用。
6. 建立样品接收、标识、流转、保存和处置动作门禁；不生成抽样、留样场景。
7. 对所有高风险 POST 做“无任命、任命过期、任命撤销、错场所、错标准、错参数、直接请求”反向测试。
8. 验证离任或责任链换版后旧任命立即回收，新任命未获批准前不得提前生效。
9. 验证系统管理员只能执行经批准的技术配置，不能自行产生业务批准、验证或报告签发证据。

## 10. 结论

现有代码已经具备“登录 RBAC + 业务岗位任命 + 场所/时效动作门禁”的正确骨架，并对设备、文控、内审、投诉、CAPA 等部分高风险动作形成了可测试控制。

但当前尚不能把角色权限判为完整闭环，主要阻断是：

- 实验室主任和两场所负责人虽已完成 SIM 铺设，但场所负责人活动岗位代码与正式职责的等同性仍待程序/任命文件确认；
- 授权签字人未形成场所—标准—项目—参数—标志的签发门禁；
- 样品、检测、培训岗位的动作授权尚未闭合；
- 检测岗位和培训岗位代码与规范目录存在不一致；
- 真实任命文件、授权签字范围、CMA/CNAS 能力附表尚未取得。

因此本文结论为：**角色权限模型可进入完整沙箱整改与复演，但仅为治理候选，不构成真实任命、真实授权或认可范围验证。**
