- 版本：v0.1
- 日期：2026-07-14
- 运行地址：<http://127.0.0.1:8010/login/index>
- 被测代码：`main` / `07f7511cc62bc0d8f3c88d60f7f64dfbe81c4a96`
- 环境性质：本机测试环境；禁止录入正式客户资料和敏感信息

## 一、登录

- 用户名：`admin`
- 密码：`password`

当前本机数据库已核验该默认密码可用。测试结束后如继续长期使用，应修改默认密码。

## 二、第一轮：安全体验（推荐先做）

1. 登录后打开“体系策划 → 责任链”。
2. 点击“建立初始草案”。
3. 在“责任结构”页确认：
   - 活动共 3 项：内部审核、管理评审、风险管理；
   - 职责共 21 项；
   - 固定岗位职责尚未选人时，应显示“岗位尚未绑定人员”；
   - 运行时角色或动态责任人应提示在具体活动实例中确定。
4. 打开“校验与签批”，点击“检查责任结构”。人员未配置时应得到 `warning`，但草案仍可保存。
5. 打开“文件对齐”。草案默认不会被当成现行事实；如需查看预演，点击“明确预览草案”。

完成以上 5 步即可证明：新页面、初始责任结构、未绑定提示、结构校验和文件对齐入口均能工作，而且不会产生正式任命。

## 三、第二轮：人员配置（可选）

1. 打开“人员配置”。
2. 为固定岗位职责选择测试人员、适用场所和拟生效日期。
3. 点击“保存人员草案”。
4. 回到“责任结构”，确认对应项目由“岗位尚未绑定人员”变成已显示具体人员。
5. 再次执行“检查责任结构”和“检查签批就绪度”。

注意：选人此时只是草案，不构成任命。签批就绪检查会验证岗位、人员、能力证据、公司总经理身份和实验室主任任命链；缺项应显示阻断，而不是静默通过。

## 四、第三轮：完整签批（最后再测）

这一轮会在本机测试数据库中形成任命证据，只使用明确标记为测试的内容：

1. 在“校验与签批”登记公司总经理既有身份证据，来源编号建议写 `TEST-20260714-GM`。
2. 发起实验室主任任命，由已登记的公司总经理账号签批；不得自己批准自己的任命。
3. 补齐所有固定岗位人员与必要证据，再执行“检查签批就绪度”。
4. 只有结果为 `pass` 时才点击“提交签批”。
5. 由页面显示的对应批准人完成各自批次签批。
6. 全部签批完成后，在“有效责任链”检查人员、岗位、职责、场所、有效期、来源版本和签批证据。

建议第一轮先不做本节。等责任结构和提示语确认符合实际机构口径后，再跑完整签批。

## 五、如何停止和重新启动

在终端进入：

```bash
cd "/Users/lc.leixyz/Documents/AI工作台/01-项目代码/LIMS-zhj/jewelry-qms"
```

停止但保留数据：

```bash
docker compose stop
```

重新启动：

```bash
docker compose start
```

不要运行 `docker compose down -v`，该命令会删除本机数据库卷。
