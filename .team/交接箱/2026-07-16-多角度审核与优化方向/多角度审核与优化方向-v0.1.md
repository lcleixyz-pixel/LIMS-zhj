# jewelry-qms 多角度审核与优化方向

- 版本：v0.1
- 日期：2026-07-16
- 审核对象：本地现用 8010（产品版本 2.1.0，Docker 部署，jewelry-qms-app-1 / jewelry-qms-db-1）
- 审核方式：五角色（admin / quality_manager / auditor / department_head / staff）HTTP 实登陆走查 41 个入口页 + 深层页面（文件详情、记录详情、记录填写表单）+ 数据库只读核对 + 代码核对 + 既有文档比对
- 证据位置：`evidence/walkthrough/`（status.tsv 为逐页状态表，digest_*.txt 为各角色页面文本摘要，*/\*.html 为原始抓取页面）
- 全程只读：未提交任何业务表单、未写业务库、未触碰云端
- 已知问题基线：`docs/同类项目差距与可行性分析-v1.0.md`、G4-R6 复审意见 v0.2、`.team/不好用清单.md`。本报告只报增量发现与基线复核结果，不重复已知结论

## 角度一：项目设计的功能性目的是否实现

定位口径（README / ARCHITECTURE / 当前战役）：面向 CMA/CNAS/ISO 17025 的质量体系证据管理系统，只增强不替换 LIMS。

### 已实现且走查确认可用

| 能力 | 走查证据 |
|---|---|
| 文控全生命周期 | 38 份现用文件在库（`documents=38`），四层级筛选、修订/评审/分发/受控打印/结构化入口齐全（`document/view` 页面九个功能区完整） |
| 记录填报→打印→PDF | 145 个记录模板（`record_form_templates=145`），2 条真实运行实例已形成 PDF；填写表单支持从人员台账勾选参训人员（真实 12 名员工）、可重复表格行、年度编号建议 |
| 体系策划追溯 | 5 部外部依据、268 条正式条款、29 个要素；追溯矩阵"条款→要素→手册/程序→记录→运行模块→岗位职责"全链呈现，且已按 G4-R6 意见拆为"完整/缺口 N"双层 |
| 责任链 | 内审/管评/风险 3 活动 21 职责，每条带 CNAS-CL01:2018 条款依据，区分"需提前指定/运行时指定"，四步签批流程页面完整 |
| 法规候选池闭环 | G4-R7 整改已落地：边界提示（"no_match 仅表示现有规则未命中，不等于不适用"）、确认适用/不适用/暂缓/转正式变更四态筛选、变更事件空态双路径引导 |
| 周期提醒 | 容器内 crond 已配置每日 08:00 `check:reminders --type=all`（B1 部署已实际存在），本月待办日历有真实提醒条目 |
| 合规驾驶舱 | 总体就绪度 19.6/100，按条款维度给出 16 项检查、高风险缺口清单直指具体文件/人员——这是"诚实的低分"，机制在工作 |

### 未实现 / 流程断头（增量发现）

1. **九大业务模块运行数据为零**。`equipments / calibrations / trainings / training_plans / capas / audit_plans / management_reviews / suppliers / nonconformities / complaints` 等 15 张运行表全部 0 条。模块功能可用但从未承载真实业务，合规驾驶舱的 11 项"不合规"大多源于此。功能目的的"容器"已达成，"运行"未开始——这与其说是缺陷，不如说是当前最大事实：**系统价值下一步取决于运营灌数据，不取决于再开发**。
2. **提醒产生了孤儿数据**：本月待办里"期间核查到期提醒"显示"关联记录不存在，请复核提醒来源"（G4-R10 清理把 smoke 设备清了，提醒没同步清）。所有角色可见，试运行第一眼就是一条坏数据。
3. **记录模板编号重复仍在库**：`XZTC/BG-04-03`×19、`BG-04-06`×9、`BG-04-05`×8、`BG-03-02`/`BG-16-01`/`BG-28-02`/`BG-33-01`×2。页面已做"编号重复：共 N 条"标红（G4-R7 第三批做了提示），但**治理动作没做**——重复模板未合并/作废。其中一条 `BG-03-02` 名称还是截断的"仪器设备使用记录表（新疆中和鉴珠宝玉石质量检测研究?）"。
4. **文件台账元数据大面积空**：38 份已发布文件的"生效日期"全为 `-`，归口部门、文件分类、复审日期为空（合规驾驶舱也点名"38 份未设置评审日期"）。文控流程功能齐全，但存量导入文件没有补齐受控属性。
5. 质量方针/质量目标模块为空（页面功能齐全，未登记任何方针目标）——管评输入链路的起点缺料。

## 角度二：质量负责人是否便于理解使用、能否辅助治理

以 quality_manager 视角评估（注：**qm_test 账号无法用文档记载的口令 `password` 登录**——数据库核验其口令哈希已非 `password`，与 A3 权限矩阵测试记录的记载不符。其余 4 账号均可登录。本次以 admin 页面 + 权限配置推演 QM 视角，QM 权限覆盖除 AI 配置外几乎全部模块）。

### 真正帮到 QM 的

- **合规驾驶舱是全系统对 QM 最有价值的一页**：19.6 分、逐条款缺口、每条给"首条原因 + 入口跳转"，等于把"迎审差什么"变成了待办清单。
- **追溯矩阵 + 策划中心**回答了"手册第 X 章由哪个程序支撑、落到哪张记录、谁负责"——这正是"梳理体系"的核心动作，纸质时代要靠 QM 脑子记。
- **责任链页面**把 CNAS 条款依据直接标在每条职责上，QM 向管理层解释"为什么必须有人干这个"时可直接引用。

### 挡住 QM 的（增量发现）

1. **qm_test 口令漂移**（上述）。真实试运行给张晓磊开账号时必须重走"重置口令+交付"流程，且 A3 记录与现状不一致这件事本身就是一条记录失真。
2. **358 条待处理建议没有批处理**：策划中心"待处理建议 358"，每条只能单独"采纳/驳回"。按每条 30 秒算是 3 小时纯点击。缺按来源/条款段批量采纳、批量驳回，或至少"同来源全部采纳"。
3. **"今天该干什么"仍分散**：待办分散在工作台卡片、本月待办、通知中心、合规驾驶舱、策划建议五处，QM 每天要跑五个页面。缺一个按角色聚合的"我的待办"。
4. **合规驾驶舱刷新是手动的**："最后评估 2026-07-11"，走查时已是 07-16，5 天前的分数挂在页上没有任何"数据已过时"提示。评估应随每日 crond 跑或页面标注时效。
5. 策划中心建议文案仍偏专家腔（"尚未映射到无编号要素。建议人工判断：映射到已有要素，或作为本地补充要素候选"）——QM 看得懂，但要传给文件管理员执行还得翻译一遍。

## 角度三：非技术、体系不熟的岗位人员是否便于理解使用

以 staff_test / head_test 实登陆走查三条最小路径。

### 走得通的

- **填一张培训记录**：记录模板列表 → 填写 → 从人员台账勾选真实同事 → 保存草稿，全程无技术术语，参训人员表格"勾选添加+增加一行"的交互对非技术人员友好，是全系统体验最好的一条链路。
- **看体系文件**：staff 能打开文件列表和详情、下载附件。
- **看自己的待办**：本月待办/通知中心可达。

### 劝退点（增量发现，按严重度排）

1. **菜单不按权限过滤（P0）**。`main.html` 只对"审核准备/体系策划/AI"三处做了 `qms_can` 判断，其余菜单（体系文件全部子项、内审、管评、CAPA、设备、培训、供应商、部门/员工/用户/批量导入）对 staff 全部照常显示。staff 点"内审计划"→ 被弹回工作台 +"您没有访问该模块的权限"。实测 staff 41 个入口中 31 个是这种"看得见进不去"。对体系不熟的人，这等于"整个系统到处是打不开的门"，也直接造成 G4-R6 说的"有事不知道从哪办"。**建议：菜单全部按 `qms_can` 过滤，staff 默认只见：工作台/本月待办/记录填报/体系文件（只读）/客户投诉/通知。**
2. **无权限提示落点错位（P1）**：被拦后跳回 dashboard，提示条出现在工作台顶部而不是当前页，用户感知是"页面闪了一下回到首页"，不明白发生了什么。
3. **详情页动作按钮不按权限渲染（P1）**：staff 打开文件详情能看到"发起修订/定期评审/受控打印/作废并回收/ONLYOFFICE"全套按钮（模板未做角色判断），点击才被拦。非技术人员会以为自己"应该能作废文件"。
4. **残余英文枚举（P2）**：记录详情页"状态：generated"（`record_form_instance/view.html:23` 直接输出原始枚举，列表页却有中文标签）；本月待办"类型：calibration"（已在不好用清单，仍未修）。
5. **ONLYOFFICE 按钮常驻但服务未启用**（config 默认 `enabled=false`），staff 点了必然失败——不可用功能不应展示。

## 角度四：外部评审人员（CNAS-CL01 现场评审）会怎么看

### 能拿得出手的

- 7.11 逐条证据映射（验证方案 v1.0）+77 个 smoke 分类口径 + 备份恢复/权限矩阵/系统失效三演练留痕 + 变更控制规定 v0.1 + 双台账。**同规模自建系统里这套自证材料完整度罕见**，评审员问"系统怎么验证的"有正面材料可答。
- 法规候选池的边界语言（"不会自动修改体系文件/人员授权/模板/培训"）恰好回应评审员对"计算机系统自动改受控对象"的敏感点。
- 责任链条款依据、追溯矩阵，能支撑 8.2/8.4 的提问。

### 现场演示会翻车的点（增量发现，评审员视角按"必问"排）

1. **调试面板全角色可见（P0）**：现用 8010 跑着 `APP_DEBUG=true`（.env 与 compose 均为 true），每页底部 ThinkPHP trace 面板暴露完整 SQL、session_id、文件路径、耗时。五角色走查页面全部命中。这在 7.11.3 a（防未授权访问/泄露）下是硬伤，且 G4-R7 第一批"隐藏调试痕迹"实际未覆盖此项（只处理了 UI 内的计时痕迹）。**修法：现用容器 `APP_DEBUG=false` 重建，一行配置。**
2. **弱口令测试账号在现用系统启用中（P0）**：`auditor_test / head_test / staff_test` 口令均为 `password` 且 publish=1。评审员做用户清单核查一眼就到。A3 记录自己也写了"默认密码 password，勿用于生产"。试运行前必须停用或改密。
3. **"已形成PDF"记录仍可编辑（P0）**：`isTerminalStatus` 只认 `locked/voided`，`generated` 状态的记录（当前仅有的 2 条真实记录都是）保留"编辑"按钮，改完可再生成 PDF 而无版本痕迹（field_change_logs 白名单不含记录实例）。评审员问"记录输出后还能改吗"，当前答案是"能，且不留痕"——7.11.3 b / 8.4.2 直接失分。**修法：generated 即进入受限编辑（须走换版/作废），或编辑自动使旧 PDF 失效并留痕。**
4. **记录内容自相矛盾**：唯一两条运行记录之一（人员培训记录表-001）"参训人员：未填写"却已生成正式 PDF，且培训讲师"李明"不在员工台账 12 人名单中。评审员抽到这条记录必挑：签到表空白的培训记录如何证明培训发生？（这是演示数据遗留，试运行前应作废并重填真实记录。）
5. **模板编号唯一性**（8.3.2）：同编号 19 条并存虽有标红，评审员仍会问"哪条是受控现行版"。
6. **审计追踪覆盖窄**：字段审计白名单仅 5 类对象（Document/Capa/Equipment/AuditFinding/ChangeEvent），记录实例、模板、培训、人员均不在内——差距分析 v1.0 已知项，未收窄。
7. 正面提醒一句：资质表达纪律（CMA 已获/CNAS 申请中）在走查页面中未见违规表述，保持住了。

## 优化方向汇总（按"挡路/有点烦/锦上添花"+ 建议顺位）

**试运行放行前必须处理（挡路级，估 1 个短战役）**

| 顺位 | 事项 | 量级 |
|---|---|---|
| 1 | 现用 8010 关 `APP_DEBUG`（去 trace 面板） | 一行配置+重建容器 |
| 2 | 停用/改密 3 个弱口令测试账号；重置 qm_test 并更新 A3 记录口径 | 运营动作 |
| 3 | `generated` 记录禁直接编辑（进换版/作废通道）或编辑留痕 | 1 次会话 |
| 4 | 清理孤儿"期间核查提醒"；作废"参训人员未填写"的演示记录，重填真实记录 | 运营+小修 |
| 5 | 菜单按 `qms_can` 全量过滤 | 1 次会话 |

**试运行第一个月内（有点烦级）**

6. 重复编号模板治理：合并/作废到每编号一条现行版；修复 BG-03-02 截断名。
7. 38 份存量文件补录生效日期/归口部门/复审日期（可批量导入）。
8. 详情页动作按钮按权限渲染；无权限提示留在原页。
9. 策划建议批量采纳/驳回；合规驾驶舱接入每日 crond 自动评估或加时效提示。
10. 记录详情页状态中文化（view.html 用 status_label）；日历类型中文化。

**攒够痛点再做（锦上添花/维持原排期）**

11. 审计追踪快照（差距②，评审前做）→ 电子签名基础档（差距③）→ 发布培训联动（差距⑤）→ 监控专项（差距⑥，等真实数据）→ UI 全站翻新（按拍板）。
