# 8010 切换机制复核与修订

> 版本：v0.1
> 日期：2026-07-17
> 性质：最终切换前只读复核与候选发布能力补齐；未切换 8010。

## 复核结论

原确认单沿用了云端 `releases/current` 的说法，但本机现用 8010 实际由
`jewelry-qms/compose.yaml` 启动，并把主工作区 `jewelry-qms/` 直接挂载到容器 `/app`。
本机此前不存在可供原子选择的 `current` 发布目录。

因此，若直接按“切换 current”执行，会出现以下问题：

1. 找不到真实可切换的本机 `current`；
2. 主工作区未提交改动会实时影响现用容器，无法把回退点冻结为确定版本；
3. 仅切 Git 分支不能证明容器依赖、上传目录和运行目录一并回退；
4. 现用开发 Compose 会在启动时重新使用源码挂载，覆盖候选镜像中的已验收代码。

该差异不影响 8011 已完成的功能验收，但属于 8010 最终切换前的阻断项。

## 已补齐的候选能力

- 新增 `jewelry-qms/deploy/local-trial/compose.yaml`：
  - 只接受显式不可变镜像标签；
  - 禁止在切换时构建；
  - 不挂载工作区到 `/app`；
  - 只绑定 `127.0.0.1:8010`；
  - 复用 `jewelry-qms_default` 网络，不重建数据库；
  - 上传和运行目录必须使用 Git 外显式持久化路径；
  - 服务端固定 `APP_DEBUG=false`、`QMS_TRIAL_MODE=true`。
- 新增切换、快照和立即回退说明。
- 新增 `qms_gr14_local_release_contract_smoke.php`，10 项契约全部通过。
- Compose 静态解析通过。

## 仍须在最终人工批准后执行

1. 在切换当刻生成数据库、上传目录、容器配置和源代码状态快照；
2. 把当前 8010 实际运行代码构建为不可变回退镜像，并在隔离端口验证；
3. 把已验收的 8011 镜像登记为候选镜像，核对镜像 ID；
4. 生成 Git 外 `releases/current/shared/snapshots` 发布根目录；
5. 先让 `current` 指向旧版并验证回退镜像，再原子指向候选版；
6. 只重建 `app`，不得删除或重建数据库容器；
7. 失败时先保全试运行证据，再回指旧版并按损害范围决定是否恢复数据库快照。

## 当前边界

- 8010 仍为原容器和原数据库，HTTP 200。
- 8011 仍为隔离候选环境，HTTP 200。
- 未创建生效的本机 `current` 指针。
- 未停止、删除、重建 8010。
- 未部署云端。

## 闸门影响

原“批准 G‑R14 最终切换”语句仍可使用，但执行解释修订为：

> 先冻结现用 8010 为不可变回退 release，再生成并校验切换当刻快照，随后通过本机 Git 外
> `current` 指针只替换 app 容器；数据库容器保持不动。失败立即回指旧 release，必要时恢复数据库快照。
