## 1. 对 v0.1 结论的修正

v0.1 的大方向仍成立：系统骨架是对的，但目前更像“专家后台”，还不是“岗位行动台”。

v0.2 补充后的更准确判断是：

1. 入口不只是“不够好找”，更大的问题是“有事不知道从哪办”。
2. 影响范围不只是“术语偏技术”，更大的问题是“岗位人员无法区分系统判断、人工结论和下一步动作”。
3. 表格模板/溯源链不只是“信息密度高”，更大的问题是“受控对象纪律、运行证据边界和删除/作废/换版语言尚未统一”。

因此，下一轮不应只做美化，应作为“试运行可信度专项”处理。

## 2. 已核实或基本成立的关键问题

### 2.1 候选详情缺少处置闭环（P0）

本地代码核验：

- `PlanningRegulatoryCandidate::view()` 只加载候选、影响行、证据引用和来源信任。
- `planning_regulatory_candidate/view.html` 顶部只有“返回候选池”。
- 页面未见“确认适用 / 确认不适用 / 暂缓 / 转正式变更事件”按钮组。

影响：候选状态显示为“待人工确认”，但界面不给确认入口，会导致“候选 → 人工确认 → 正式事件”的质量管理链条断在页面上。

### 2.2 结论列不能简单改成动作列（P0 修正）

v0.1 曾建议把 `较可能影响` 改为 `建议复核`。复审意见指出这里存在边界风险，这个意见成立。

调整为：

- 保留“初步结论/可能性判断”：如 `较可能有影响`、`可能有影响`、`现有规则未命中`。
- 新增“建议动作”：如 `请质量负责人确认是否转正式事件`、`请文件管理员复核外来文件台账`。

原因：法规候选池输出的是机器辅助候选和初步影响，不是最终适用性判定。系统不得让岗位人员误以为“系统已经定性”。

### 2.3 菜单不建议改成动态名称（P1 修正）

v0.1 曾建议入口可命名为“法规候选池（待确认）”。复审意见认为固定菜单不宜混入动态状态，这个意见成立。

调整为：

- 固定菜单名保持“法规候选池”。
- 有待确认项时，在菜单或工作台卡片显示数字角标。
- 无待确认项时，角标消失。

### 2.4 仪表盘数据可信度要前置（P0）

本地库核验：

- `equipments` 当前为 0。
- `calibrations` 当前为 0。

截图复审中“设备总数 0，但校准结果分布仍有圆环分布”的问题，应作为 P0 缺陷处理。即使实际成因是图表空值渲染，也会破坏试运行人员对系统的信任。

建议：

- 当图表数据合计为 0 时，不绘制空饼图/空折线，显示“暂无校准记录 / 暂无 CAPA 数据”。
- 工作台数据卡与图表必须同源或显示口径说明。
- 右上角红色 `0` 通知角标无未读时不应显示为红色。

### 2.5 记录模板编号重复与“删除”按钮风险（P0）

本地库核验到重复编号：

- `XZTC/BG-04-03`：19 条。
- `XZTC/BG-04-06`：9 条。
- `XZTC/BG-04-05`：8 条。
- `XZTC/BG-03-02`：2 条。
- 另有 `XZTC/BG-16-01`、`XZTC/BG-28-02`、`XZTC/BG-33-01` 等重复。

本地页面代码核验：

- `record_form_template/index.html` 对列表中模板均显示“删除”按钮。
- 页面没有按 `published / draft / obsolete` 区分“删除、作废、换版”。
- 列表直接显示 `print_template_key`，如 `rf_xztc_bg_...`。

质量管理含义：

- CNAS-CL01 / ISO/IEC 17025:2017 8.3.2 要求文件具有唯一标识，并避免误用过时文件。
- 对已发布记录模板，界面语言应优先使用“作废 / 换版 / 保留历史”，不宜给普通岗位人员“物理删除”的暗示。

### 2.6 填写记录生命周期语言不足（P1）

本地代码核验：

- 当前状态词包括 `草稿 / 已生成 / 已归档 / 已作废`。
- 列表缺少“填写人 / 审核人”列。
- 按钮“2025 运行确认”语义偏短。

建议改为质量记录生命周期语言：

- 草稿 → 已提交 → 已审核 → 已归档 / 已作废。
- 列表显示填写人、审核人、归档状态。
- “2025 运行确认”改成“2025 年度记录运行确认”。

### 2.7 追溯矩阵“完整”需要拆成两层（P1）

复审意见认为“完整”绿标可能过度承诺，这个意见成立。

建议从单一“完整”改为：

- `结构完整 · 运行证据 3`
- `结构完整 · 尚无运行证据`
- `结构缺口 · 缺程序/缺记录`

理由：文件覆盖不能替代运行证据。CNAS-CL01 / ISO/IEC 17025:2017 8.4 要求记录证明符合性；8.8、8.9 的内审和管理评审也需要运行证据支撑。

## 3. 下一轮实施顺序建议（G4-R7）

### 第一批：可信度与可读性修复

性质：低风险，主要是显示层与文案层。

1. 仪表盘图表无数据时显示空态，不画“假有数据”的图。
2. 隐藏普通用户可见的调试/性能计时痕迹。
3. 法规候选池列表优化列宽、日期格式、来源显示。
4. 建立“机器词 → 业务词”映射表：
   - `unverified` → `来源待核验`
   - `no_match` → `现有规则未命中`
   - `likely` → `较可能有影响`
   - `possible` → `可能有影响`
   - `manual_only` → `仅人工登记`
5. 体系策划菜单增加分组，固定名保留“法规候选池”，待确认数量用角标。

### 第二批：候选处置闭环

性质：涉及状态流转，需有本地验证和回退。

1. 候选详情增加处置按钮组：
   - 确认适用。
   - 确认不适用。
   - 暂缓。
   - 转正式变更事件。
2. 增加“已生效 X 天 / 距生效 X 天”提示。
3. 增加“建议动作”列或卡片，但保留“初步结论”。
4. 转正式事件前提供预览，仍不得自动修改体系文件、人员授权、模板、培训或 LIMS 规则。
5. 正式变更事件空态解释两条路径：
   - 候选经人工确认后进入这里。
   - 也可由质量负责人手工登记事件。

### 第三批：受控对象与记录纪律

性质：质量管理硬边界，建议放在一个独立 PR。

1. 记录模板新增/编辑时校验编号唯一性，至少对重复编号醒目标红。
2. 已发布模板不提供“删除”，改为“作废 / 换版”；删除仅限草稿。
3. `print_template_key`、`rf_...` 等技术字段移入详情页或技术依据折叠区。
4. 填写记录列表补充填写人、审核人，状态语言改为质量记录生命周期。
5. 系统维护类按钮移至系统设置或管理员维护区。

### 第四批：溯源链与真实案例验收

性质：服务真实岗位试运行，避免只做页面装饰。

1. 追溯矩阵改为“结构完整度 + 运行证据数”双层标识。
2. 缺口行增加“去处理”入口，但只跳转到相关页面，不自动修订。
3. 候选详情增加“建议复核对象”：
   - 体系文件。
   - 外来文件台账。
   - 记录模板。
   - 人员/岗位。
   - 培训。
   - 报告模板/CMA 标志控制。
4. 建立两个端到端验收用例：
   - 用例 A：`一单一库`，预期识别能力项目、合同评审、CMA 标志、报告模板、外来文件台账、人员培训等影响，但不得自动修改。
   - 用例 B：`GL011/GL012:2025 换版`，预期识别外部依据换版、CX-20/CX-21 程序参照旧版的复核需求，并可进入正式变更事件；不得自动改程序正文。

## 5. 当前不建议直接做的事

1. 不建议自动修订体系文件正文。
2. 不建议自动作废或换版记录模板。
3. 不建议自动生成培训完成记录。
4. 不建议自动变更人员授权或岗位职责。
5. 不建议把 `no_match` 解释为“不适用”；只能解释为“现有规则未命中”。

## 6. v0.2 收口结论

可以进入 G4-R7 设计/实现准备，但建议把标题从“页面优化”升级为：

> G4-R7 试运行可信度与候选处置闭环专项

首批目标不追求功能大而全，而是让真实岗位人员做到三件事：

1. 看得懂：机器词被翻译成业务词，结论和动作分开。
2. 敢相信：仪表盘、空态、重复编号、调试痕迹不再破坏信任。
3. 知道下一步：候选详情、追溯缺口、正式事件空态都有明确出口。
