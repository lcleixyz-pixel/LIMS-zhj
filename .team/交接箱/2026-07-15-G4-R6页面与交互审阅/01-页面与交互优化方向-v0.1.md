## 总体判断

骨架是对的：候选只读、六类影响、证据引用、正式变更事件分离、模板和溯源链底座都已经具备。但对真实试运行人员来说，目前更像“专家后台”，还不是“岗位行动台”。

优先优化方向应从“增加功能”转为“把已有能力串成清楚的行动路径”。

## 1. 法规候选池入口是否好找

### 现状

入口在顶部导航“体系策划”下拉菜单中，位于第 7 项；候选池页面右上角有“查看正式变更事件”。

### 风险

1. 对质量负责人和系统管理员来说能找到；对授权签字人、技术负责人、文件管理员、培训负责人来说不直觉。
2. 首页没有“待确认法规候选”卡片，用户无法从工作台发现新候选。
3. 候选池和正式变更事件是两个入口，方向对，但缺少“候选 → 人工确认 → 正式事件”的视觉路径。

### 优化建议

P0：

- 在工作台增加“法规候选待确认”卡片，展示待确认数量、最高影响类别、最近发现时间。
- 在“审核准备”或“本月待办”中增加待办入口：`法规候选待人工确认`。
- 将“法规候选池”在“体系策划”下拉中与“变更事件”组成一组，视觉上加分隔或小标题：`外部变化管理`。

P1：

- 候选池标题下增加一条流程提示：`候选池 → 人工确认 → 正式变更事件 → 影响评估/任务分派 → 记录归档`。
- 入口名称可调整为“法规候选池（待确认）”，让非技术人员知道这是待处理事项。

## 2. 岗位人员是否看得懂影响范围

### 现状

列表页以彩色标签展示六类影响；详情页以表格展示类别、结论、证据、规则 ID、置信度。

### 风险

1. 列表页标签密集，容易变成“风险贴纸堆”。岗位人员能看到“较可能影响”，但不一定知道自己是否要行动。
2. 详情页证据完整，但规则 ID、置信度等字段偏专家/调试视角；普通岗位人员会关心“谁看、看什么、做什么、留下什么记录”。
3. `unverified`、`manual_only`、`likely/possible/no_match` 对非系统人员不够友好。虽然有边界提示，但提示与具体行动未绑定。
4. 影响类别目前是横向并列，没有按岗位重组。例如：
   - 质量负责人：总体判断、是否转正式事件、影响分派。
   - 技术负责人/授权签字人：能力范围、CMA 标志、报告签发边界。
   - 文件管理员：外来文件台账、体系文件/模板复核。
   - 培训负责人：需培训岗位、培训记录模板。

### 优化建议

P0：

- 在候选详情顶部增加“岗位行动摘要”卡片：
  - 质量负责人：需决定是否进入正式变更。
  - 技术负责人/授权签字人：复核能力项目与 CMA 标志边界。
  - 文件管理员：检查外来文件台账、相关程序文件和报告模板。
  - 培训负责人：确认是否需要培训及培训对象。
- 将“结论”改成更业务化的短句：
  - `较可能影响` → `建议复核`
  - `可能影响` → `需人工判断`
  - `现有规则未命中` → `暂未发现直接影响，仍需确认`
- 在列表页只展示前三个最高优先级影响，其余折叠为“+3 项影响”，减少噪声。

P1：

- 详情页把“规则 ID / 置信度”默认折叠到“技术依据”区域；默认显示“证据、相关岗位、建议动作”。
- 增加“不得自动修改”的状态条，但用业务语言：`本页仅提出候选影响，所有修订、培训、授权变更仍需人工确认和记录。`
- 对 `来源信任 unverified` 改为中文：`来源待核验`，并显示“需核验官方链接/公告号/附件”。

## 3. 表格模板/溯源链是否能支撑实际质量管理动作

### 现状

系统已有较强底座：

- 追溯矩阵覆盖：外部条款 → 体系要素 → 手册/程序 → 记录表格/运行模块 → 岗位职责/运行证据。
- 文件结构化页面能显示结构覆盖率、记录要求字段覆盖率、程序记录要求缺口。
- 记录模板页面能查看、编辑、填写模板。

### 风险

1. 这些能力彼此存在，但候选详情页没有直接把影响链接到相关模板/溯源证据。
2. 用户看到“报告模板、合同评审、CMA 标志控制、培训可能影响”，但系统没有给出“建议查看哪些模板/哪些程序/哪些人员”的候选清单。
3. 追溯矩阵页面信息密度高，适合质量负责人或系统管理员，不适合岗位人员直接行动。
4. 正式变更事件为空态时，只显示“暂无外部变更事件”，没有提示“从候选池确认后会进入这里”。

### 优化建议

P0：

- 在候选详情页增加“建议复核对象”分区：
  - 相关体系文件：外来文件控制、合同评审、报告管理、CMA 标志控制等。
  - 相关记录模板：合同评审表、报告模板复核表、培训记录、外来文件台账。
  - 相关岗位：质量负责人、技术负责人、授权签字人、文件管理员、培训负责人。
- 每个对象只提供“查看/加入待办/标记无需处理”入口，不自动修改。
- 在正式变更事件空态增加解释：`候选经人工确认后，会在此生成正式变更事件。`

P1：

- 候选详情页增加“溯源链预览”：
  - 影响类别 → 相关 17025/CMA 条款 → 相关程序/模板 → 责任岗位。
- 记录模板列表增加按“受影响类别/岗位/体系要素”筛选，而不仅是编号、名称、模块。
- 文件结构化页的“变更影响预检”按钮可以作为候选详情的下一步入口，但需要命名更清楚：`查看可能受影响文件/模板`。

## 4. 信息架构建议

推荐把法规候选池从单页列表升级为 4 段式工作台：

1. 待确认候选：新公告、新外部依据、来源状态。
2. 影响摘要：六类影响 + 最高优先级 + 需参与岗位。
3. 建议复核对象：体系文件、模板、人员/岗位、培训、LIMS 规则。
4. 人工处置：确认适用 / 确认不适用 / 暂缓 / 转正式变更事件。

这样能保持“不得自动修改”的纪律，同时让岗位人员知道自己下一步该看哪里、留下什么记录。

## 5. 可访问性与可读性风险

1. 彩色标签较多，不能只靠颜色表达风险；应配文字和优先级。
2. 表格列多，窄屏下阅读成本高；候选详情建议用卡片分区替代全表横向阅读。
3. 规则 ID 使用粉色小字，技术人员可用，但岗位人员会跳过；建议折叠。
4. 顶部导航下拉项较多，键盘和小屏可发现性需另测；本次仅基于桌面截图审阅，未做完整键盘可达性测试。

## 6. 建议落地顺序

### 第一批：低风险页面优化

1. 工作台增加“法规候选待确认”卡片。
2. 候选池列表影响标签收敛为“最高三项 + 其余数量”。
3. 候选详情增加“岗位行动摘要”。
4. 正式变更事件空态增加“候选确认后进入这里”的说明。

### 第二批：质量管理动作闭环

1. 候选详情增加“建议复核对象”。
2. 每个复核对象只提供查看与待办，不直接改对象。
3. 增加“转正式变更事件”前的确认预览。

### 第三批：溯源链增强

1. 候选影响与追溯矩阵联动。
2. 记录模板按影响类别/岗位筛选。
3. 形成“一单一库”试运行专用验收视图。

## 7. 不建议现在做

1. 不建议直接做自动修订体系文件。
2. 不建议自动生成培训完成记录。
3. 不建议自动变更授权签字人或岗位职责。
4. 不建议让每个岗位直接面对完整追溯矩阵，应先给岗位化摘要。
