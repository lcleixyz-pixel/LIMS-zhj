# 现用质量手册 vs 工程包桥接验证报告（只读试跑）

生成日期：2026-07-07
执行角色：Codex 只读验证
结论等级：可作为桥接审查基础；不可直接作为“现用文件已通过工程包强校验”的结论

## 一句话结论

现用《质量手册（第四版）》的条款骨架基本可行，已经覆盖 ISO/IEC 17025 / CNAS-CL01 常见 4.1 至 8.9 主条款；但用工程包直接验证现用文件时，目前只能得到“弱通过”，不能得到质量体系意义上的闭环通过。

主要卡点有四个：

1. 原始 `.docx` 不是工程包脚本可直接读取的输入。
2. LIMS 已导出的 Markdown 可以跑脚本，但没有工程包证据卡回链，`回链 0 个` 也会通过。
3. 手册引用的 30 个支撑程序全部是 `2018` 版，而 LIMS 当前导出的对应程序是 `2022` 版。
4. 现用手册仍引用旧版/废止依据，包括 `CNAS-CL01-G003:2018` 与 `RBT 045-2020`。

## 主要差距清单

### GATE-01 原始 Word 不能作为直接工程输入

风险等级：中
影响：自动化校验容易因文件格式而非内容失败。
证据：`manual_check.py` 第 5 行直接 `open(..., encoding='utf-8')` 读取文本；原始 `.docx` 直接运行报 `UnicodeDecodeError`。
建议：工程包验证入口固定使用 LIMS 的 Markdown 导出，不直接读 Word。

### GATE-02 `manual_check.py` 对现用导出的通过结论过弱

风险等级：高
影响：现用文件没有任何工程包证据卡回链也会显示通过，容易产生假阳性。
证据：现用 Markdown 试跑输出 `回链 0 个`；脚本只检查“出现的回链是否存在”，没有检查“是否必须有回链”。
建议：新增最小回链覆盖率规则，例如每个主条款至少 1 个依据卡/事实卡/控制卡；总回链覆盖按条款出矩阵。

### GATE-03 手册支撑程序引用与现用程序导出不闭合

风险等级：高
影响：评审时可能被判为文件体系引用关系不清、过时文件误用风险。
证据：手册中识别到 30 个 `XZTC/CX-xx-2018` 支撑程序引用；程序导出中对应为 `XZTC/CX-xx-2022`，精确匹配数为 0。
代表样例：

| 编号基底 | 手册引用 | LIMS 程序导出 |
|---|---|---|
| XZTC/CX-01 | XZTC/CX-01-2018 | XZTC/CX-01-2022 |
| XZTC/CX-08 | XZTC/CX-08-2018 | XZTC/CX-08-2022 |
| XZTC/CX-20 | XZTC/CX-20-2018 | XZTC/CX-20-2022 |
| XZTC/CX-26 | XZTC/CX-26-2018 | XZTC/CX-26-2022 |
| XZTC/CX-35 | XZTC/CX-35-2018 | XZTC/CX-35-2022 |

另有 7 个 2022 程序未被手册按同编号基底引用：`XZTC/CX-03-2022`、`XZTC/CX-04-2022`、`XZTC/CX-07-02-2022`、`XZTC/CX-18-2022`、`XZTC/CX-24-2022`、`XZTC/CX-25-2022`、`XZTC/CX-34-2022`。

建议：先做“手册支持性文件清单 vs 程序文件清单”对照表，再决定是更新手册引用，还是确认 2018/2022 的版本沿革。

### GATE-04 依据现行性存在高风险项

风险等级：高
影响：评审员会直接挑现行有效性。
证据：

| 现用手册写法 | 核验结果 | 建议 |
|---|---|---|
| `CNAS-CL01-G003:2018《测量不确定度的要求》` | CNAS 当前公开为 `CNAS-CL01-G003:2021`，2023-01-01 第一次修订 | 更新依据名称和引用版本 |
| `RBT 045-2020检验检测机构管理和技术能力评价 内部审核要求` | 全国标准信息公共服务平台显示 `RB/T 045-2020` 已于 2024-11-26 废止 | 不再作为现行依据；如保留，只能标历史参考 |
| `CNAS-CL01-G001:2024` | 与 CNAS 当前公开页面一致 | 可保留 |
| `检验检测机构资质认定评审准则（2023年版）` | 市场监管总局 2023 年第 21 号公告，自 2023-12-01 施行 | 可保留 |

### GATE-05 抽样条款需要从“混写”改成“条件化”

风险等级：中
影响：现用手册既写“一般不进行抽样/不从事送检产品抽样”，又保留抽样计划、统计方法、抽样记录等完整抽样活动要求。逻辑不是错，但需要更清楚地区分“当前不开展现场抽样”和“若开展抽样时启用”。
工程包启发：工程包已有 `C3-A 不开展现场抽样 / C3-B 开展现场抽样时启用` 的条件块思路，适合移植为现用手册的表达方式。
建议：保留 7.3 条款，但把当前状态写成主文，把“若开展现场抽样”写成启用条件和程序触发条件。

### GATE-06 工程包机构画像不能直接套到现用机构

风险等级：中
影响：工程包质量手册仍使用 `星辰宝玉石检测有限公司【虚构】`、单一固定场所、CMA/CNAS 状态、未来引入 LIMS 等假设。
建议：建立 XZTC 画像参数表，至少包括机构名称、场所、能力范围、资质状态、人员规模、授权签字人、现用 LIMS/电子表格/纸质记录边界。

## 可复用的桥接验证路线

推荐以后按这 6 个闸口跑：

1. 输入闸口：只接受 `knowledge/internal` 导出的 Markdown，不直接接收 `.docx`。
2. 条款骨架闸口：检查 4.1-8.9 是否完整。
3. 证据卡闸口：每个主条款至少绑定工程包 K/F/G 卡；禁止 `回链 0` 通过。
4. 程序闭合闸口：手册支持性文件编号必须能匹配现用程序清单。
5. 依据现行性闸口：CNAS/CMA/RB/T/法规依据逐项查现行有效状态。
6. 画像一致性闸口：工程包参数不得保留虚构机构或与现用机构不一致的默认设定。
