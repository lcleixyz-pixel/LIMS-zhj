```text
jewelry-qms/.env: APP_DEBUG = true
```

页面证据：

```text

HTML 中检出：
- SQL
- 运行时间
- SESSION_ID=...
- /app/vendor/...
- ShowPageTrace
```

判断：未登录页面都暴露 trace，试运行和外部评审前必须关闭。

### 2. 测试账号仍启用，弱口令仍有效

当前账号状态：

```text
qm_test       publish=1 soft_delete=0 password=password? no
auditor_test  publish=1 soft_delete=0 password=password? yes
head_test     publish=1 soft_delete=0 password=password? yes
staff_test    publish=1 soft_delete=0 password=password? yes
admin         publish=1 soft_delete=0 password=password? yes
```

判断：

- `auditor_test` / `head_test` / `staff_test` 仍是弱口令测试账号。
- `qm_test` 口令已漂移，和早前测试矩阵“password”口径不一致。
- `admin=password` 也应纳入体验环境账号交付收口，但需避免在聊天中暴露新口令。

### 3. `generated` 记录仍可直接编辑

代码证据：

```php
private function isTerminalStatus(string $status): bool
{
    return in_array($status, ['locked', 'voided'], true);
}
```

`RecordFormInstance::edit()` 只有 `isTerminalStatus()` 为真时才拦截，因此 `generated` 不会被拦。

视图证据：

```html
<a href="/record_form_instance/edit?id={$record.id}" class="btn btn-sm btn-outline-secondary">编辑</a>
```

记录状态：

```text
generated = 2
```

判断：已形成 PDF 的记录仍能进入编辑，且编辑保存会清空 PDF 路径并退回 `draft`。这需要设计为“换版/作废/留痕”而不是普通编辑。

### 5. 菜单权限过滤仍不完整

- `Rbac` 中无权限时会 `Session::flash('error', '您没有访问该模块的权限')` 并重定向 `/dashboard/index`。

## 建议分闸门

### G4-R11-B：低耦合运营/配置硬伤

目标：尽快消除试运行一眼可见的安全和坏数据问题。

- B1：关闭本地 `APP_DEBUG`，重建/重启容器，验证登录页不再出现 trace。
- B2：停用或改密测试账号；重置 `qm_test`；形成账号交付记录，口令不进 Git、不进聊天。
- B3：归档孤儿期间核查提醒；标记或作废明显演示培训记录。

### G4-R11-C：记录生成后编辑控制

目标：`generated` 记录不能普通编辑。建议先做最小安全版：

- `generated/locked/voided` 都视为不能直接编辑。
- 详情页对 `generated` 隐藏或禁用“编辑”按钮。
- 后续另开“作废/换版/更正”流程。

### G4-R11-E：菜单权限过滤

目标：按角色只显示可进入菜单。建议先对主导航做 `qms_can` 包裹，详情页动作按钮另开 D/E 后续小步处理。

## 本轮结论

G4-R11-A 只读复核完成。当前不建议直接云端部署新版；建议先批准 G4-R11-B，处理 debug、账号和明显孤儿提醒/演示记录。
