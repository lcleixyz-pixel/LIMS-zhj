# G4-R4 候选池中文乱码修复记录 v0.1

## 结论

已修复云端“一单一库”候选的中文乱码。修复后，候选池列表页和详情页均能显示正常中文，且候选仍停留在 `pending` 状态，未转正式变更事件。

## 根因

本地原始候选 JSON 中文正常；云端数据库中同一条候选为乱码。

根因是 G4-R2 手工写入候选时，MySQL 客户端连接未显式指定 `utf8mb4`，UTF-8 中文被按错误连接字符集解释后再入库，形成 mojibake。

后续写入候选或 JSON 字段时必须使用：

```bash
mysql --default-character-set=utf8mb4
```

并在 SQL 中执行或等效保证：

```sql
SET NAMES utf8mb4;
```
