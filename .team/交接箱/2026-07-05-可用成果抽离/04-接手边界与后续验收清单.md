## 3. 推荐验收顺序

### 第一步：确认运行环境

目标：确认 `jewelry-qms` 可以在本机或 Docker 访问。

建议检查：

```bash
cd /Users/lc.leixyz/Documents/AI工作台/01-项目代码/LIMS-zhj/jewelry-qms
docker compose ps
curl -I http://127.0.0.1:8010/login
```

如果不用 Docker，则确认 PHP 服务和数据库连接。

### 第二步：跑轻量 smoke

目标：先确认不依赖生产库的静态和轻量测试。

```bash
php tests/qms_validation_smoke.php
php tests/qms_current_files_enumeration_smoke.php
git diff --check
```

### 第三步：验收知识导出

目标：确认 `knowledge/internal` 可重跑且边界明确。

```bash
php think qms:seed-current-files --enumerate-procedures
php think qms:seed-current-files --export-knowledge-internal
```

验收点：

- 程序目录总数 42。
- 编号文件 38。
- 质量手册导出 1。
- 程序文件导出 37。
- 待复核问题 1。
- 报告说明 `XZTC/CX-05-02-2022` 的附件/表单边界。

### 第四步：抽检原文

目标：确认结构化导出不是“看起来有内容”，而是真的没有丢关键章节。

建议抽检：

- `XZTC/CX-08-2022 文件控制程序`
- `XZTC/CX-20-2022 内部管理体系审核程序`
- `XZTC/CX-21-2022 管理评审程序`
- `XZTC/CX-26-2022 计算机文件及数据控制程序`
- `XZTC/CX-32-2022 风险评估控制程序`

每份检查：

- 标题层级是否正确。
- 目的、范围、职责、程序、记录是否完整。
- 表格是否丢行。
- 原文件路径是否能追溯。
- 是否需要映射记录表格 schema。

### 第五步：校准 v2.2 状态

目标：把文档 pending 与代码已落地的部分分开。

优先核对：

- `check:reminders` 对应提醒去重和定时命令。
- `qms_validation_smoke.php` 对应服务端校验。
- `FieldAuditService` 对应字段审计。
- `sites` 和 `equipment_transfers` 对应多场所和设备调拨。
- `FormTokenCheck` 中间件和页面 token 对应 CSRF。
- `PlanningChangeEvent` 对应外部变更事件。

核对后再决定是补代码、补测试，还是更新路线图状态。

## 4. 后续最值得做的三件事

### 4.1 做一份“当前功能验收矩阵”

把每个模块列成：

- 页面入口。
- 数据表。
- 关键服务。
- 已有测试。
- 是否需要数据库写入验证。
- 是否需要人工业务验收。

这能把“代码存在”和“业务可用”区分开。

### 4.2 完成内部文件到条款的粗映射

先不追求块级精细，先把 37 份程序文件映射到 ISO 17025 / CNAS / CMA 主条款，产出：

- 文件 -> 条款。
- 条款 -> 文件。
- 疑似无文件覆盖条款。
- 疑似无记录证据条款。

### 4.3 给 AI 专家建立最小可用知识闭环

最小闭环：

1. `knowledge/standards/` 先做一批高频条款卡片。
2. `knowledge/internal/` 作为内部文件证据。
3. 桌面技能或系统 Copilot 回答时必须引用条款号和内部文件。
4. 无卡片支持时标注“待核”，不编造。
