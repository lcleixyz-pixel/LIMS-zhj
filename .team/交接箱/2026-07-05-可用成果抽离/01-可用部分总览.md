# 可用部分总览

## 1. 主成果边界

本项目当前应按“一个主系统 + 一个知识资产导出层 + 一套说明和验收文档”理解。

| 层 | 可用成果 | 当前作用 |
|---|---|---|
| 主系统 | `jewelry-qms/` | ThinkPHP 8 版珠宝检测实验室 QMS，服务 CMA/CNAS 和 ISO/IEC 17025 质量管理体系。 |
| 知识资产导出层 | `knowledge/internal/` | 从结构化库单向导出的内部体系文件 Markdown，用于专家智能体、审查、后续知识库建设。 |
| 项目说明层 | `docs/` | 架构、运行、体系策划、记录表格、专家路线图、任务卡和边界说明。 |

两个 FlinkISO 参考目录不是当前成果主体：

- `flinkiso/` 与 `flinkiso-lite-master/` 只是参考项目快照。
- 当前真正可跑、可验收、可继续增强的是 `jewelry-qms/`。
- 旧版 `jewelry-qms-legacy/` 也不作为主运行版本。

## 3. 已可用能力分组

### 3.1 QMS 主业务模块

已经在 `jewelry-qms` 中形成页面、模型、数据表和路由的业务模块包括：

- 文件控制：文件层级、模板、附件、审批、发布、修订、分发、回收、废止、受控打印入口。
- 审批与待办：按文件层级差异化审批，审批结果写入相关状态和通知。
- 内审：计划、日程、检查表、发现项，发现项可触发 CAPA。
- 管理评审：评审记录、输入汇总、决议事项、后续验证。
- CAPA：来源关联、原因分析、措施实施、有效性验证、关闭。
- 投诉与不符合：投诉推进、不符合处置，并可转 CAPA。
- 设备与校准：设备台账、校准记录、校准证书、期间核查相关记录表格承接。
- 标准物质与设备授权：标准物质管理、设备授权使用人。
- 培训与能力：培训计划、培训记录、能力确认、员工证书附件。
- 供应商：供应商、供应商评价、合格状态。
- 多场所和设备调拨：`sites`、`equipment_transfers` 已有表、模型、控制器和路由。
- 通知、导入、仪表盘：通知列表、CSV 导入、看板聚合、提醒命令。

### 3.2 体系策划与追溯

已经具备的策划中心能力：

- 外部依据登记、上传、查新、条款抽取入口。
- 条款库、条款文本、无编号体系要素。
- 要素与条款、手册章节、程序文件、记录表格、岗位、业务模块的追溯模型。
- 结构化文件主表、内容块、块级链接、结构化变更日志。
- 体系包渲染入口和运行产物路径。
- 外部变更事件登记、状态流转、附件和字段审计。

### 3.3 记录表格链路

已经形成的记录表格能力：

- `record_form_templates.field_schema` 承载表格 schema。
- 模板状态、来源预览、字段复核、批量 seed、缺口 seed。
- 运行记录实例创建、编辑、查看、打印、PDF 导出入口。
- 大量 `record_form_print` 模板，用于把不同表格渲染为可打印样式。
- 记录表格重构审查、schema 重建、来源实例草稿等命令和测试。

### 3.4 AI 辅助能力

已经有代码骨架和部分可用入口：

- `AiAssistant`：文档抽取、确认、拒绝、预览、历史。
- `AiChat`：会话创建、消息发送、清理。
- `AiSettings`：AI 设置保存与测试。
- `DeepSeekService`、`AiChatService`、`CopilotReadService`、`PageContextBuilder`、`AiContextToolService` 等服务。

重要边界：这些能力涉及外部模型 API。正式喂入体系文件、标准原文或敏感业务资料前，需要用户确认保密边界和 API 使用范围。

### 3.5 知识资产导出层

`knowledge/internal/` 当前不是手工写的资料库，而是由主系统结构化库导出：

- 质量手册：1 份。
- 2022 版程序文件：37 份。
- 2022 程序目录基线：42 个文件，其中编号文件 38 份，排除封面、目录、批准页、修改页 4 份。
- 待复核边界：`XZTC/CX-05-02-2022` 是编号附件/表单，不作为程序文件结构化导出。

## 4. 已有但不能夸大的部分

以下部分已经有代码或文档起点，但还不应对外宣称“完全完成”：

| 部分 | 当前状态 | 不能夸大的点 |
|---|---|---|
| v2.2 路线图 | 文档中不少 todo 仍为 pending，但代码已有部分落地 | 开工前必须先做状态验收，不能按文档 pending 从零做，也不能按代码存在就算通过。 |
| 内部文件结构化导出 | 已导出 1 份手册和 37 份程序文件 | 仍需人工抽检原文，尤其表格、标题层级、附件边界。 |
| 标准知识库 | `knowledge/standards/` 有骨架 | ISO 17025、CNAS、CMA 标准卡片尚未全量完成。 |
| 条款映射 | 数据模型和部分页面具备 | 内部程序文件到条款的人工复核映射还未完成。 |
| AI 专家智能体 | 系统内 AI 骨架和桌面技能方向已有 | 还未完成“知识卡片检索 + 严格条款引用 + 生成审批闭环”的全链路验收。 |
| 外部变更事件 | 事件登记和状态流转已落地 | 影响分析、redline 修订、闭环复算仍是后续任务。 |

## 5. 最适合下一步复用的成果

如果要继续推进，优先复用这些现成资产：

   继续处理结构化文件、系统包、`knowledge/internal` 导出，不要另写一套平行解析器。

   继续做现用文件枚举、结构化刷新和知识导出。

3. `jewelry-qms/app/service/RecordForm*` 系列服务
   继续接记录表格 schema、来源实例、重构审查和打印输出。

4. `jewelry-qms/app/service/ComplianceCheckService.php`
   继续扩展合规看板、差距扫描和缺口证据，而不是另起“合规扫描”入口。

   继续承接外部规范变更事件登记和后续影响分析。

   作为当前内部文件结构化质量和待复核边界的事实入口。
