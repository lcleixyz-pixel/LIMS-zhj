# 手册治理后真实岗位试运行可行性评估 v0.1

> 日期：2026-07-14
> 结论：**有条件可行；应按“受控试运行”实施，不能把当前状态直接认定为正式投用**
> 评估对象：T3 第二批逐项核验暴露的问题、第五版候选稿、最新责任链系统、云端体验环境

## 一、建议目标

把原来的“纯体验站”升级为：

> 采用真实机构结构、真实岗位和经授权的真实人员，在完成文件治理、职责批准、系统确认和安全加固后，使用明确标识的模拟业务记录开展受控试运行；试运行合格前，不用于正式客户检测、正式原始记录、CMA/CNAS 报告或法定证据保存。

这一路线既能让人员按真实职责发现系统问题，也不会把尚未确认的 QMS 和 LIMS 当成正式运行事实。

## 二、为什么当前不能直接完整上线

### 2.1 文件治理尚未闭合

T3 第二批已确认的主要问题包括：

- 内审计划、管理评审报告、风险措施、不符合评价、记录表格设计等职责冲突；
- 文件手写修改、记录保存年限、文件换版规则存在直接冲突；
- 管理评审程序记录挂接错误、CX-21 缺少 4.5 节；
- CX-20 程序编号张冠李戴，部分依据名称失效；
- CX-03/CX-04 期间核查职责重叠，CX-05 源文件正文缺损；
- Y16 校准方案三要素是否在运行表单承接仍未确认；
- Y7/Y8 是否适用仍取决于机构是否开展钻石以外的人为定级/分级；
- “总经理、实验室主任、检测部经理、检测室主任”等称谓与任命关系尚未由组织文件证实。

因此治理对象不是单独一份质量手册，而是“手册 + 程序 + 表单 + 组织任命 + 运行证据”的一致性闭环。

### 2.2 责任链当前仍是草案

本地数据库只读核对结果：

| 项目 | 当前状态 |
|---|---|
| 责任链版本 | 1 个，状态 `draft` |
| 活动 / 职责 | 3 / 21 |
| 人员指定 | 6 个，均为 `draft`，未形成校验结论 |
| 审批记录 | 0 |
| 人员任命记录 | 0 |
| 用户 | 5 个，仅管理员关联员工；其余 4 个角色账号未关联员工 |

这意味着系统虽然具备责任链能力，但尚未形成 CNAS-CL01 5.5、6.2.4—6.2.6 所要求的“职责明确、传达、能力确认和授权”证据。

### 2.3 LIMS 尚未完成正式投用确认

此前用户确认口径是：`jewelry-qms` 仍为建设中系统，不写入质量手册正文，只写入实施计划。若改为真实岗位试运行，应先完成 CNAS-CL01 7.11.2—7.11.6 要求的投用前确认、变更授权、访问控制、数据完整性、故障记录、备份恢复和数据传输核查。

### 2.4 云端安全边界需要升级

当前云端具备 HTTPS、BasicAuth、应用回环监听和数据库不开放端口，适合体验测试；但真实人员信息、岗位授权和真实业务数据进入公网云服务器前，还应增加：

- 按岗位最小权限配置和账号单独交付；
- 禁止共享账号，停用默认管理员口令；
- IP 白名单、VPN 或零信任访问层中的至少一种；
- 登录与权限操作审计、异常登录检查；
- 自动备份、异地副本、恢复演练和故障处置记录；
- 个人信息分类、最小化和访问期限控制。

《个人信息保护法》第五十一条要求分类管理、去标识化或加密、合理权限和应急预案；《数据安全法》第二十七条要求建立全流程数据安全管理制度和技术措施。

## 三、可行的五道闸门

### G0：事实确认

闭合三类事实：人为定级项目适用性、实际组织/任命关系、校准计划或送校文件是否承接参数/范围/准确度或不确定度要求。

### G1：文件治理

1. 以第五版候选稿为母版，不覆盖现行第四版。
2. 对 T3 已确认问题建立“问题—条款—修订文件—表单—责任岗位—验证证据”矩阵。
3. 同步修订涉及的程序、记录清单和表单，重点至少覆盖 CX-20、CX-21、CX-08、CX-19、CX-15、CX-16、CX-17、CX-03、CX-04、CX-32、CX-05、CX-29。
4. 统一机构岗位词汇、批准权限、保存期限、换版规则和程序互引。
5. 将 2026 年 CMA “一单一库”变化纳入外来文件识别和能力范围复核；它不阻断内部试运行，但正式报告和 CMA 标志使用必须按现行范围确认。

### G2：受控批准与培训

- 编制、审核、批准、发放、旧版作废均形成记录；候选稿不能直接替代现行文件。
- 质量负责人、技术负责人、实验室主任及相应过程负责人完成真实签核。
- 按岗位生成学习材料、理解确认题和问题反馈记录；培训完成不等于授权完成。

### G3：系统和责任链确认

- 部署 `main@1551525`，完成 79 张表迁移、14 项责任链回归和 5 项部署冒烟。
- 真实用户逐一关联员工、部门、场所和岗位；每人使用独立账号。
- 责任链经过校验、审批后从 `draft` 转为 `effective`，并保留内容 hash 和审批证据。
- 完成权限矩阵、审计追踪、备份/恢复、故障、PDF、上传和持久化确认。

### G4：受控试运行

首轮建议采用：真实人员 + 真实岗位 + 真实流程 + 模拟业务数据。

- 选择内审、管理评审、设备校准计划、文件修订、记录更正等低风险治理流程进行试运行；
- 所有试运行记录标记 `TEST-RUN` 或“【试运行】”；
- 不出具正式客户报告，不使用 CMA/CNAS 标志，不作为正式检测原始记录；
- 运行 2—4 周，登记问题、权限冲突、职责断点和系统故障；
- 由内审/专项审核确认问题闭环后，再决定是否转正式运行。

### G5：正式投用裁决

只有以下证据同时存在，才可建议正式投用：文件批准发布、岗位授权、人员培训、LIMS 确认报告、权限矩阵、备份恢复演练、试运行问题闭环、管理层投用批准。

## 四、哪些内容可以“真实”

| 内容 | 首轮受控试运行 |
|---|---|
| 真实组织结构、岗位、场所 | 可以，需用户确认并形成受控记录 |
| 真实人员姓名与岗位关系 | 可以，需最小化联系方式并完成安全加固 |
| 真实账号和权限 | 可以，必须独立账号、最小权限、可审计 |
| 真实手册和程序 | 可以，但必须走审核批准、旧版作废流程 |
| 真实客户、样品和检测数据 | 首轮不建议 |
| 正式原始记录和正式报告 | 首轮禁止 |
| CMA/CNAS 标志和认可状态声明 | 首轮禁止 |

## 五、现行依据复核

- CNAS 官网当前仍列 CNAS-CL01:2018（2019 年第一次修订）及 CNAS-CL01-G001:2024 为实验室认可准则和应用要求。
- CNAS-GL011:2025、CNAS-GL012:2025 已于 2025-12-01 实施，适合指导内部审核和管理评审成熟度，但指南本身不替代 CL01/G001 的强制要求。
- 市场监管总局 2023 年第 21 号公告发布的《检验检测机构资质认定评审准则》自 2023-12-01 施行。
- 市场监管总局 2026 年第 14 号公告自 2026-06-01 起实施 CMA “一单一库”管理；正式能力范围和 CMA 标志使用应纳入本轮外来文件变更复核。

## 六、最终判断

项目具备实现真实岗位试运行的代码基础、云端基础和治理材料，**可行性为“可行，但必须分阶段”**。不建议采用“先把问题文字改完、整库上传、员工直接开始用”的一步式方案；该方案会把未批准文件、未生效责任链、未确认权限和未完成系统确认同时带入实际运行。

推荐下一步：先批准“G0 事实确认 + G1 治理方案 v0.1”，完成修订影响矩阵和待确认事实表，再逐文件修订，不立即写云端。
