## 四、UX 问题清单（需修复）

### BUG-1 [严重] 部分字段原值回填为 `{}`

**现象**：在更正申请表单中选择"培训日期"字段时，"原值（冻结保留）"栏显示 `{}`（空JSON对象），而非实际值 `2026-07-26`。选择"标题"等文本字段则正常。

**根因**：模板 `governed_change_panel.html` 第 113 行 `data-current="{$field.value|htmlentities}"`，后端 `GovernedChangePolicyService` 对日期型 / 对象型字段返回的是原始对象或数组，未做标量格式化，`htmlentities` 后渲染为 `{}`。

**影响**：非技术用户看到 `{}` 完全无法理解；以该状态提交申请，审批人侧的原值也会显示 `{}`。

**建议**：后端在构建 `fields` 列表时，将所有类型的 value 统一转为字符串标量（日期格式化为 `Y-m-d`，对象取属性值，数组取 JSON 或 join）。

### UX-2 [中等] 成功提示不在辅助功能树中

**现象**：提交更正申请或批准后，页面顶部出现绿色 `alert-success` 提示框，DOM 中存在且可见，但 `browser_snapshot`（辅助功能树）未将其捕获为文本节点。提示框含"关闭提示"按钮但消息正文被省略。

**根因**：`alert-dismissible` 的关闭按钮先于文本进入 a11y tree，ThinkPHP `Session::flash` 渲染的 alert 可能缺少 `role="alert"` 或 `aria-live` 属性。

**影响**：对使用屏幕阅读器的视障用户不可见；辅助功能合规性欠缺。

**建议**：在 flash 消息容器上增加 `role="alert"` 和 `aria-live="polite"`。

### UX-3 [中等] 顶部 badge 数字无文字说明

**现象**：右上角显示红色数字 badge（如"8"、"10"、"18"），但没有任何 tooltip 或文字标签说明这是"待办数"还是"通知数"。`sim_approver` 同时显示"18"和"2"两个 badge，用户不知道分别代表什么。

**建议**：给 badge 加 `title` 或 `aria-label`，如"10 条未读通知"。

### UX-4 [低] 更正表单术语不友好

**现象**：
- "要批注的字段" —— "批注"一词偏技术，非技术用户可能理解为"添加备注"
- "冻结保留" —— 未做解释
- 下拉选项暴露了英文技术字段名 "Training Plan Id"

**建议**：
- "要批注的字段" → "要更正的字段"
- "冻结保留" → "原记录（不可修改）"
- 过滤掉纯技术字段（如 `training_plan_id`、`department_id`）或改为中文标签
