# 记录字段级更正实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法跟踪进度。

**目标：** 将 8021 试运行环境的记录更正从自由文本说明升级为字段级申请、审批和追加登记，支持普通字段、已有表格单元格和表格新增整行。

**架构：** 原记录 `field_values`、原 PDF 和已打印纸件始终不覆盖。更正申请保存目标字段路径、原值和拟更正值；审批人核对结构化前后值，批准后系统自动向 `record_form_corrections` 追加一条更正记录。旧自由文本联调记录保留并按“整表补充说明”兼容显示。

**技术栈：** ThinkPHP 8、MySQL 8、ThinkPHP 模板、Bootstrap 5、原生 JavaScript、PHP 冒烟测试。

---

- 创建 `jewelry-qms/app/service/RecordFormCorrectionService.php`：解析模板快照和原值，生成可更正目标，校验提交目标并形成不可变的字段级快照。

- [ ] **步骤 3：实现最小解析和校验**

服务公开两个入口：

```php
public static function targets(array $schema, array $values): array;
public static function prepare(array $schema, array $values, array $input): array;
```

`prepare()` 只接受 `field:<key>`、`cell:<table>:<row>:<column>`、`append:<table>` 三类路径，从服务端原记录读取原值，拒绝客户端伪造字段、行号或原值。

### 任务 3：结构化申请与审批自动追加

- [ ] **步骤 1：为控制器行为增加失败断言**

断言控制器调用 `RecordFormCorrectionService::prepare`、写入 `record_form_correction_requests`，并在批准分支通过事务写入 `record_form_corrections`。

- [ ] **步骤 2：运行并确认 RED**

- [ ] **步骤 3：修改申请动作**

`requestCorrection()` 接收 `correction_type/field_path/corrected_value/row_values/reason`，由服务端形成原值和字段标签快照；事务内写申请表并发通知。

- [ ] **步骤 4：修改审批动作**

`decideCorrection()` 只处理 `pending` 申请；批准时在同一事务内更新申请状态并追加更正记录，驳回时只更新申请。重复提交不得产生第二条更正记录。
