# 全项目修改治理实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法跟踪；不得写入 8010。

**目标：** 在 8021 为全部相关 QMS 模块建立统一的生命周期写入闸门、冻结后字段更正审批、最终值投影和历史留痕，同时保留文件换版、记录实例和职责链等现有专用流程。

**架构：** 新增一个轻量公共治理层。策略服务只负责判断对象属于直接编辑、专用流程、通用更正或事件管理；通用更正服务只追加请求和批准后的更正，不覆盖原字段。`CrudBase` 统一执行后端闸门；布局中的公共面板负责展示冻结状态、申请、审批和历史。已有专用流程不接管、不重写。

**技术栈：** ThinkPHP 8、MySQL 8.4、Bootstrap 5、原生 JavaScript、PHP smoke/runtime 测试、8021 浏览器验收。

**工作区说明：** 8021 当前挂载 `codex/governance-resolved-docs-v02`；为确保页面实时看到结果，在现有非 main 分支原地实施，不另建 worktree。

## 文件结构

**新建**

- `jewelry-qms/config/governed_changes.php`：模块策略、冻结状态、父记录冻结关系、保护字段和业务提示。
- `jewelry-qms/app/service/GovernedChangePolicyService.php`：解析模块、对象、冻结状态及直接编辑/删除规则。
- `jewelry-qms/app/service/GovernedChangeService.php`：校验请求、追加审批结果、读取有效值和更正历史。
- `jewelry-qms/app/controller/GovernedChange.php`：通用更正申请和审批端点。
- `jewelry-qms/app/view/common/governed_change_panel.html`：全模块共用的冻结、申请、审批和历史面板。
- `jewelry-qms/database/migrations/20260726_governed_changes.sql`：通用更正请求与批准更正表。
- `jewelry-qms/tests/qms_governed_change_policy_smoke.php`：策略和覆盖范围。
- `jewelry-qms/tests/qms_governed_change_service_smoke.php`：准备、投影和不可覆盖规则。
- `jewelry-qms/tests/qms_governed_change_ui_smoke.php`：路由、授权、公共面板和 CRUD 闸门。
- `jewelry-qms/tests/qms_governed_change_runtime_smoke.php`：8021 数据库的申请、批准、投影和清理。

**修改**

- `jewelry-qms/app/controller/CrudBase.php`：编辑、删除前执行治理闸门；详情页提供最终值。
- `jewelry-qms/app/view/layout/main.html`：详情页按策略装载公共治理面板。
- `jewelry-qms/app/service/ActionAuthorizationService.php`：允许有效用户申请，质量负责人/批准人审批。
- `jewelry-qms/app/service/FieldAuditService.php`：补齐受治理模型的关键字段审计，状态变化继续形成追加日志。
- `jewelry-qms/route/app.php`：增加通用更正 POST 路由。

- [ ] **步骤 3：实现最小策略服务**

服务公开接口固定为：

```php
public static function policy(string $subjectType): array;
public static function subject(string $subjectType, string $subjectId): ?Model;
public static function isFrozen(string $subjectType, Model $record): bool;
public static function guardDirectUpdate(string $subjectType, Model $record, array $changes): void;
public static function guardDelete(string $subjectType, Model $record): void;
public static function context(string $subjectType, string $subjectId): array;
```

策略分类：

- `revision`：文件、记录模板和体系结构化内容，沿用既有换版链。
- `specialized`：记录实例，沿用现有字段级更正。
- `correction`：完成/关闭后冻结，或形成即冻结的业务证据。
- `event`：设备、人员、供应商主档；允许普通资料编辑，保护状态和履历字段。
- `direct`：基础配置；保留审计和停用，不开放通用批注。
