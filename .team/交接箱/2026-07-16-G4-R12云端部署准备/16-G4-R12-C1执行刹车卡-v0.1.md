# G4-R12-C1 执行刹车卡 v0.1

日期：2026-07-16

## 用途

本卡用于用户明确批准 C1 后执行：

```text
批准 G4-R12-C1：推送集成分支并创建 Draft PR，不部署云端
```

本卡不是批准本身；没有上述授权时，不得执行推送或创建 PR。

## C1 边界

C1 只允许：

- 推送本地集成分支 `codex/g4-r12-pr31-integrated-deploy-prep` 到 GitHub；
- 基于该分支创建 Draft PR；
- 复核 PR 是否为 Draft、目标分支是否为 `main`、正文是否来自 `10-G4-R12-C1-Draft-PR正文-v0.1.md`。

C1 不允许：

- 上传云服务器；
- 切换服务器 `current`；
- 导入或修改云端数据库；
- 开放员工登录；
- 合并 PR；
- 关闭或合并 PR #31；
- 开启法规月度监测定时任务。

## 执行前实时刹车检查

以下检查必须在推送前即时运行。任一检查失败则停止，不进入 `git push`。

```bash
set -euo pipefail

WORKTREE="/Users/lc.leixyz/Documents/AI工作台/01-项目代码/LIMS-zhj/.worktrees/g4-r12-pr31-integrated-deploy-prep"
BRANCH="codex/g4-r12-pr31-integrated-deploy-prep"
PR_BODY=".team/交接箱/2026-07-16-G4-R12云端部署准备/10-G4-R12-C1-Draft-PR正文-v0.1.md"

cd "$WORKTREE"

test "$(git branch --show-current)" = "$BRANCH"
test -z "$(git status --porcelain)"
test -f "$PR_BODY"

git fetch --all --prune

test "$(git rev-parse origin/main)" = "adc243c2640b61a6e9eeb2de7dc3dd23b83036bf"
test "$(git rev-parse HEAD:jewelry-qms)" = "863cfe4e48649155f4b4294004fa976a7fbdb654"

test -z "$(git ls-remote --heads origin "$BRANCH")"
test "$(gh pr list --head "$BRANCH" --state all --json number --jq 'length')" = "0"
test "$(gh pr view 31 --json state,isDraft --jq '.state + \":\" + (.isDraft|tostring)')" = "OPEN:true"

echo "C1 preflight OK: 可以在本轮授权内推送并创建 Draft PR"
```

## C1 执行命令

仅当上一节输出 `C1 preflight OK`，且用户已明确批准 C1 时执行：

```bash
git push -u origin codex/g4-r12-pr31-integrated-deploy-prep

gh pr create \
  --draft \
  --base main \
  --head codex/g4-r12-pr31-integrated-deploy-prep \
  --title "G4-R12 云端体验部署准备：集成 PR #31 法规监测线" \
  --body-file .team/交接箱/2026-07-16-G4-R12云端部署准备/10-G4-R12-C1-Draft-PR正文-v0.1.md
```

## C1 执行后验证

创建 PR 后必须即时验证：

```bash
gh pr list \
  --head codex/g4-r12-pr31-integrated-deploy-prep \
  --state open \
  --json number,state,isDraft,baseRefName,headRefName,title,url
```

验收标准：

- 返回 1 个新 PR；
- `state=OPEN`；
- `isDraft=true`；
- `baseRefName=main`；
- `headRefName=codex/g4-r12-pr31-integrated-deploy-prep`；
- PR 标题为 `G4-R12 云端体验部署准备：集成 PR #31 法规监测线`；
- PR 正文不是空白，且包含“与 PR #31 的关系”“明确未做”“审查重点”。

## 失败处理

- 如果 `git push` 前检查失败：停止，补一份新的只读远端复核记录，不推送。
- 如果 `git push` 成功但 `gh pr create` 失败：不要重复推送；先用 `gh pr list --head ... --state all` 检查是否已有半成品 PR。
- 如果误建为非 Draft PR：立即停止，不合并；记录 PR URL，等待用户批准是否改回 Draft 或关闭。
- 如果发现 PR #31 状态已变化：停止，重新评估“集成 PR 与 PR #31 的关系”。
