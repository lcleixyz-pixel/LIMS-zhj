## 设计意图

C2 涉及多段命令：本地 preflight、PR 分支同步、服务器只读体检、快照、上传、SHA 校验、docker load、release 解压和 compose config 检查。手工复制容易漏一步或越过停点，因此将命令拆成可单独执行的 mode。

脚本没有提供“一键全跑”模式，避免一次性越过多个风险点。

## 安全设计

默认安全：

- `help` 只显示帮助；
- `local-preflight` 只做本地和 GitHub 只读检查；
- SSH 默认使用 G1 专用密钥 `~/.ssh/zhj_qms_g1_ed25519`，必要时可用 `SSH_KEY=...` 覆盖；
- 远端 `docker compose exec` 命令使用 `< /dev/null`，避免容器命令读取 SSH here-doc 的后续脚本行；
- 其他 mode 均要求显式环境变量：

```bash
export G4_R12_C2_APPROVAL="批准 G4-R12-C2"
```

未设置该变量时，脚本会拒绝执行远端写入、SSH 上传、服务器快照或 docker load。

## 当前前置状态读取方式

本说明最初创建时曾记录过当时的 local HEAD、origin HEAD 和 ahead 数。由于 C2 准备阶段会继续追加刹车卡、模板、脚本说明、静态复核等本地交接材料，固定写死的 ahead 数会很快过期。

正式执行 C2 前，不再依赖本节的旧数字，而应实时执行：

```bash
git status --short --branch
git rev-list --left-right --count HEAD...origin/codex/g4-r12-pr31-integrated-deploy-prep
git log --oneline origin/codex/g4-r12-pr31-integrated-deploy-prep..HEAD
```

若存在本地领先远端的 C2 准备文档提交，应先在用户授权范围内执行：

```bash
export G4_R12_C2_APPROVAL="批准 G4-R12-C2"
.team/交接箱/2026-07-16-G4-R12云端部署准备/scripts/g4-r12-c2-runbook.sh push-docs
```

然后再次执行：

```bash
.team/交接箱/2026-07-16-G4-R12云端部署准备/scripts/g4-r12-c2-runbook.sh local-preflight
```
