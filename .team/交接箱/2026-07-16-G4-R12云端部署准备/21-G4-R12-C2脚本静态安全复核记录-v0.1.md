## 4. C2 允许与禁止边界复核

### C2 获批后允许

- 推送 C2 文档提交到 PR #32；
- 服务器只读体检；
- 升级前数据库与上传文件快照；
- 上传候选包、镜像包、SHA 文件、release manifest；
- 服务器侧 SHA 校验；
- `docker load` 导入候选镜像；
- 解压候选包到新的 release 目录；
- 使用临时环境文件运行 `docker compose config` 检查。

### C2 仍然禁止

- 切换 `releases/current`；
- 启动、停止或重建云端业务容器；
- 修改 `$BASE/shared/.env` 的正式配置；
- 导入业务/质量数据；
- 执行数据库迁移或结构变更；
- 开放员工登录；
- 把 Draft PR 改为 Ready。

## 5. 结论

C2 脚本草案符合“分步执行、默认拒绝、获批后只做上传校验与快照、不切换不启动”的边界。
下一步若用户批准 C2，应先推送当前本地领先的文档提交到 PR #32，再按 `local-preflight → remote-readonly → snapshot → upload → verify-load → unpack-release → compose-check` 分步执行，并把每步证据填入 `19-G4-R12-C2执行完成记录模板-v0.1.md`。
