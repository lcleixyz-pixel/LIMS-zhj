# 四视角二次体验模拟与优化意见 v0.2

> 日期：2026-07-21 ｜ 基于 UX-1 中文化文案速赢批已落地（v0.1 的 26 条建议已采 23 条并修正 3 条） ｜ 新增 4 个岗位视角

## 说明

本报告在 v0.1「王姐（计算机小白质量员）」视角基础上，新增四类真实用户：

1. **纸质质量员老张**：50 岁，熟悉纸质台账、公章、手写签字，电脑只会开机和看 Excel。
2. **技术负责人李工**：40 岁，懂技术审核与签字，但以前只管图纸和报告，没用过管理系统。
3. **新人记录员小陈**：25 岁，计算机操作还行，但对质量管理、体系文件一窍不通。
4. **文件资料管理员周姐**：48 岁，熟悉办公流程、收发文件、编号归档，但未接触过体系文件和技术术语。

本批模拟重点：UX-1 已改完后，**还卡在哪里**？哪些地方中文化了但仍不符合岗位语言习惯？哪些流程步骤缺引导？

## 1. 各角色模拟实录

### 1.1 纸质质量员老张

#### 旅程 A：第一次登录
登录页现在写的是「珠宝检测实验室质量管理系统」，老张看懂了。输入账号密码后，页面右上角铃铛旁边没有 0 了，但多了两个字「通知」。老张心想：「通知」是让我点进去看通知吗？我现在没有通知，点进去会不会空？

#### 旅程 B：找一份体系文件
老张以前找文件是去文件柜看编号。现在点「体系文件」→「体系文件列表」，看到表格里有文件编号、文件标题、文件层级、版本/修订状态、文件状态、生效日期。老张盯着「版本/修订状态」那一栏的值「A/0（A 版第 0 次修订）」看了半天：A 版就是第一版，0 次修订就是没改过，合在一起念起来绕口。他更习惯文件柜标签上写的「A/0 版」。

#### 旅程 C：给文件换版签字
已发布文件点「发起修订」，填修订内容，保存后变成「草稿」。点「提交审核」，页面出现黄色卡片，标题现在叫「在线签批」，说明写着「请点击下方"打开签署页"完成电子签字。签名完成后自动进入下一环节。」老张心里踏实多了，但表格里角色显示「审核人」「批准人」，他不知道自己该点哪个。他看到自己的邮箱是 qm@lab.com，对应角色是「批准人」，但按照纸质流程，质量员通常是先审核再批准，这里怎么只有「批准人」？

签完字，状态变成「已批准」，又变成「已发布」。老张松了口气。但页面下方「分发记录」让他犯难：要选接收人、填分发说明。老张想：以前发文件是文员复印后盖「受控」章，谁签收谁签字。现在让我选接收人，我不知道哪些人要发。说明改成了「请说明分发用途，如：培训用、受控副本等」，老张还是不知道写什么，空着点了「分发」。

#### 旅程 D：看今天该干什么
点「本月待办」，出来日历。老张想找今天到期的校准，但日历上密密麻麻都是字，找不到「今天」高亮。老张眼睛不好，看小字费劲。

**老张的核心困惑**：
- 「通知」两个字代替 0 后，含义仍不明确，不知道是入口还是状态。
- 版本/修订状态的括号说明太长，不符合纸质习惯。
- 签批时不知道自己该当「审核人」还是「批准人」。
- 分发记录不知道该发给谁、写什么用途。
- 本月待办找不到今天。

### 1.2 技术负责人李工

#### 旅程 A：第一次登录
李工登录后看到系统标题是中文，主导航也中文化了，觉得还行。但他注意到右上角除了「修改密码」「退出」，还有个「通知」。李工心想：我在其他系统里，通知一般是铃铛图标，没有字。这里写个「通知」反而像菜单项。

#### 旅程 B：审核一份体系文件
李工作为技术负责人，被分配审核一份文件。他进入文件详情页，看到按钮一排：编辑、提交审核、发起修订、定期评审、下载附件、在线编辑、受控打印、返回列表。李工纳闷：「提交审核」是我把文件送出去审核，还是我已经审核完了提交？按钮没有主从关系，他不知道第一步该点哪个。

黄色卡片「在线签批」里，角色显示「审核人」。李工点「打开签署页」，签名区上方小字写着「审核人 · qm@lab.com」。李工签完字，状态变成「已批准」。他愣了：我只是审核人，怎么就「已批准」了？在纸质流程里，审核和批准是两个人、两个动作。系统里审核人签完字就直接变成已批准，让他觉得自己是不是越权了。

#### 旅程 C：处理不符合工作
李工点「质量改进」→「不符合工作」，看到一条记录，详情页按钮是「创建纠正措施」。李工懂纠正措施，但不知道点击后会发生什么：是自动生成一张纠正措施单，还是弹窗让我填？弹窗文案现在是「创建纠正措施单（CAPA）？」，比原来的「创建CAPA？」好，但仍没有说明创建后会关联到当前这条不符合工作。

#### 旅程 D：责任链签批
李工进入「体系策划」→「责任链」，页面提示「保存只是草稿。完成校验并签批后，授权才正式生效。」这句话比原来短了，但李工作为技术负责人，关心的是：我要签什么？我签的是整个责任链，还是我一个人的任命？页面下方「我的待签批批次」里列出了待签批的人员和岗位，李工看到后才明白：原来我签的是对某几个人的任命。

**李工的核心困惑**：
- 「提交审核」按钮语义不清，审核人和提交人角色混淆。
- 审核人签完字状态直接变「已批准」，与纸质审核-批准分离流程冲突。
- 创建纠正措施弹窗缺少后续说明。
- 责任链签批缺少「本次我签的是什么」的明确提示。

### 1.3 新人记录员小陈

#### 旅程 A：第一次登录
小陈登录后页面很正常，但首次改密时看到提示：「首次登录需设置安全密码：请使用 8 位以上，包含大小写字母、数字和符号（例如 Zb@2026lab，请勿直接使用示例）。」小陈觉得示例很清楚，但提示里「当前密码」让他困惑：我是第一次登录，哪来的当前密码？后来才明白是当前账号的初始密码。

#### 旅程 B：填一条记录
小陈点「记录填报」→「填写记录」，找到一条记录详情页。页面状态显示「草稿」，小陈放心了：草稿就是还能改。但他看到按钮「生成PDF」「下载PDF」「编辑」。小陈想：我先填内容，再生成 PDF 交差。他点「编辑」，发现可以改。填完后点「生成PDF」，状态变成「已生成PDF」。

过了几天领导说数据填错了。小陈再点「编辑」，按钮灰了，悬停提示：「已形成 PDF，不可直接编辑。如需修改，请联系质量负责人走作废/换版/更正流程。」小陈懵了：什么叫走流程？他找了半天没找到「作废」或「更正」按钮。最后只好问质量负责人。

#### 旅程 C：看本月待办
小陈点「本月待办」，看到日历上列了校准、期间核查、内审节点、标准查新提醒。他不知道是哪些事归自己管。日历上没有「我的待办」过滤，所有事混在一起。

**小陈的核心困惑**：
- 首次改密「当前密码」说法对新人不友好。
- 记录已形成 PDF 后，找不到「作废/更正」入口。
- 本月待办没有「指派给我」的过滤。

### 1.4 文件资料管理员周姐

#### 旅程 A：第一次登录
周姐登录后看到系统标题是中文，觉得亲切。但右上角「通知」两个字让她以为是工作通知，点进去发现是消息中心，里面空着。她想：没有通知就别显示啊，或者显示「无新通知」。

#### 旅程 B：收发文件
周姐的工作是收发文件。她进入文件详情页，看到「分发记录」区域。要选接收人、填说明，然后点「分发」。周姐想问：能不能像邮件一样选部门群发？多选框里是按人列的，没有按部门筛选。她还要一个个勾选。

被分发的人登录后看到「确认接收」按钮，点了就行。周姐想知道谁还没确认，但列表里「接收确认」一列显示的是时间或「未确认」。周姐希望有批量提醒功能：给未确认的人发通知。

#### 旅程 C：文件作废
文件需要作废时，周姐看到红色按钮「作废并回收」。她点了，弹窗现在是「作废后，系统将通知接收人确认回收。是否继续？」周姐松了口气：至少知道是系统去通知，不是她一个个打电话。但她还是担心：作废后旧版文件还能下载吗？电子版是不是自动失效？页面上没说。

#### 旅程 D：文件版本管理
周姐看到文件详情页「版本/修订状态」显示「A/0（A 版第 0 次修订）」。她熟悉档案编号，但这种写法不习惯。她想看修订历史，页面下方有「修订历史」表格，列名是版本、修订次、修订说明、快照文件、修订时间。周姐不懂「快照文件」是什么，点了一下是下载链接。她建议叫「历史版本附件」或「旧版文件」。

**周姐的核心困惑**：
- 「通知」入口语义不清。
- 分发记录缺少按部门群发和批量提醒。
- 作废后旧版文件是否可用没有说明。
- 「快照文件」术语不直观。

## 3. Top 10 速赢清单（按性价比排序）

1. **本月待办默认「今日待办」+「指派给我」过滤** → 每天上班第一眼就能看到今天该干什么。
2. **记录详情增加「发起更正」入口** → 解决已形成 PDF 后用户找不到路的核心痛点。
3. **签批卡片标记当前角色「（我）」并默认展开** → 避免签错位置。
4. **审核人签完状态显示「已审核」而非「已批准」** → 符合纸质流程认知，减少越权焦虑。
5. **文件详情按钮按角色/状态动态显示主操作** → 减少一排按钮的认知负担。
6. **分发记录增加按部门全选和默认用途** → 文件管理员收发文件效率翻倍。
7. **右上角「通知」无消息时只显示铃铛图标** → 进一步减少视觉噪音。
8. **作废弹窗补充旧版文件不可用说明** → 让文件管理员敢点。
9. **创建纠正措施弹窗说明关联关系** → 减少误操作。
10. **版本/修订状态简化为「A/0 版」+ hover 说明** → 更符合纸质档案员习惯。

## 4. 给开发团队的总体建议

UX-1 把英文术语清零后，系统已经从"看不懂"变成了"能看懂但不知道怎么操作"。下一步重点是**把"系统语言"翻译成"岗位语言"**：不是把英文换成中文就够了，而是要让每个角色在每一步都知道"我现在该干什么""我点了这个会发生什么"。

具体建议三条：

1. **按角色裁剪界面**。审核人、批准人、文件管理员、记录员登录后，同一个页面应该突出不同的主操作。不要把所有按钮都摆出来让用户自己挑。

2. **状态词要匹配纸质流程**。审核通过就是「已审核」，不要直接跳到「已批准」；记录锁定就是「已锁定/已归档」，不要让用户猜「已生成PDF」是什么意思。

3. **每个危险操作和流程断点都要给下一步入口**。比如编辑按钮灰掉时，不要只说"走流程"，要给出"发起更正"按钮或明确的联系人；分发文件时，要给默认用途和按部门全选，不要让用户从空白开始填。

总之，中文化只是第一步。真正的用户体验优化，是让系统学会用每个岗位习惯的方式说话。
