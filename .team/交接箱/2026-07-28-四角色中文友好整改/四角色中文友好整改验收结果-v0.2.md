# 四角色中文友好整改验收结果 v0.2

日期：2026-07-28
环境：`http://127.0.0.1:8021` 治理试运行模拟环境
结论：本轮规格内的四条关键路径已完成整改，并在 8021 通过浏览器复验和自动回归。纸质体系仍为唯一正式体系，本结论不代表电子体系正式发布。

## 一、完成结果

### 1. 质量员查阅体系文件

- 文件列表持续显示“纸质文件仍为正式依据”，并区分当前试运行版本、纸质现用来源和历史版本。
- 文件详情把修订摘要作为主要内容，原始 JSON 和技术字段降入“技术信息”。
- 连续正文按标题、段落、清单和表格渲染。
- 生成批次、内部状态、SHA-256 和系统内部路径已移入折叠的“技术信息”，默认阅读页不再暴露。
- 文件变更历史中的 `trial_ready`、`obsolete` 已改为“当前试运行版本”“历史版本（已停用）”。

### 2. 技术负责人审核与签字

- 工作台只统计当前账号真实待签数量，不再把全库草稿误称为待审核。
- 待办入口直达“待我签批”清单；没有任务时明确显示“当前没有需要您签批的文件”。
- `status=reviewing` 正确回显“审核中”，不再错误显示“已作废”。
- 通知按最新时间倒序，以中文显示业务类型、状态、完整对象和“查看并处理”主操作。

### 3. 新人记录员填写记录

- “填写记录”页面改为“已填记录”，主入口统一为“开始填一张新表”。
- 表格输入格具备中文可访问名称、必填标识、输入提示和固定单位。
- `SIM-XZTC/BG-02-01` 已通过换版建立 `GOV-TRIAL/0.2`：
  - 监控月份使用月份控件；
  - 日期使用日期控件；
  - 温度、湿度使用数值控件并显示 `℃`、`%RH`；
  - 符合性使用“符合/不符合”选择；
  - 判定“不符合”时，异常处置自动变为必填；
  - 记录人使用人员选择；
  - 至少填写一行逐日监控数据后才能保存。

### 4. 文件资料管理员换版与打印

- 只有“草稿＋支持格式＋在线编辑服务可用”时才显示在线编辑入口。
- 受控状态文件统一从“发起修订”建立新草稿；页面预告原版本、拟生成版本和旧版本完整保留规则。
- 受控打印必须先填写份数、用途、接收人，并勾选核对确认，之后才创建打印登记。
- Markdown/文本附件会把完整正文合并到打印页并显示试运行水印。
- Word/PDF 暂不能自动合并正文时，页面明确说明“登记已创建、正文尚需下载打印”，不再暗示已经生成完整受控副本。
- 受控打印记录新增“接收人/部门”字段并在详情页展示。

## 二、浏览器复验

| 角色视角 | 实际身份 | 复验结果 |
|---|---|---|
| 熟悉纸质体系、不熟悉电脑的质量员 | `sim_preparer` | 能从文件详情进入连续正文；业务正文与技术信息已分层 |
| 只负责技术审核签字的技术负责人 | `sim_reviewer` | 工作台显示本人真实待签数量，通知和待签清单使用中文业务语言 |
| 计算机操作尚可的新人记录员 | 借用 `sim_reviewer` 的 staff 权限 | 能按月份、日期、数值、符合性和人员字段填写；条件必填实时生效 |
| 熟悉办公流程的文件资料管理员 | `sim_preparer` | 能预知修订后果，打印前必须确认，打印后能看到用途、接收人和唯一编号 |

复验期间发现并当场修复：

1. Markdown 打印正文误调用不存在的 `render()` 方法导致页面错误，已改为真实存在的安全渲染方法 `toHtml()`，并增加回归断言。
2. 文件变更历史残留内部英文状态码，已统一转换为中文业务状态。
3. 工作台快速入口仍使用旧文案“选择模板填写”，已统一为“开始填一张新表”。

## 四、数据与运行边界

- 本轮只对 8021 增加 `controlled_print_logs.recipient` 字段，并换版一张 SIM 记录模板。
- 模板升级脚本具备试运行开关、批次和数据库边界校验；重复执行会识别为已是目标版本，不会继续生成新版本。
- 本轮未对 8010 执行数据写入、迁移或重建。
- 原模板、原文件和原记录均未覆盖或删除。

## 五、仍保留的后续项

这些不影响本轮规格验收，但不应误报为已经完成：

1. 尚未建立独立 `sim_recorder`，因此新人最小权限和菜单隔离仍需专门验收。
