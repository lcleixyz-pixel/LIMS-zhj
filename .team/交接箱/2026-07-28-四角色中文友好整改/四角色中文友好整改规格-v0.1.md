# 四角色中文友好整改规格 v0.1

## 目标

让熟悉纸质体系但不熟悉电脑的质量员、只负责技术审核与签字的技术负责人、新人记录员、文件资料管理员，能够在 8021 试运行环境中根据中文业务提示独立完成主要操作，不需要先理解数据库状态、内部路径、英文枚举或技术组件名称。

## 已确认方案

采用“定向业务流程整改”：

1. 不更换 ThinkPHP、Bootstrap、现有权限和签批架构。
2. 不整站视觉翻新，只整改四个角色真实经过的页面、数据口径和反馈文案。
3. 页面先回答“这是什么、现在到哪一步、我要做什么”，技术信息降级到可展开区域。
4. 修复真实数据口径错误，不用文案掩盖待审数量、状态筛选和字段类型问题。
5. 仅在 8021 写入明确的试运行模板修正；不写 8010。

未采用的方案：

- 仅改按钮和提示语：改动轻，但不能解决待审数字、筛选和字段约束错误。
- 全量重做四套岗位首页：收益可能更高，但当前文件仍在治理换版，范围过大且会拖慢试运行。

## 业务语言规则

1. `draft`、`reviewing`、`trial_ready` 等英文状态不得作为主要展示文字。
2. “试运行就绪”必须解释为“8021 当前可试用，纸质文件仍为正式依据”。
3. “已发布”在 8021 不得暗示已经替代纸质体系。
4. 每个成功提示使用“动作 + 结果 + 下一步”。
5. 不可用入口不展示；确需展示时必须说明不可用原因和可执行替代路径。
6. 内部文件路径、SHA、打印模板键、原始 JSON 默认不直接暴露给普通业务人员。

## 四条整改链

### 1. 质量员查阅体系文件

- 文件筛选必须正确回显选中的层级和状态。
- 同编号多版本必须明确标识“当前试运行版本、纸质现用来源、历史/冲突版本”。
- 文件详情显示可理解的修订摘要；原始 JSON 放入“技术信息”。
- 结构化状态翻译为中文业务状态。
- 连续正文按标题、段落、清单和表格渲染，不再显示原始 Markdown 和内部路径。

### 2. 技术负责人审核与签字

- 首页“待我签批”只统计当前登录人的待处理审批，不统计全系统草稿。
- 点击数字进入“待我签批”清单，不进入全体审核中文件。
- 通知按最新时间排序，显示业务类型、完整对象、结果和唯一主操作。
- 没有本人待办时明确显示“当前没有需要您签批的文件”。

### 3. 新人记录员填写记录

- “填写记录”列表改名为“已填记录”；主按钮改为“开始填一张新表”。
- 表单控件具备中文标签、输入示例、必填标识和键盘可识别名称。
- `XZTC/BG-02-01` 环境监控表使用月份、日期、数值、选择人员和符合性选择控件。
- 温度、湿度显示固定单位；异常处置在判定“不符合”时必填。
- 至少填写一行逐日监控数据后才能保存。

### 4. 文件资料管理员换版与打印

- 仅当在线编辑服务真实可用、附件格式受支持且文件为草稿时显示“在线编辑”。
- 已发布/试运行就绪文件只能通过“发起修订”建立新草稿，不出现覆盖式编辑暗示。
- 发起修订页显示原版本、拟生成版本、审批路径和旧版保留说明。
- 受控打印先填写用途、份数、接收人并确认，再创建打印日志。
- 对可直接渲染的 Markdown/文本附件，在打印页展示完整正文并叠加水印。
- 对 Word/PDF 等暂不能合并的附件，明确显示“登记已完成、正文尚需下载打印”，不得暗示完整打印已经完成。

## 数据与安全边界

- 8021 是试运行沙箱，纸质体系仍为唯一正式体系。
- 不改 8010 数据，不迁移真实运行记录，不把模拟记录作为正式证据。
- 受控文件原版本和原始记录不得覆盖或删除。
- 本轮数据库调整只允许增加受控打印接收人字段及更新一张 SIM 环境监控模板。

## 验收标准

1. 自动回归覆盖上述四条路径，并完成至少一次红灯到绿灯验证。
2. 使用四个 SIM 角色在浏览器重新走查关键页面。
3. 技术负责人首页不再显示与本人无关的待审数字。
4. `status=reviewing` 筛选正确显示“审核中”，不得误显示“已作废”。
5. 连续正文页面不再以整页 `<pre>` 原样输出 Markdown。
6. 环境监控表按月份、日期、数值、选择项和人员控件显示并执行服务端校验。
7. 未配置 OnlyOffice 时，文件详情不显示“在线编辑”入口。
8. 点击受控打印不会立即生成日志，必须经过中文确认表单。
9. 8021 复验通过；8010 不写库、不重建、不迁移。
