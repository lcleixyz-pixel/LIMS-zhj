## 1. 验证目的与边界

确认 jewelry-qms 的访问控制、数据完整性、变更控制、备份恢复、系统失效应对和数据交换能力具备可复核证据。验证对象为当前代码、Docker 部署定义及隔离测试环境；不把技术演练冒充真实事故、受控发布或长期运营记录。

## 2. 方法与环境

- 功能确认：仓库现有 77 个 `*_smoke.php`。
- 演练确认：A2 备份恢复、A3 五角色权限矩阵、系统失效隔离与恢复。
- 文档确认：`QMS_OPERATIONS_RUNBOOK.md`、系统变更控制规定和变更台账。
- 数据边界：重复性测试使用由当前基线克隆的临时数据库，测试结束即销毁；系统失效演练使用独立 8011 实例，现用 8010 服务全过程保持 HTTP 200。

## 4. 2026-07-11 收官验证结果

| 类别 | 数量 | 结果 |
|---|---:|---|
| 可重复自动冒烟测试 | 75 | 75 通过，0 失败（隔离临时数据库） |
| 外部数据验收脚本 | 2 | 不计入自动回归；需指定原始工作簿或当前人工填报源材料 |
| 合计脚本 | 77 | 分类完整，无以跳过冒充通过 |

两项外部数据验收脚本为：

1. `qms_current_files_seed_smoke.php`：依赖两份当前环境不存在的指定 Excel 原件，且包含 `apply=true`，只可在材料齐备并单独授权时执行。
2. `record_form_source_instance_draft_smoke.php`：读取可变的人工填报源材料；当前材料存在待人工补录字段，不适合作为固定值自动回归。

收官中发现并修复：站点测试 ID 冲突、结构包测试取错记录块、重建评审断言仍指向旧编号、长表单会话保活脚本未纳入版本控制，以及外部依据 PDF 抽取镜像缺少 `pdftotext`。五项定点复验均通过。

## 5. 演练结论

- 备份恢复：临时库完成备份、删除、恢复和销毁，记录实例数 12→11→12，现用库未改。
- 权限矩阵：staff 填写页返回 200；auditor 建立体系文件被 302 拦回仪表盘。
- 系统失效：独立 8011 服务停止后不可访问，重启后恢复 200；现用 8010 全程 200；纸质替代记录模板可定位；演练前后核心业务计数不变。
