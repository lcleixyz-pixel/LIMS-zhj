# GOV-TRIAL/0.2 连续修订解析稿设计

## 1. 目标

在 8021 隔离环境中，以现用质量手册和 2022 版程序全文为底稿，将已经签认的 G1 修订决定按可验证补丁叠加，形成连续可读、来源可追溯、冲突可阻断的 `GOV-TRIAL/0.2` 质量手册和程序解析稿。

本功能解决当前 `GOV-TRIAL/0.1` 只有条款块、关系块和修订说明，使用人不能从头到尾阅读实际修订后正文的问题。

## 2. 边界

- 纸质体系仍是唯一正式体系。
- 只写 8021/3319 隔离环境，不写 8010/3307。
- 不修改现用 Word、现用 Markdown 转换件或 `knowledge/internal/`。
- 不把解析稿标为正式受控文件，不自动执行发布、作废、培训或真实记录迁移。
- 不依赖 OnlyOffice 在线保存能力。
- 本轮输出连续 Markdown 和 HTML 阅读稿；正式 Word 排版与修订痕迹文件不在本轮范围。

## 3. 采用方案

采用“现用全文 + 可验证补丁 + 冲突阻断 + 连续渲染”。

不直接重写整篇文件，也不把候选稿全文当作现用底稿。系统先读取现用文件的连续文本，再逐条应用有签认来源的修订补丁。未被补丁命中的原文必须原样保留。

## 4. 输入

### 4.1 基线正文

- 质量手册：现用第四版的连续 Markdown 转换件。
- 程序文件：37 份 2022 版程序连续 Markdown 转换件。
- 附录：现用手册附录 14～16；必须进入质量手册连续稿和结构化块。

每份基线登记：

- 文件编号和标题；
- 原始路径；
- SHA-256；
- 版本；
- 文本行数；
- 表格数量；
- 标题层级；
- 读取时间。

### 4.2 修订依据

只接受以下状态的治理材料作为自动补丁来源：

- 已签认候选；
- 收官纪要明确生效；
- 后续签认文件明确修正或取代前一决定。

“候选、待人审、建议、拟定、待确认”不得自动改写正文，只能进入冲突或待审清单。

G2 记录蓝图用于核对程序的记录要求和表号，不直接改写手册或程序正文，除非 G1/G2 收官文件明确要求同步修改程序记录节。

## 5. 补丁模型

每项补丁是一个明确对象，至少包含：

```php
[
    'patch_id' => 'G1-R10-CX26-001',
    'target_doc_number' => 'XZTC/CX-26-2022',
    'operation' => 'replace_exact',
    'anchor' => '待替换的原文或稳定标题',
    'expected_old_sha256' => '原文片段哈希',
    'replacement_markdown' => '已签认的新文字',
    'source_path' => '.team/交接箱/...',
    'source_sha256' => '签认来源哈希',
    'decision_status' => 'signed',
    'decision_date' => '2026-07-22',
    'supersedes_patch_id' => '',
    'clause_refs' => ['7.11', '8.3'],
    'reason' => '修订原因',
]
```

支持的操作仅限：

- `replace_exact`：精确替换一段原文；
- `insert_after_heading`：在唯一标题后插入新条款；
- `delete_exact`：按明确签认决定删除原文；
- `append_record_requirement`：在程序记录章节追加已确认的记录要求。

不提供模糊全文替换或运行时 AI 自主改写。

## 6. 内容保留规则

1. 仅统一换行符，不自动改写标点、术语、表格或段落顺序。
2. 未命中补丁的文本逐字符保留。
3. 表格作为正文的一部分保留；补丁如涉及表格，必须以完整表格行或唯一单元格文本为锚点。
4. 删除必须由 `delete_exact` 表达，并有明确签认来源。
5. 原文存在但新稿未覆盖的内容继续保留，不能因“新稿看起来更完整”而整体替换。
6. 附录 14～16 与正文一起参与完整性校验。
7. 渲染前后分别计算未修改区段哈希，发现意外变化即阻断。

## 7. 冲突审查

### 7.1 阻断型冲突

以下任一情况出现时，补丁不得应用，目标文件不得进入 `trial_ready`：

- 基线文件 SHA-256 与登记值不一致；
- 原文锚点不存在或出现多次；
- `expected_old_sha256` 不匹配；
- 两个补丁修改同一文本区间且没有明确取代关系；
- 后一签认没有明确说明取代前一签认，但内容相互矛盾；
- 候选或待确认材料试图覆盖已签认决定；
- 删除操作没有明确签认依据；
- 手册与程序对同一职责、批准岗位、适用性、期限或记录表号给出相反要求；
- 输出丢失正文、表格或附录；
- 输出仍保留已明确退场的现行依据或路径，且没有历史说明。

### 7.2 提醒型发现

以下情况生成提醒，但不阻断连续预览：

- 原文存在明显错别字，但签认材料没有授权修改；
- 同一术语存在不同写法但不改变业务含义；
- 程序记录节未列全已签认记录表，但补丁依据仍需人工复核；
- 章节编号连续性可疑但正文未丢失。

### 7.3 决定优先级

只有明确的世系关系才能自动确定优先级：

1. 明确写明“修正、替代、以本件为准”的后续签认；
2. 同一批次的终局/收官签认；
3. 较早的已签认决定；
4. 候选和建议材料。

同级文件仅因日期较晚，不自动覆盖。无法确定时保留原文并阻断。

## 8. 已知高风险冲突专项

冲突审查至少覆盖：

- 手册仍引用 2018 程序编号，而现用程序为 2022；
- 手册正文程序数量、附录程序数量和现用程序数量不一致；
- CX-21 管理评审批准岗位冲突；
- CX-20 内审职责、自审和批准权冲突；
- 不抽样与 CX-35 仍有效之间的冲突；
- 不分包与 BG-10、CX-28 分包路径之间的冲突；
- 不常规留样与 CX-28、BG-30 留样复测之间的冲突；
- BG-21-03 名称和用途冲突；
- BG-35 标准物质记录号与 CX-35 抽样程序号冲突；
- 保存期限 3 年、6 年和不少于 6 年之间的冲突；
- RB/T 214-2017 仍作为现行 CMA 主依据的问题；
- 电子记录投用前后、人工编号与系统编号并行的冲突。

## 9. 处理流程

```text
冻结基线全文与哈希
  → 加载已签认补丁清单
  → 校验补丁来源和世系
  → 执行锚点与重叠冲突检查
  → 对无冲突补丁生成解析稿
  → 校验未修改内容、表格、附录和编号
  → 生成连续正文、修订对照和冲突报告
  → 无阻断文件装入 GOV-TRIAL/0.2
  → 有阻断文件保留预览但不进入签批
```

## 10. 系统装配

### 10.1 版本世系

- 保留 `GOV-TRIAL/0.1` 数据和输出。
- 新建 `GOV-TRIAL/0.2` 结构化文件版本。
- `0.2` 记录其基线文件、来源哈希和取代的 `0.1` 试运行对象。
- 不复用 `0.1` 的 `not_rendered` 状态冒充新版本。

### 10.2 状态

- `draft`：已生成连续预览，仍有阻断冲突或尚未复核；
- `trial_ready`：补丁、完整性和冲突检查均通过；
- `under_review`：进入 8021 模拟审核；
- `published` 不用于本轮治理解析稿。

### 10.3 结构化文件

- 每份程序按连续正文的实际标题拆分为多个稳定内容块；
- 手册正文和附录均形成稳定内容块；
- 按 `sort_order` 重新渲染连续 Markdown；
- 渲染文件、历史存档、内容哈希和变更记录沿用 `QmsDocumentStructureService`；
- 不直接修改 `knowledge/internal/`，需要时由现有导出命令重新生成。

## 11. 输出

交接目录：

`.team/交接箱/2026-07-25-8021治理体系试运行装配/GOV-TRIAL-0.2/`

至少包含：

- `连续正文/`：质量手册和程序连续 Markdown；
- `修订对照/`：每项补丁的原文、修订后文字、来源和结果；
- `冲突审查/冲突总表.md`；
- `冲突审查/冲突总表.json`；
- `装配清单.json`；
- `验证报告.md`；
- `版本台账.md`。

每份连续正文首页必须显示：

- `SIM` 和“治理试运行候选”；
- 基线版本；
- 解析稿版本；
- 生成批次；
- 阻断冲突数量；
- 非正式受控文件提示。

## 12. 页面入口

复用“文件结构化”和“文件详情”页面：

- 增加“连续正文”入口；
- 增加“修订对照”入口；
- 增加“冲突审查”入口；
- 有阻断冲突时隐藏或禁用“提交审核”；
- 页面明确显示“本文件由现用全文与已签认补丁生成”。

不进行整体界面翻新。

## 13. 错误处理

- 单个文件冲突不终止其他文件生成；
- 单个补丁失败不得部分写入该文件；
- 先生成内存结果并完成校验，再以事务写入 8021；
- 交接文件先写临时路径，校验完成后再替换目标文件；
- 重复执行相同批次必须幂等；
- 非 `QMS_TRIAL_MODE=true` 或批次不匹配时拒绝应用。

## 14. 测试

### 14.1 单元行为

- 精确替换成功；
- 唯一标题后插入成功；
- 未修改文本保持一致；
- 锚点缺失、多义、哈希漂移和重叠补丁被阻断；
- 没有明确取代关系的签认冲突被阻断；
- 明确修正关系按世系生效；
- 未签认候选不能进入正文；
- 删除无签认依据被阻断；
- 表格和附录完整保留。

### 14.2 集成行为

- 生成连续手册和程序解析稿；
- 多块按顺序渲染；
- `0.1` 保留，`0.2` 建立新世系；
- 有冲突文件保持草稿且不能提交审核；
- 无冲突文件可进入 `trial_ready`；
- 重复装配数量和哈希不变；
- 8021 有新增结果，8010 前后指纹一致。

## 15. 完成判据

- 质量手册形成一份从头到尾可读、包含附录 14～16 的连续解析稿；
- 37 份程序均形成连续解析稿或明确的阻断报告；
- 每项实际修改都能回溯到签认来源；
- 未修改内容无意外丢失或改写；
- 所有阻断冲突均显式列出，没有静默裁决；
- 8021 可查看连续正文、修订对照和冲突审查；
- 通过自动测试和隔离环境验证；
- 8010、现用文件和 `knowledge/internal/` 无本任务写入。
