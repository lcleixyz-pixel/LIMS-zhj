# 仓库拆分：移除参考系统至独立归档仓

> spec 日期：2026-07-09
> 决策来源：《项目管理体检诊断-2026-07-09》+ 用户拍板
> 性质：仓库结构整理，不改业务代码、不改 git 历史。

## 背景

体检发现主仓 `.git` 已 150M、13229 个跟踪文件，其中三个根目录占了大头：

| 目录 | 体积 | 性质 | 来源 |
|---|---|---|---|
| `flinkiso/` | 96M | CakePHP 旧 LIMS 参考实现 | initial monorepo（reference projects） |
| `flinkiso-lite-master/` | 40M | 旧 LIMS 精简版参考 | 同上 |
| `jewelry-qms-legacy/` | 37M | jewelry-qms 的 CakePHP 前任 | CakePHP→ThinkPHP 迁移遗留 |

合计约 173M、1.1 万文件，全是参考/历史性质。已验证：主项目运行代码（`jewelry-qms/app`、路由、配置）对它们**零依赖**。

## 决策（用户拍板）

1. **彻底度**：目录清爽即可——不移除 git 历史、不改写提交哈希、不可逆操作一律不做。仓库 `.git` 体积暂不减，接受。
2. **去向**：另建独立归档仓 `LIMS-zhj-reference`，保留当前文件快照（不带主仓历史，历史本就留在主仓 git log 里）。

## 范围（严格限定）

**移除清单（仅根目录这三个）：**
- `flinkiso/`
- `flinkiso-lite-master/`
- `jewelry-qms-legacy/`

**原样保留（一个文件不动）：**
- `整合/`（含技能套装=内容引擎、接口契约、金样、总体规划、体检诊断、证据导出）
- `jewelry-qms/`（运行平台本体）
- `.team/`（作战室、当前战役、行动单、不好用清单）
- `docs/`、`knowledge/`、`参考/`、`现用文件/`

## 步骤

1. **建归档仓**：在 `01-项目代码/LIMS-zhj-reference/` 新建独立 git 仓，复制三目录当前内容，做首个 commit。
2. **主仓移除**：`git rm -r` 三目录，单独 commit（信息写明移至归档仓）。历史保留，可逆。
3. **留指针**：主仓根目录加 `REFERENCE_ARCHIVE.md`，说明三目录去向与归档仓位置。
4. **防误加**：三目录名加入 `.gitignore`。

## 交付物

- 干净主仓：跟踪文件数从 ~1.3 万降到 ~2000，根目录一眼看清。
- 独立归档仓 `LIMS-zhj-reference`：三参考系统完整在内。
- 团队审计看主仓当前分支（体检→救作战室→工程链路→拆仓，完整故事）。

## 风险与可逆性

极低。三目录完整历史留主仓 git，归档仓有完整文件副本，任何一步可 `git revert`。不影响 jewelry-qms 运行（零依赖已验证）。

## 不做（YAGNI）

- 不用 filter-repo 改写历史。
- 不删 `.git` 旧对象（体积暂不减）。
- 不新开 `clean-for-review` 分支。
- 不动整合/技能套装（核心活资产，非遗留）。
