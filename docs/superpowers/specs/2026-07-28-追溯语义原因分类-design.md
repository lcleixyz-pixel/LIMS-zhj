# 追溯语义原因分类设计

## 1. 目标

解决工作台把“章节正确但关系混装”笼统说成“章节错挂”的问题，让用户能直接看懂：

1. 错的是章节；
2. 错的是关系形态；
3. 章节和关系形态都可以，但尚未人工确认。

本项只改语义解释、页面标签和下一步动作，不自动确认、不自动拆分、不改写历史关系。

## 2. 采用方案

保留现有顶层状态，增加原因分类：

| 顶层状态 | 原因代码 | 中文标签 | 含义 |
|---|---|---|---|
| `suspected_mismatch` | `wrong_section` | 章节不匹配 | `implements` 指向的章节不在建议主章节集合内 |
| `suspected_mismatch` | `mixed_relation` | 关系混装 | 手册章节夹在非 `implements` 关系或多对象历史关系中 |
| `review_required` | `unconfirmed_relation` | 尚未确认 | 章节候选吻合，但置信度不足或带有继承待复核标记 |

`aligned`、`missing_primary`、`candidate_unavailable` 等现有状态保持不变，治理队列的数量、筛选参数和完成度算法不变。

### 未采用方案

- 直接把三类原因升级为新的顶层状态：会破坏现有治理队列筛选和统计，改动面过大。
- 只改页面文案：服务和其他页面仍会继续输出矛盾解释，无法形成统一契约。

## 3. 判定优先级

对带手册章节的关系按以下顺序判断：

1. `mentions`、`supporting` 仍是辅助关系，不进入主链异常。
2. 关系不符合 `implements` 契约，或历史行被关系策略识别为混装：`mixed_relation`。
3. `implements` 的章节不属于建议主章节：`wrong_section`。
4. 章节正确但置信度不是 `high`，或说明包含“待0.2逐块复核”：`unconfirmed_relation`。
5. 章节正确、关系正确且人工确认充分：已确认主链。

混装优先于章节不匹配，因为应先恢复“一条关系一个用途”的结构，再判断独立手册关系是否选对章节。

## 4. 服务输出

`QmsTraceSemanticGuardService` 为单条手册关系提供统一解释结果：

- `state`：沿用现有治理状态；
- `reason_code`：三类原因之一或空；
- `reason_label`：中文短标签；
- `message`：说明“当前是什么、为什么不能计入、应该怎么处理”；
- `recommended_action`：供工作台下一步动作直接使用。

工作台顶层 `issues[0]` 同样携带 `reason_code`、`reason_label` 和 `recommended_action`。

## 5. 中文解释

### 章节不匹配

“当前手册章节 4.2 与建议主手册章节 8.3 不一致。请移除或改为辅助关系，再单独建立 8.3 手册主链。”

### 关系混装

当章节与候选一致：

“6.2 章节候选正确，但当前与运行记录、岗位等对象混在同一关系中，尚不能作为手册主链。请按拆分预览建立独立的 6.2 手册主链。”

当章节也不一致：

“当前关系同时混装多个对象，且手册章节 4.2 与建议章节 8.3 不一致。请先按拆分预览拆开，再复核手册章节。”

### 尚未确认

“6.2 与建议章节一致，但该关系仍是继承或待复核候选，尚未人工确认，暂不计入闭环。”

## 6. 页面交互

- 工作台结论区显示原因标签，不再统一使用“疑似错挂”。
- 手册条款卡片对异常行显示“章节不匹配”“关系混装”或“尚未确认”。
- 下一步动作直接使用服务提供的中文建议：
  - 章节不匹配：移除或改为辅助关系，再补正确主链；
  - 关系混装：先按拆分预览拆开，再确认独立主链；
  - 尚未确认：逐条确认继承关系。
- 追溯复核页沿用 P0-3 的历史混装拆分预览，不增加自动拆分按钮。

界面保持现有 Bootstrap 信息层级，不增加弹窗、动画或新的页面。

## 7. 边界

- 不新增数据库字段或迁移；
- 不改变关系保存契约；
- 不修改历史追溯关系；
- 不改变候选是否计入闭环的规则；
- 不写 8010，不把 8021 结果当作正式运行证据。

## 8. 验收标准

1. 正确章节夹在 `requires_record` 混装关系中时，显示“关系混装”，不再说章节错了。
2. 独立 `implements` 指向错误章节时，显示“章节不匹配”。
3. 正确的继承关系显示“尚未确认”。
4. 三类情况都有不同的下一步动作。
5. 现有治理队列顶层状态和统计不回退。
6. 8021 页面中文解释与服务输出一致，浏览器控制台无错误，验收过程不写数据。
