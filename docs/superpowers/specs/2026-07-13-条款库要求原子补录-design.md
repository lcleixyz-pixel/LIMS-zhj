# 条款库要求原子补录设计

- 日期：2026-07-13
- 状态：用户已批准
- 适用系统：`jewelry-qms`

## 目标

依据用户提供并已归档到 T1 交接包的 Markdown 原文，补齐当前条款库中缺失的“可用于符合性判定的要求原子”，同时避免把术语、章节标题和纯引用文件当作要求条款。

## 已批准口径

1. GB/T 27025-2019 的 `3.1–3.9` 是术语和定义，不补录。
2. GB/T 27025-2019 只补录 7 个已核实缺失要求：`4.1.1、5.5、6.3.2、6.3.5、7.2.1.6、7.7.3、7.8.2.2`。
3. CNAS-CL01-G001:2024 和 CNAS-CL01-A015:2018 只补录要求原子，不补录章级标题、父级目录、术语或纯引用项。
4. CNAS-CL01:2018 不复制一套与 GB/T 27025 重复的条款，只在依据记录中登记“适用、等同采用、以 GB/T 27025 为稳定条款载体”的说明。
5. 不修改质量手册、程序文件和 `knowledge/internal/`，不启动 T2。

## 数据边界

- 写入：`qms_clauses`、`qms_clause_texts`；以及 CNAS-CL01 对应 `qms_sources.review_note`。
- 不写入：要素映射、手册章节映射、程序文件映射、记录表格、运行证据。
- 已存在的同依据同编号条款不覆盖；内容不一致时停止并报告冲突。
- 所有新增文本均保留 Markdown 文件名、行号定位、SHA-256 哈希和“人工确认要求原子”复核说明。

## 要求原子清单

- GB/T 27025-2019：7 条。
- CNAS-CL01-G001:2024：37 条。
- CNAS-CL01-A015:2018：18 条。原 v0.2 清单漏掉了与 `7.4.1` 同行出现的 `7.4.4`，本次按原文补正。
- 合计计划新增：62 条；实际新增数以写库前现库去重预演为准。

## 安全与回滚

1. 写库前导出 `qms_sources`、`qms_clauses`、`qms_clause_texts` 的 SQL 备份。
2. 补录器默认只生成预演 JSON/CSV/Markdown；只有显式 `--apply` 才写库。
3. 正式写入使用单一数据库事务；任一来源缺失、原文未唯一定位、编号冲突或写后计数不符时整体回滚。
4. 补录器幂等：重复执行应报告 `existing`，不得产生重复行。

## 验收

- 三份依据的要求原子编号与批准清单完全一致。
- GB/T 27025 不出现 `3.1–3.9` 新增记录。
- G001/A015 不出现章级、父级标题和 A015 `2.1–2.8` 引用文件行。
- 每条新增要求都同时存在条款元数据和原文记录，且文本哈希匹配。
- CNAS-CL01 条款行仍为 0，但依据说明明确等同关系。
- 补录后再次运行预演，新增数为 0、已存在数为 62。
