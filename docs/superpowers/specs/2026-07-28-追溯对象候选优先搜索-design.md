# 追溯对象候选优先搜索设计

日期：2026-07-28

状态：方案已确认，待书面规格复核

## 1. 目标

将追溯复核页中一次加载数十至数百项的对象下拉框改成中文可搜索选择：用户可按编号或名称过滤，本文件治理候选优先排列并明确标识。

本功能只降低人工查找成本，不自动选择非候选对象、不自动确认关系、不自动保存。

## 2. 已确认边界

- 只增强 8021 治理试运行源码。
- 沿用现有 Bootstrap 页面，不引入第三方前端库和新后台接口。
- P0-2 候选定向预填、P0-3 单一对象保存门禁保持有效。
- 本轮不处理重复对象、版本取舍、状态清理和乱码，这些继续由 P1-2 治理。
- 不改写历史追溯关系，不迁移真实运行记录，不写入、部署或改动 8010。
- 纸质体系仍是唯一正式体系。

## 3. 方案比较与选择

### 方案 A：原生选择框加轻量搜索（采用）

在每个证明对象选择框上方增加搜索输入框，按当前选项的编号和名称即时过滤；候选对象加“★ 本文件候选”并排在其他对象之前。

优点：零依赖、改动小、保留原表单提交和后端门禁，适合当前试运行节奏。

### 方案 B：引入第三方组合框

使用 Choices.js、Tom Select 等组件提供一体化搜索、标签和键盘交互。

不采用原因：需要增加并维护前端依赖，当前收益不足以抵消装配和兼容成本。

### 方案 C：后台搜索接口

用户输入关键词后从后台分页搜索，只返回少量结果。

不采用原因：适合数万项数据；当前最大对象集约数百项，增加路由、权限和异步错误处理过重。

## 4. 数据处理

追溯复核详情继续一次性取得现有对象选项，并在服务层完成候选标记和排序：

1. 重新取得当前结构化文件的语义候选；
2. 将外部依据候选 ID 对应到外部条款；
3. 将手册候选 ID 对应到手册章节；
4. 将运行记录候选 ID 对应到记录模板；
5. 给命中对象增加 `is_candidate=true`；
6. 候选排在同类对象最前，其余对象保持原编号顺序。

不存在于当前全库选项中的候选不生成虚假选项，由现有候选治理提示继续说明。

## 5. 页面交互

每个用途驱动的证明对象区域包含：

- 对象名称标签；
- 搜索输入框，提示“输入编号或名称搜索”；
- 原生选择框；
- 动态结果说明，例如“找到 12 项，其中本文件候选 2 项”。

交互规则：

- 搜索忽略大小写和首尾空格；
- 空关键词恢复全部选项；
- 已选项即使与新关键词不匹配也保留显示，避免无提示丢失；
- 关系用途切换后，隐藏对象的搜索框和选择框同时禁用；
- 重新显示对象时保留用户已输入的关键词和选择；
- 没有匹配项时显示“未找到，请换用编号或名称”，不自动清空当前值；
- 三类候选选项显示“★ 本文件候选 · 编号 名称”；
- 其他对象仍可人工搜索和选择。

不使用占位文字代替字段标签，不增加动画，不改变保存按钮位置。

## 6. 默认关系用途

没有 P0-2 候选预填时，根据内容块类型给出初始用途：

- `record_requirement`：默认“主链：运行记录”；
- 其他内容块：保持现有“主链：落实手册”。

若 P0-2 已带入候选，以候选关系用途优先。默认值只影响初始显示，不代表人工确认。

## 7. 安全与兼容

- 表单字段名和值不变，保存仍走现有 `/planning/structures/links/save`。
- 搜索只改变浏览器中选项的可见性，不改变提交载荷。
- JavaScript 不可用时，原生选择框仍显示全部对象并可正常提交。
- 普通无候选入口、候选预填入口、辅助关系和仅提及路径均保持可用。
- 后端继续拒绝关系用途与证明对象不一致、多对象混装或缺少必选对象。

## 8. 验收标准

1. 外部条款、手册章节、程序文件、记录表格、岗位、运行模块和要素均可按编号或名称过滤。
2. 当前文件的外部依据、手册和记录候选在对应选择框顶部显示并带中文候选标识。
3. 搜索结果数和候选数以中文实时反馈；无结果时给出可恢复提示。
4. 切换关系用途后，隐藏搜索框与隐藏选择框均不参与提交。
5. `record_requirement` 内容块无候选参数进入时默认“主链：运行记录”。
6. P0-2 候选预填仍优先于内容块默认值，复核状态仍是“等待复核”。
7. 禁用 JavaScript 时原生选择框仍可用。
8. 页面操作前后有效追溯关系数量不变；专项测试、相关回归和 8021 浏览器验收通过。
