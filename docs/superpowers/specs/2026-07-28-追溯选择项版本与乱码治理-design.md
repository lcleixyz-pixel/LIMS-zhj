# 追溯选择项版本与乱码治理设计

日期：2026-07-28

状态：方案已确认，待书面规格复核

## 1. 目标

在不删除、不改写数据库对象的前提下，治理追溯复核页中的重复版本、历史对象和乱码条款，让默认选择范围聚焦当前文件候选，同时保留人工查看其他版本的路径。

## 2. 真实数据基线

8021 当前只读检查确认：

- 18 组手册章节标签完全重复，主要来自纸质现用第四版与电子治理候选并列；
- 2 组记录模板同编号同名称但治理版本或状态不同；
- 1 组程序文件同编号同标题但版本不同；
- 13 条外部条款标题含 Unicode 替换字符 `�`；
- 13 条乱码条款均已被历史追溯关系引用。

因此，本轮不能把“列表治理”误作“删除历史证据”。

## 3. 已确认边界

- 只增强 8021 治理试运行源码。
- 不删除、不软删除、不改名、不修补数据库中的原对象。
- 不自动迁移或换挂现有追溯关系。
- 不替机构确认纸质现用版本与电子候选的正式受控地位。
- P1-1 中文搜索、P0-2 候选预填和 P0-3 保存硬门禁保持有效。
- 不迁移真实运行记录，不写入、部署或改动 8010。
- 纸质体系仍是唯一正式体系。

## 4. 方案比较与选择

### 方案 A：非破坏式选择器治理（采用）

默认显示当前文件候选或解析出的当前版本；历史和其他版本折叠显示；乱码对象禁止新增选择，但已有关系继续展示。

优点：最快降低误选风险，不破坏来源和历史链。

### 方案 B：直接清洗数据库

修正乱码标题，并删除或合并重复版本。

不采用原因：13 条乱码均被历史关系引用，直接改写会改变已有证据；重复版本也尚未完成正式版本裁决。

### 方案 C：只增加版本标签

所有对象继续同时显示，只在文字后补版本和状态。

不采用原因：能解释重复，但不能降低默认选择范围和误选概率。

## 5. 选择项治理服务

在现有 `QmsTraceReviewOptionService` 中增加非破坏式治理结果：

```php
[
    'options' => [...],
    'summary' => [
        'clauses' => [
            'candidate' => 16,
            'current' => 16,
            'secondary' => 459,
            'excluded_invalid' => 13,
        ],
    ],
]
```

每个可选对象增加：

- `is_candidate`：是否属于当前文件语义候选；
- `is_secondary`：是否默认折叠到历史/其他版本；
- `version_label`：版本；
- `status`、`status_label`：机器状态与中文状态；
- `source_label`：来源文档或外部依据；
- `governance_label`：供页面显示的完整中文标签。

所有排序、折叠和隔离只作用于页面选项数组，不回写模型。

## 6. 当前与历史规则

### 6.1 有本文件候选的对象组

外部条款、手册章节和记录模板：

1. 当前文件候选默认显示并置顶；
2. 其他全库对象标为 `is_secondary=true`；
3. 用户点击“显示历史/其他版本”后才展开其他对象；
4. 候选对象仍按治理来源顺序排列。

这样既不把候选等同于人工确认，也不会让数百条全库对象持续挤占默认列表。

### 6.2 没有本文件候选的对象组

要素、程序文件、岗位和运行模块默认仍可见，避免辅助关系和职责关系无对象可选。

若同一业务标签存在多个程序版本：

1. 优先显示 `GOV-TRIAL/0.2`；
2. 其次显示非作废版本；
3. 其余重复版本标为历史/其他版本；
4. 所有版本都保留可展开入口，不自动删除。

## 7. 重复识别键

- 手册章节：来源文档 + 章节号 + 标题；跨来源的同号同标题不删除，只依候选与历史规则折叠。
- 程序文件：规范化文件编号 + 标题。
- 记录模板：`canonical_doc_number`；缺失时使用去除 `SIM-` 前缀后的文件编号。
- 外部条款：外部依据编号 + 条款号 + 标题。

重复识别只用于显示分组，不用于数据库合并。

## 8. 版本与状态标签

页面显示业务可读标签：

- `draft`：草稿；
- `trial_ready`：试运行就绪；
- `published`：已发布；
- `obsolete`：已作废；
- 无状态：状态待确认。

手册、程序和记录对象显示“编号 / 版本 / 状态 / 名称”；外部条款显示“依据编号 / 版本 / 状态 / 条款号 / 标题”。

## 9. 乱码隔离

对象标签只要包含 Unicode 替换字符 `�`：

1. 不进入新增追溯关系的可选列表；
2. 在页面显示隔离数量和原因；
3. 已有追溯关系继续按原值展示；
4. 不修改条款 ID、标题或历史关系；
5. 后续只有取得可靠来源文本并完成来源核验后，才能另行修正数据库。

页面提示采用：

> 已隔离 13 条疑似乱码外部条款，不能用于新增关系；已有历史关系未删除，请按来源核验后另行治理。

## 10. 页面交互

- 当前候选或当前解析版本默认可见；
- 存在折叠对象时显示“显示历史/其他版本（数量）”开关；
- 开关默认关闭，打开后搜索范围包含历史和其他版本；
- 关闭开关时，如果当前已经选择历史对象，该对象继续保留显示，不静默清空；
- 搜索结果提示同时说明当前范围，例如“找到 2 项；历史/其他版本已隐藏 18 项”；
- 乱码隔离提醒显示在新增关系表单内，不阻断查看现有关系。

JavaScript 不可用时，服务端仍按当前/历史顺序输出全部非乱码选项，原生选择框可正常使用；页面折叠只是渐进增强。

## 11. 错误处理与安全

- 候选服务不可用：不猜测当前候选，回退为带版本状态标签的全库选项。
- 版本字段缺失：显示“版本待确认”，不据此删除或隐藏唯一对象。
- 当前候选本身含乱码：隔离该候选并显示警告，不提供带入或保存捷径。
- 历史对象被已填入表单：即使折叠开关关闭也保留当前已选值。
- 保存仍由 P0-3 校验关系用途和唯一对象，页面治理不能绕过后端门禁。

## 12. 验收标准

1. CX-03-02 手册、外部条款和记录选择器默认只显示本文件候选。
2. 点击“显示历史/其他版本”后，可搜索全库非乱码对象。
3. 手册、程序和记录选项显示版本、状态及来源，重复标签可人工区分。
4. `6.4 设备` 默认只显示候选来源版本，历史纸质来源可展开查看。
5. 两组重复记录模板能区分 `GOV-TRIAL/0.1` 与 `GOV-TRIAL/0.2` 及状态。
6. 同编号程序文件能区分 `A/2` 与 `GOV-TRIAL/0.2`。
7. 13 条含 `�` 的条款不再出现在新增选择器，并显示隔离提醒。
8. 含乱码条款的已有历史关系仍存在且可查看。
9. 搜索、候选预填、用途切换和保存硬门禁相关回归保持通过。
10. 浏览器验收前后有效追溯关系数量不变，未写入 8010。
