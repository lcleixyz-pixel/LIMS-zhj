# RBAC 与系统失效应急修复设计

## 目标

修复控制器名称归一化不一致导致的角色写权限错误，并补齐 `CNAS-CL01 7.11.3 e` 所需的系统失效应急响应制度内容。

## 范围

### RBAC

- `RbacService::canWrite()` 的限制名单与 staff 写权限名单必须使用和 `canAccess()` 相同的控制器归一化规则。
- staff 应能访问并填写记录实例。
- auditor、department_head、staff 不得新增、编辑或删除体系文件、文件分类和文件模板。
- admin、quality_manager 保持体系文件写权限。
- 不调整现有角色的模块读取权限，不改变 quality_manager 管理用户的现行组织决定。

### 7.11.3 e

- 在 `jewelry-qms/docs/QMS_OPERATIONS_RUNBOOK.md` 增加“系统失效应急响应与恢复”章节。
- 内容覆盖：失效判定与报告、停止高风险操作、纸面或离线替代、数据保护、故障恢复、恢复后验证、临时记录补录、原因分析和纠正措施记录。
- 明确应急制度文本不等于已经完成应急演练；没有演练证据时不得把状态写成“完整验证通过”。
- 同步更新计算机化系统验证方案，使其准确区分“制度条款已补”和“演练证据待形成”。

## 实现方式

1. 先增加最小权限回归测试，并在当前实现上观察预期失败。
2. 提取或复用统一的控制器名单匹配逻辑，避免对白名单手工维护两种命名形式。
3. 运行权限单元/烟雾测试和真实 HTTP 角色页面回归。
4. 补写运行手册应急章节，并更新验证方案的条款映射、待补证据和版本记录。
5. 运行文档关键词检查、PHP 语法检查、相关测试及 `git diff --check`。

## 验收标准

- staff 的 `record_form_instance/create` 不再被 RBAC 重定向到仪表盘。
- auditor 对 `document/add`、`doc_category/add`、`doc_template/add` 仍被拒绝。
- quality_manager 对上述体系文件入口仍可访问。
- 自动化测试能覆盖带下划线配置名与无下划线运行时控制器名的匹配。
- RUNBOOK 含可执行的系统失效应急流程和记录要求。
- 验证方案不再写“应急条款缺失”，但明确应急演练仍待执行。

## 安全边界

- 不写生产数据库，不提交真实业务记录。
- 不部署、不推送远端。
- HTTP 回归只执行登录和 GET 页面访问，不提交写操作。
