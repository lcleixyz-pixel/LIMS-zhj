# QMS 轻量双层收口设计

日期：2026-08-24  
选定方案：A「轻量双层」  
适用环境：8021 治理试运行环境

## 1. 目标

把已经完成的路径 B 从“页面内部变简单”进一步收口为“普通员工从进入系统开始就简单”：员工只面对“我的工作、查文件、查记录”，质量治理人员从单独入口进入完整治理功能。

本轮解决四个已经确认的问题：

1. 日常入口与后台管理入口重复，用户不知道该点哪个。
2. “纸质执行”与“已发布登记”等表达同时出现，容易误解为电子正式发布。
3. 普通员工会看到 `SIM-GOV03`、`GOV-TRIAL/0.3` 等内部试装标识。
4. 阅读页三栏同时展开导致正文偏窄，链路信息抢占阅读空间。

## 2. 明确不做

- 不改变任何文件、表单、记录、链路或审批数据。
- 不修改 65 份来源 Word，也不改变其 SHA-256。
- 不自动确认待复核链路，不补造表格、岗位、培训或运行证据。
- 不触碰 8010，不增加“转正式”按钮。
- 不引入新的在线 Office、编辑器、前端框架或 UI 依赖。
- 不把技术自测等同于真实员工易用性验收。

## 3. 双层入口

### 3.1 日常工作层

所有可登录用户默认进入日常工作层。顶部只保留：

- `我的工作`
- `查文件`
- `查记录`
- 当前用户与退出入口

具有质量治理权限的用户额外看到一个明确的 `进入质量管理` 按钮。原有“工作台、文件管理、记录管理、审核评审、质量改进、资源管理、体系策划、系统设置”等后台入口不在日常工作层展开。

日常工作层不根据用户身份推测职责；只按现有权限决定是否显示质量管理入口。

### 3.2 质量管理层

质量治理人员点击 `进入质量管理` 后进入现有治理功能集合。质量管理层保留完整业务入口，但增加明显的 `返回日常工作`，避免用户找不到出口。

页面所在路由决定当前层级，不新增数据库字段，不在账号上保存人工模式开关：

- `/quality-workbench`、`/document/index`、`/document/read` 和普通记录入口使用日常工作层。
- 评审项目、文件信息、完整链路矩阵以及既有后台模块使用质量管理层。

没有治理权限的用户即使手工输入治理地址，仍由现有权限服务拒绝访问；不能仅靠隐藏菜单实现权限控制。

## 4. 状态文案

### 4.1 唯一边界提示

日常工作层只显示一条统一提示：

> 纸质文件为正式依据 · 系统用于快速查阅与治理核对

不再同时重复“治理试运行模拟环境”“治理中 · 纸质执行”等多条含义相近的横幅。

### 4.2 文件状态

普通员工页面统一显示 `当前治理阅读版`，不显示：

- `published`
- `试运行环境已发布登记`
- `8021 当前阅读版`
- `SIM-GOV03-` 前缀
- `GOV-TRIAL/0.3`

文件编号优先使用员工熟悉的业务编号，例如 `CX-08`。完整模拟编号、内部版本、结构化状态和数据库状态仍保留在质量人员的“文件信息”页面，数据本身不修改。

已作废文件继续明确显示 `已作废 · 仅供追溯`，且不进入默认文件列表。

## 5. 文件库

文件库继续保留一个主搜索框和快速分类。普通员工的每条文件只突出：

1. 点击名称或 `阅读正文` 进入阅读页。
2. `来源 Word` 下载只读来源快照。
3. `相关信息` 进入当前文件的简明链路入口。

`文件信息`、历史版本和完整链路矩阵只在质量管理层提供，不与日常动作并排争夺注意力。

编号或名称精确命中继续优先于正文命中。没有结果时显示可执行建议，例如“检查编号，或改用文件名称中的关键词”，不展示数据库术语。

## 6. 正文阅读页

### 6.1 默认布局

桌面端默认使用两栏：

- 左侧：章节目录。
- 中间：连续正文。

原右侧文件链路改为正文下方的可展开区域 `相关依据、表格和责任岗位`。默认收起并显示关系数量；用户展开后按“依据什么、落实到哪些文件、需要哪些表格、谁负责、在哪里办理”分组展示。

已确认与待复核关系继续使用不同文案和视觉标记。关系为空时显示“当前未建立直接关系，需由质量人员复核”，不得显示为已闭合。

### 6.2 阅读信息层级

页首按以下顺序显示：

1. 员工熟悉的文件编号与名称。
2. `当前治理阅读版`。
3. `下载来源 Word（用 WPS 打开）`。
4. `打印阅读稿（非受控）`。

完整模拟编号、内部版本和结构化信息移入质量层的文件信息页面。

### 6.3 响应式与无脚本可用

- 宽屏：目录与正文两栏。
- 窄屏：目录折叠到正文上方，正文占满宽度。
- 链路使用浏览器原生可展开结构，JavaScript 不可用时仍能展开阅读。
- 键盘用户可以定位搜索框、章节、Word 下载和链路展开控件，并有清晰焦点样式。
- 打印时隐藏导航、搜索和链路交互，在每页保留“阅读稿（非受控）”提示。

## 7. 权限与数据流

本轮只调整呈现层与已有权限判断：

`当前用户 → 现有 ActionAuthorizationService → 选择日常/治理导航 → 原控制器与服务读取原数据`

- 不新增表，不执行 migration。
- 不修改 `documents.status` 或候选文件的 `published` 数据值；普通页面只做适合当前治理阶段的文案转换。
- 来源 Word 继续经过固定根目录、扩展名、存在性和 SHA-256 校验后下载。
- 链路继续来自现有结构化块和关系服务，不增加推测型关系。

## 8. 验证

### 8.1 自动测试

- 日常导航只出现“我的工作、查文件、查记录”；质量入口按权限出现。
- 日常页面不出现 `SIM-GOV03`、`GOV-TRIAL/0.3`、`published` 和“已发布登记”。
- 质量管理页面保留后台入口，并提供“返回日常工作”。
- 正文页默认为目录加正文两栏，链路为可展开区域。
- 已确认、待复核和空链路三种状态均有明确文案。
- 现有来源 Word、安全、权限、工作台和文件阅读回归测试继续通过。

### 8.2 浏览器抽验

抽验“我的工作”、文件库、CX-08 正文和文件链路评审详情：

- 日常入口无重复导航。
- 纸质正式边界只出现一次且表述一致。
- CX-08 正文宽度明显增加，链路可展开和收起。
- 来源 Word 下载仍可用。
- 治理人员可以从日常层进入质量层并返回。

### 8.3 后续用户验收

代码和浏览器自测完成后，仍需 3 名非质量管理员进行无讲解任务测试。达到 90% 首次完成率和 60 秒内看到目标正文后，才能认为易用性目标得到用户证据支持。

## 9. 成功标准

- 普通员工从登录后的任意日常页面只看到 3 个主要工作入口。
- 文件名称到正文不超过一次点击。
- 普通页面不存在互相矛盾的“纸质执行/电子发布”表达。
- 普通页面不暴露内部试装编号和状态码。
- 正文是阅读页视觉主体；链路只有在用户需要时展开。
- 既有数据、8010、来源 Word、真实记录和权限边界保持不变。
