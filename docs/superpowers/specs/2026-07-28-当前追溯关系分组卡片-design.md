# 当前追溯关系分组卡片设计

日期：2026-07-28

状态：方案 A 已确认，待书面规格复核

## 1. 目标

把追溯复核页下方“当前追溯关系”从十列横向宽表改为中文分组卡片，让熟悉纸质体系但不熟悉软件的人员先看懂“这条关系证明什么”，再决定确认、调整、拆分或删除。

本轮只改变读取后的页面组织与显示，不批量改写追溯关系。

## 2. 已确认方案

按业务用途分组：

1. 主链证据；
2. 职责；
3. 运行入口；
4. 辅助关系。

历史混装关系不塞入普通分组，单独放在最上方“需优先处理”区域，并保留拆分预览。

## 3. 分组规则

| 页面分组 | 关系类型 | 中文说明 |
|---|---|---|
| 主链证据 | `basis`、`implements`、`requires_record` | 外部依据、手册落实和运行记录组成文件设计主链 |
| 职责 | `responsible` | 说明由哪个岗位承担职责 |
| 运行入口 | `renders_to` | 说明要求在系统哪个模块执行或留痕 |
| 辅助关系 | `supporting`、`mentions` 及未知兼容类型 | 提供辅助证明或仅在正文中提及 |

`relation_policy.is_mixed=true` 的关系进入“需优先处理”，不再重复出现在上述四组中。

分组只用于页面呈现，不改变数据库中的 `relation_type`。

## 4. 卡片内容

每条关系卡片按阅读顺序显示：

1. 关系用途，如“主链：运行记录”；
2. 治理状态，如“已确认主链、等待复核、疑似错挂、辅助关系”；
3. 实际关联对象，只显示有值的对象，不再展示七个空列；
4. 复核说明；
5. “确认或调整关系”及“删除关系”操作。

对象名称使用中文标签：

- 外部条款；
- 手册章节；
- 程序文件；
- 记录表格；
- 岗位；
- 运行模块；
- 要素。

同一历史关系包含多个对象时，卡片逐项列出，避免横向找列。

## 5. 需优先处理区域

历史混装关系显示：

- “历史混装，需拆分”警示；
- 当前包含的对象数量；
- 对象清单；
- 只读拆分预览；
- “请在上方逐条新增，核对后再删除旧关系”的中文指引；
- 原删除入口和必填删除说明。

系统不自动拆分、不自动保存、不自动删除旧关系。

## 6. 操作能力保留

普通关系继续保留：

- 调整关系用途；
- 调整复核状态；
- 填写复核依据；
- 对手册错挂进行移除或改选；
- 保存复核结论；
- 填写说明后删除。

所有表单仍提交现有路由和字段，不新增写接口，不放宽 P0-3 保存硬门禁。

## 7. 页面布局

- “需优先处理”占整行并置顶。
- 四个业务分组按有内容才显示。
- 桌面端每行两列，窄屏自动单列。
- 分组标题同时显示数量，例如“主链证据 3 条”。
- 每组显示一句纸质体系语言说明。
- 没有任何关系时，显示“暂无追溯关系，请在上方选择对象后保存”。
- 不依赖 JavaScript完成分组和基本操作。

## 8. 服务边界

新增纯展示服务，将现有 `links` 转为：

```php
[
    'priority' => [...],
    'groups' => [
        [
            'key' => 'primary',
            'title' => '主链证据',
            'description' => '...',
            'links' => [...],
        ],
    ],
    'total' => 5,
]
```

服务负责：

- 稳定分组；
- 中文关系用途；
- 中文治理状态；
- 提取非空关联对象。

模板只负责渲染和保留现有表单，避免继续堆叠关系判断。

## 9. 错误与兼容

- 未知关系类型归入辅助关系，并显示“待确认关系”。
- 对象名称缺失但 ID 存在时显示“对象信息待补充”，不隐藏关系。
- 治理状态缺失时显示“状态待确认”。
- 历史混装优先级高于普通关系分组。
- 旧关系、乱码条款历史引用和软删除规则不受影响。

## 10. 测试与验收

自动化覆盖：

1. 七类关系进入正确业务分组；
2. 历史混装只进入优先处理区；
3. 未知关系类型安全进入辅助关系；
4. 只输出有值的关联对象；
5. 现有确认、调整、拆分和删除表单字段及路由完整保留；
6. 读取前后有效追溯关系数量不变；
7. P0-1 至 P1-2 相关回归继续通过。

8021 浏览器验收至少覆盖：

- 只有一条混装关系的内容块；
- 同时具有主链、职责或辅助关系的内容块；
- 卡片在窄屏下无横向宽表；
- 确认/调整详情可以展开；
- 不提交表单，验收前后有效关系保持 3182。

## 11. 非目标

- 不修改关系数据或复核结论；
- 不自动治理历史混装；
- 不新增批量操作；
- 不重做上方新增关系表单；
- 不迁移真实运行记录；
- 不写入、部署或改动 8010；
- 不改变纸质体系作为唯一正式体系的边界。
