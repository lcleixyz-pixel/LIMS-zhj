# 追溯候选定向预填设计

日期：2026-07-28

状态：已确认，进入实施

## 1. 目标

让文件治理工作台中已经识别出的外部依据、手册章节和运行记录候选，各自进入合适的程序内容块，并在追溯复核页预填关系用途、证明对象和推荐理由。

预填只减少重复查找，不代替人工判断，不自动保存，也不把候选计入闭环。

## 2. 已确认边界

- 只增强 8021 治理试运行源码。
- 不修改候选来源和语义判断口径。
- 不自动新建、拆分、删除或确认追溯关系。
- 不改变 P0-3 的保存端单一对象硬门禁。
- 不迁移真实运行记录，不写入、部署或改动 8010。
- 纸质体系仍是唯一正式体系。

## 3. 方案比较与选择

### 方案 A：候选逐条定向预填（采用）

每条候选包含建议内容块、关系用途、目标对象和推荐理由，点击后进入对应内容块的现有复核表单。

优点：改动轻、路径短、仍由人工保存，符合当前最快试运行目标。

### 方案 B：进入复核页后再按候选类型切换

保留一个通用入口，在复核页增加外部依据、手册、记录三个候选页签。

缺点：仍需用户先判断应在哪个内容块办理，不能解决错进记录块的问题。

### 方案 C：建立跨内容块治理向导

用多步骤向导批量完成外部依据、手册和记录关系。

缺点：工程量和状态管理明显更重，不符合当前“先把治理体系落进系统试运行”的节奏。

## 4. 定向规则

候选路由按内容块类型确定，并在同类型内选择排序最靠前的内容块。

| 候选 | 关系用途 | 证明对象 | 内容块优先级 |
|---|---|---|---|
| 外部依据 | `basis` | `clause_id` | 目的 → 控制要求 → 工作程序 → 其他 |
| 手册章节 | `implements` | `manual_section_id` | 工作程序 → 控制要求 → 目的 → 其他 |
| 运行记录 | `requires_record` | `record_form_template_id` | 记录要求 → 工作程序 → 其他 |

没有可用对象 ID 或可进入内容块时，只显示原因，不生成可点击的带入入口。

## 5. 数据结构

候选服务原有三组数组保持不变，在工作台组装阶段为每条候选增加：

- `candidate_kind`：候选类型；
- `relation_type`、`relation_label`：建议关系用途；
- `target_field`、`target_id`：证明对象字段和值；
- `target_block_id`、`target_block_title`、`target_block_type`：建议办理内容块；
- `recommendation_reason`：业务可读推荐理由；
- `review_url`：仅包含候选类型和候选 ID 的定向复核地址；
- `routable`、`routing_issue`：能否带入及不能带入的原因。

候选仍保留 `review_required=true`，不得混入已确认主链。

## 6. 复核页行为

复核页只接受当前文件治理候选中的对象：

1. 根据 `block_id` 读取当前结构化文件；
2. 重新取得该文件的候选和全部内容块；
3. 重新执行定向规则；
4. 仅当候选 ID、候选类型和目标内容块同时匹配时生成预填；
5. 预填关系用途、证明对象和推荐理由；
6. 复核状态固定先显示“等待复核”；
7. 页面明确提示“尚未保存，请人工核对”。

无效、过期或被人为改写的候选参数不产生预填，并显示中文原因；普通无参数进入复核页的旧路径保持不变。

## 7. 中文交互

工作台每条候选显示：

- 候选编号与名称；
- “建议办理到：内容块标题”；
- “建议用途：主链：外部依据 / 落实手册 / 运行记录”；
- “带入此候选”按钮；
- 不可带入时的具体原因。

复核页顶部显示一张简洁提示：

- 来源：治理装配蓝图 / 本地条款映射；
- 已带入候选；
- 建议内容块；
- 建议用途；
- 推荐理由；
- “系统尚未保存”的边界提醒。

不增加动画，不引入新前端依赖，沿用现有 Bootstrap 样式和响应式布局。

## 8. 错误处理

- 候选不属于当前文件：不预填，提示“该候选已变化，请返回治理工作台重新进入”。
- 候选不属于当前内容块：不预填，提示“建议内容块已变化，请返回治理工作台重新进入”。
- 候选对象尚未入库：工作台禁用带入入口并说明原因。
- 候选服务异常：保留现有候选不可用提示，不影响普通人工复核。
- 保存阶段继续由 P0-3 后端门禁校验，预填不能绕过门禁。

## 9. 验收标准

1. 外部依据、手册章节、运行记录分别进入符合规则的内容块。
2. 复核页正确预选关系用途和唯一证明对象。
3. 推荐理由可见、可修改，复核状态仍为“等待复核”。
4. 页面明确说明预填尚未保存。
5. 无参数旧入口仍可正常使用。
6. 伪造或过期候选参数不能生成有效预填。
7. 打开工作台和复核页前后，活跃追溯关系数量不变。
8. 相关静态、服务和 8021 运行回归全部通过。
