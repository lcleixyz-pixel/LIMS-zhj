# 文件治理工作台 v0.1 设计

## 1. 目标

在现有 `jewelry-qms` 中增加一个文件治理工作台，让用户用一个页面看清某份体系文件的完整设计链：

> 外部依据 → 手册条款 → 程序落实方法 → 记录表格或系统记录 → 试运行与签批状态。

v0.1 以 `XZTC/CX-03-02-2022 标准物质管理程序` 为首个样板。工作台只聚合、解释和导航，不在页面内重复实现修改、追溯复核、换版和签批。

## 2. 已确认方案

采用“证据链总览 + 现有受控页面办理”方案。

- 工作台负责显示当前结论、证据链完整度、阻断项和下一步。
- 用户点击动作后，进入现有结构化文件、追溯复核、记录模板、文件修订或文件签批页面。
- 用户完成办理后返回工作台，系统重新读取数据并计算状态。
- 不提供“手工勾选完成”能力。

没有采用单纯的左侧材料导航，因为它不能让用户立即看出断链位置。没有采用五步治理向导，因为它容易把真实冲突压缩成形式化打勾。

## 3. 运行边界

- 纸质体系仍是唯一正式体系。
- 8021 是治理试运行沙箱，不作为正式 CMA/CNAS 评审证据。
- 不写 8010，不迁移正式运行记录。
- 不自动判定体系合格。
- 不自动关闭冲突，不代替人工复核。
- 不改变现有文件、追溯、换版和签批权限。
- 不引入新前端框架，沿用现有 ThinkPHP 8、Bootstrap 和页面布局。
- 不重构无关模块。

## 4. 页面信息结构

### 4.1 页头

显示：

- 文件编号和标题；
- 结构化版本；
- 试运行边界提示；
- 返回文件列表；
- “处理下一项”主动作。

### 4.2 当前结论

用业务语言显示：

- 当前能否继续试运行；
- 当前能否提交签批；
- 阻断提交的直接原因；
- 最先应处理的具体对象。

文案遵循“动作 + 结果 + 下一步”，不能只显示状态码。

### 4.3 系统设计链

横向显示 4 个环节：

1. 外部依据；
2. 手册条款；
3. 程序落实方法；
4. 运行证据。

每个环节显示：

- 已找到的有效对象数量；
- 完整、待核对、断链或材料缺失；
- 查看证据明细的入口。

程序落实方法即当前结构化程序文件及其内容块。运行证据包括记录表格和已关联的系统业务模块。

### 4.4 文件内容与审查材料

提供只读入口：

- 连续正文；
- 修订对照；
- 冲突审查；
- 变更记录。

材料缺失时显示“材料尚未生成”和可执行的返回路径，不显示空白按钮。

### 4.5 下一步动作

最多显示 3 项，按以下优先级排序：

1. 补齐外部依据、手册或程序追溯断链；
2. 核对记录表格字段是否足以证明程序运行；
3. 处理本文件的阻断冲突；
4. 处理体系级提醒；
5. 修订或复制为新版本；
6. 提交、继续或完成签批；
7. 查看已完成证据。

按钮只跳转到现有受控入口。无权办理时仍可看见应做事项，但按钮显示无权限原因。

## 5. 数据设计

新增只读聚合服务 `QmsFileGovernanceWorkbenchService`。服务不创建表、不写数据库。

### 5.1 文件基线

调用 `QmsDocumentStructureService::structuredDocumentDetail()` 获取：

- 结构化文件；
- 关联受控文件；
- 内容块；
- 块级追溯；
- 变更记录；
- 源文件和渲染存档。

不存在或已软删除的结构化文件返回空结果，由 Controller 转为 404。

### 5.2 证据链

遍历当前文件全部有效内容块及其追溯关系，按对象 ID 去重：

- 外部依据：外部条款、外部证据来源；
- 手册条款：质量手册章节；
- 程序落实：当前程序和内容块；
- 运行证据：记录模板、业务模块；
- 辅助信息：责任岗位和体系要素。

数量必须来自真实查询，禁止写死 CX-03-02 的演示数字。

### 5.3 记录支撑充分性

复用 `QmsDocumentStructureService::recordRequirementSchemaCoverage()`，按当前结构化文件 ID 或受控文件 ID 过滤。

每条记录要求归入以下状态之一：

- `covered`：已关联记录模板，且要求字段可识别；
- `needs_review`：已关联模板，但字段或业务含义仍需人工确认；
- `missing`：程序要求记录，但没有有效记录模板；
- `not_applicable`：有明确不适用依据。

工作台只显示已有检查结果和复核入口，不在 v0.1 中新增字段编辑器。

### 5.4 冲突

冲突必须分两层展示：

- 本文件阻断：目标文件或其补丁、记录表号、职责、期限等存在直接冲突；
- 体系级提醒：其他文件造成的全局阻断或非阻断治理提示。

不能直接把 `currentPackageBlockingCount()` 的全局数量当作当前文件的阻断数量。页面必须分别说明，避免用户误以为当前文件本身存在所有问题。

连续正文、修订对照和冲突材料入口复用 `GovernedTrialResolvedDocumentService::resolvedArtifactLinks()`。

### 5.5 试运行和签批

结构化文件有 `document_id` 时，读取关联 `Document`：

- 当前文件状态；
- 版本世系；
- 文件详情入口；
- 修订或复制为新版本入口；
- `ApprovalService::documentWorkflowStatus()` 返回的当前签批阶段。

签批办理仍进入 `/document/view?id=<document_id>`。工作台不加载 DocuSeal 嵌入页，不直接处理签署。

### 5.6 状态计算

服务返回统一的页面 ViewModel，至少包含：

```php
[
    'document' => [],
    'boundary_notice' => '',
    'summary' => [
        'level' => 'ready|warning|blocked|completed',
        'message' => '',
        'next_step' => '',
        'completed_checks' => 0,
        'total_checks' => 0,
    ],
    'chain' => [
        'external_sources' => [],
        'manual_sections' => [],
        'procedure_blocks' => [],
        'record_evidence' => [],
    ],
    'artifacts' => [],
    'conflicts' => [
        'document_blockers' => [],
        'system_notices' => [],
    ],
    'signing' => [],
    'actions' => [],
]
```

`completed_checks` 只统计有明确数据依据的检查项。没有数据的检查项保持“待确认”，不得计为完成。

## 6. 路由与权限

新增只读路由：

```text
GET /planning/structures/workbench?id=<structured_document_id>
```

在 `PlanningStructure` Controller 增加 `workbench()` 方法，并新增模板：

```text
app/view/planning_structure/workbench.html
```

入口位置：

- 结构化文件列表增加“治理工作台”；
- 结构化文件详情增加“治理工作台”；
- 仅对质量手册、程序文件和作业指导书显示入口。

沿用 `planning/structures` 的登录与角色访问边界。工作台本身只读；跳转后的写操作继续由目标页面执行原有授权检查。

## 7. 视觉与交互

本页属于现有受监管后台系统的增量页面，不做营销式改版。

- 保留现有顶部导航、字体、Bootstrap 组件和响应式断点。
- 主色沿用系统绿色，黄色仅表示待确认，红色仅表示阻断。
- 卡片圆角、按钮尺寸和表格密度与现有体系文件页面一致。
- 主按钮每次只强调一个“处理下一项”。
- 禁用按钮必须同时显示不可用原因。
- 空状态提供返回入口或下一步，不显示无文字提示框。
- 窄屏下证据链改为纵向顺序，箭头改为向下，动作区排在正文材料之前。
- 所有状态不能只靠颜色表达，必须配文字。

## 8. 错误处理

- 文件不存在：404，显示“结构化文件不存在”，提供返回文件列表入口。
- 关联受控文件缺失：保留结构化文件页面，显示“尚未关联受控文件”，隐藏签批动作。
- 追溯为空：显示“待补链”，不显示“0 项已完成”。
- 解析材料缺失：显示缺失的材料名称，不阻断其他证据展示。
- 签批服务异常：显示“签批状态暂时无法读取”，保留文件详情入口，不伪造签批阶段。
- 历史快照指向已重建内容块：只显示历史追溯提示，关闭现行编辑入口。
- 用户无办理权限：显示目标岗位或联系质量负责人的提示，不展示失效链接。
- 单个区块查询失败：页面整体进入错误提示，不用部分成功数据形成“可提交”结论。

## 9. 测试设计

### 9.1 服务测试

- CX-03-02 能生成完整 ViewModel；
- 证据对象按 ID 去重；
- 数量来自输入数据而非固定值；
- 记录支撑状态正确区分 `covered`、`needs_review` 和 `missing`；
- 本文件阻断与体系级提醒分开；
- 没有关联受控文件时不生成签批动作；
- 下一步优先级符合第 4.5 节；
- 已废止文件不生成提交或发布动作。

### 9.2 页面与路由测试

- 新路由存在；
- 列表和详情页出现“治理工作台”入口；
- 页面显示纸质体系边界；
- 页面显示当前结论、4 段证据链、材料入口和下一步；
- 断链、空状态、禁用原因和 404 文案可见；
- 窄屏布局有明确的响应式规则；
- 页面没有新增数据库写入表单。

- 核对文件详情和签批状态能回链；

## 10. 完成判据

- 用户从结构化文件列表进入 CX-03-02 工作台后，可在一页看清完整证据链。
- 页面能明确指出断链、字段待核对、文件阻断和体系级提醒。
- 页面给出唯一优先的下一步，并跳转到现有受控办理页。
- 办理完成后返回工作台，状态由真实数据重新计算。
- 页面没有手工完成开关，没有新增写库接口。
- 自动测试通过，8021 真实数据验证通过。
- 8010、正式纸质体系和现用文件没有本任务写入。
