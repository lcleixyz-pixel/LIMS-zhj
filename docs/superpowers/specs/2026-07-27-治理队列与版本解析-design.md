# 治理队列与版本解析设计

## 1. 目标

在现有 8021 文件治理链中增加一个轻量、只读的 37 份程序治理队列，并让同一文件编号的电子治理候选、纸质现用来源和历史版本不再混淆。

本次只实现：

1. 统一当前电子治理候选的解析规则；
2. 展示 37 份 `GOV-TRIAL/0.2` 程序的语义状态和下一步；
3. 从单份治理工作台直接进入下一份未完成文件。

不实现工单、分派、工时、批量确认或自动保存追溯关系。

## 2. 已确认边界

- 纸质体系仍是唯一正式体系。
- 8021 仅用于治理试运行，不形成正式评审证据。
- 不写 8010。
- 队列及下一份计算只执行读取，不修改数据库。
- 不修改 Claude 正在修订的文件正文。
- 沿用 ThinkPHP 8、Bootstrap 5 和现有页面布局，不引入新前端框架。

## 3. 当前版本规则

规范文件编号是逻辑文件身份。当前电子治理候选必须同时满足：

- 结构化文件角色为 `procedure`；
- 版本等于 `GovernedTrialResolvedManifestService::VERSION`；
- 文件编号以 `SIM-GOV02-XZTC/CX-` 开头；
- 未软删除。

同一规范文件编号：

- 恰有一个候选：标记为“当前电子治理候选”；
- 其他受控文件版本：标记为“纸质现用来源”；
- 出现多个电子候选：标记“候选冲突”，不得静默选择任意一条；
- 与本批次无关的文件：保持原有展示。

文件列表、治理队列和后续导航共用这一解析服务。

## 4. 治理队列

新增只读页面：

```text
GET /planning/structures/governance-queue
```

队列只读取当前 37 份程序。顶部显示：

- 总数；
- 已对齐；
- 疑似错挂；
- 主链缺失；
- 版本冲突。

支持：

- 按语义状态筛选；
- 按文件编号或标题搜索；
- 每行一个主操作“继续治理”。

每行显示：

- 文件编号和标题；
- 当前候选版本；
- 文件状态；
- 语义状态；
- 缺失链条；
- 记录字段覆盖状态；
- 明确证据项数；
- 最近更新时间；
- 下一步。

已废止文件保留显示，但不进入“下一份未完成”计算。

## 5. 下一份未完成

新增只读跳转：

```text
GET /planning/structures/governance-next?current_id=<structured_document_id>
```

计算规则：

1. 使用治理队列的稳定文件编号顺序；
2. 从当前文件之后寻找 `blocked`、`warning` 或 `ready` 项；
3. 跳过已废止文件、候选冲突和当前文件；
4. 到队尾后从队首继续寻找；
5. 没有未完成文件时返回队列并给出明确提示。

单份工作台页头提供：

- 返回治理队列；
- 下一份未完成；
- 查看结构化文件。

## 6. 页面设计

这是受监管实验室后台的增量改造：

- 设计变化 3；
- 动效 2；
- 信息密度 6；
- 保留现有 Bootstrap 视觉语言；
- 绿色表示可继续，黄色表示待复核，红色表示阻断；
- 状态始终同时显示文字，不能只靠颜色；
- 搜索框有可见标签；
- 空结果说明如何清除筛选；
- 桌面表格按钮不换行，窄屏允许横向滚动。

## 7. 错误与异常

- 没有候选文件：显示空状态，不伪造 0% 完成率。
- 候选重复：显示“候选冲突”，禁用继续治理。
- 单份工作台读取失败：该行显示“状态暂不可用”，不把它计为已对齐。
- 下一份不存在：返回队列并提示“当前没有其他未完成文件”。
- 非本批次文件调用下一份：从队列第一份未完成开始。

## 8. 验收标准

1. 8021 只读队列返回 37 份程序。
2. 当前数据统计为已对齐 4、疑似错挂 14、主链缺失 19。
3. `SIM-GOV02-XZTC/CX-03-02-2022` 的 `GOV-TRIAL/0.2` 标为电子治理候选，`A/2` 标为纸质现用来源。
4. 队列支持状态筛选和关键词搜索。
5. 工作台能够进入下一份未完成。
6. 读取前后结构化文档、追溯关系和体系文件计数不变。
7. 既有语义防错和文件治理工作台测试继续通过。
