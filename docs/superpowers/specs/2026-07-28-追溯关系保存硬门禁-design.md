# 追溯关系保存硬门禁设计

## 1. 目标

在 8021 人工复核追溯关系时，执行“一个关系用途、一个主要对象”规则，防止继续生成手册、条款、记录和岗位混装在同一行的关系。

本设计只约束人工保存入口 `QmsDocumentStructureService::upsertBlockTraceLink()`，不改变结构化装配和历史种子生成逻辑，不批量改写既有关系。

## 2. 关系契约

| 关系用途 | 必选主要对象 | 可选辅助对象 | 禁止对象 |
|---|---|---|---|
| `basis` 外部依据 | 外部条款 | 要素 | 手册、程序、记录、岗位、运行模块 |
| `implements` 落实手册 | 手册章节 | 无 | 其他全部对象 |
| `requires_record` 运行记录 | 记录表格 | 无 | 其他全部对象 |
| `responsible` 职责 | 岗位 | 无 | 其他全部对象 |
| `renders_to` 运行入口 | 运行模块 | 无 | 其他全部对象 |
| `mentions` 仅提及 | 七类对象中恰好一个 | 无 | 第二个及后续对象 |
| `supporting` 辅助关系 | 七类对象中恰好一个 | 无 | 第二个及后续对象 |

七类对象为：要素、外部条款、手册章节、程序文件、记录表格、岗位和运行模块。

## 3. 后端门禁

新增独立策略服务 `QmsTraceRelationPolicyService`：

1. 提供关系用途、中文名称、必选对象和允许对象定义；
2. 校验人工提交的标准化 payload；
3. 非法组合抛出业务可读的中文异常；
4. 分析既有关系是否混装，并生成只读拆分预览。

`upsertBlockTraceLink()` 在任何数据库保存前执行策略校验。校验失败时：

- 不新增或更新追溯关系；
- 不生成变更日志；
- 返回例如“主链：落实手册只能选择手册章节，请清除记录表格后再保存”的中文提示。

## 4. 页面交互

新增关系表单采用渐进式显示：

- 先选择“关系用途”；
- `basis` 显示外部条款和可选要素；
- `implements`、`requires_record`、`responsible`、`renders_to` 分别只显示一个适用选择器；
- `mentions`、`supporting` 先选择“对象类别”，再显示对应选择器；
- 隐藏字段同时禁用，避免浏览器继续提交旧值；
- 表单上方用一句中文说明当前用途能证明什么。

现有关系区域：

- 正常单对象关系保留“确认或调整关系”；
- 历史混装关系显示醒目的“历史混装，需拆分”提示；
- 展示拆分预览，例如“外部条款 → 主链：外部依据”“记录表格 → 主链：运行记录”；
- 不提供自动拆分按钮，不静默改写；用户按预览逐条新增正确关系，再凭复核说明删除旧关系。

## 5. 数据与兼容边界

- 不增加数据库字段或迁移；
- 不改历史追溯关系；
- 不改变系统装配、种子和导入程序创建 `supporting` 复合证据的现有行为；
- 只约束 8021/后续版本中的人工新增和人工修改入口；
- 8010 不部署、不写入。

## 6. 测试

1. 策略 smoke 覆盖七种关系用途、必选对象、禁止混装和拆分预览；
2. 数据库 smoke 证明非法混装提交不会增加关系或变更日志；
3. 既有合法 `responsible` 保存、变更日志和软删除回归继续通过；
4. UI smoke 检查用途驱动字段、中文说明、禁用隐藏字段和历史混装预览；
5. 在 8021 使用 SIM 编制人做真实页面验收，确认浏览器控制台无错误；
6. 复跑语义门禁、治理工作台和治理队列相关回归。

## 7. 验收标准

- 非法组合在后端被阻断且数据库计数不变；
- 七种关系用途均有明确中文契约；
- 页面不再同时暴露所有主要对象选择器；
- 历史混装关系没有被自动修改，可看见明确拆分预览；
- 8021 页面正常，8010 未改动。
