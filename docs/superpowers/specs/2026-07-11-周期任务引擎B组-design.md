## 北极星

周期任务**自动**提醒（不靠人脑记），本月体系待办**一页看清**。日常使用中最快"有感"的改进。

## 现状（2026-07-11 核实）

- `check:reminders` 命令存在，命令行能跑，现支持 **4 类**：calibration / capa / doc_review / competency。调 `NotificationService::runReminderChecks($type)`。
- **无定时机制**——Docker 里没 cron，得手动跑。
- **无"本月待办日历页"**——有 Dashboard，但没专属视图。
- Dockerfile 基于 Alpine（composer:2.8），**busybox crond 自带**。

## B1 容器内定时（用户已拍板方案 1）

**方案**：用 Alpine 自带的 busybox crond，app 容器后台跑定时。零新增依赖。

**改动**：
1. 新增 `jewelry-qms/docker/crontab`：`0 8 * * * cd /app && php think check:reminders --type=all >> /tmp/reminders.log 2>&1`（每天 8:00 跑全量检查）
2. 改 `docker/entrypoint.sh`：启动时把 crontab 装到 `/etc/crontabs/root`、后台启 `crond -b`，再 `exec "$@"`
3. Dockerfile **不用改**（busybox crond 已在）

**成功标准**：`docker compose up` 后，连续 3 天 `/tmp/reminders.log` 里有自动执行记录（即使没人手动跑）。

**回滚**：删 crontab + entrypoint 改回（一个 commit 的事）。

## B2 扩 3 类检查

**方案**：`NotificationService::runReminderChecks` 加 3 类，照现有 4 类模式：
- **期间核查**（equipment 模块的期间核查计划到期）
- **内审年度计划节点**（audit_plan 的年度节点）
- **标准查新到期**（qms_sources / external_sources 的查新到期日）

**改动**：
1. `NotificationService`：加 3 个 private 检查方法；`runReminderChecks` 的 `type=all` 和 3 个新 type 分支调它们
2. `CheckReminders` 命令：`--type` 选项的说明加 3 个新值

**前置**：实现前核对数据库表/字段名（equipment_maintenance / audit_plan / qms_sources），避免幻觉。

**成功标准**：各造一条临期测试数据，`check:reminders --type=新type` 能检出并建通知。

## B3 本月体系待办日历页

**方案**：新 controller + view + 路由，从 Notification 模型读本月到期提醒，按日期聚合。

**改动**：
1. `app/controller/Calendar.php`：`index` 读本月 `due_date` 的通知
2. `app/view/calendar/index.html`：列表/简单表格（先不做精美日历组件，沿用 Bootstrap 风格，UI 翻新等独立小战役）
3. `route/app.php`：`calendar/index` 路由
4. 主菜单加"本月待办"入口

**依赖**：B1 定时产生的通知 + B2 新增类型的通知。

**成功标准**：打开一页能看清本月该干什么，不用翻各模块。

## 实现顺序与测试

B1（最独立）→ B2（依赖数据模型核对）→ B3（依赖 B1/B2 数据）。

每步：VM 里 `php -l` 静态语法检查 → 用户 `docker compose up --build` 重建验证 → 问题记入不好用清单。

## 风险

- B1 改 entrypoint：需 `docker compose up --build` 重建。失败回滚简单。
- B2 依赖表结构：实现前必须核对字段名（Read model/SQL），照现有 4 类模式。
- B3 新页面：UI 沿用现有 Bootstrap 风格（暂不翻新，翻新是独立小战役）。

## 不做（YAGNI）

- 不做复杂调度引擎（先满足"每日跑一次"）。
- 不做通知升级催办（多次未处理自动升级提醒频率）——放后续。
- B3 不做精美日历组件——先用列表/表格，够用。
- 不碰宿主机 cron（用户已选容器内方案）。
