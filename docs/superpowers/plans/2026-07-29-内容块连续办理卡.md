# P1-4 内容块连续办理卡实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 在文件治理工作台新增只读“按内容块连续办理”卡片，把混装、错挂、待确认和缺主链问题按内容块归并，并复用现有追溯复核及候选预填入口。

**架构：** 新增纯展示服务 `QmsTraceWorkItemService`，只读取既有内容块、关系和已路由候选，生成稳定的办理卡模型；文件治理工作台服务负责接线，ThinkPHP 模板与项目 CSS 负责响应式展示。所有按钮均为现有 GET 导航，不新增写接口、不改数据库、不自动确认。

**技术栈：** ThinkPHP 8、PHP 8.2、ThinkPHP 模板、Bootstrap 5、现有 `qms.css`、PHP smoke 测试、DOMDocument 真实模板渲染测试。

---

- [ ] **步骤 3：实现最小纯展示服务**

公开接口：

```php
public static function build(array $blocks, array $candidateTrace): array
```

实现边界：

- 从 `candidateTrace.manual_sections` 提取建议手册章节，交给 `QmsTraceSemanticGuardService::combinedLinkState()`；
- 先用 `QmsTraceRelationPolicyService::inspectExistingLink()` 判断混装；
- 非混装关系再按 `suspected_mismatch`、`pending_review` 分类；
- 候选用 `target_block_id` 归并，并按 `target_field + target_id` 与该块已确认关系比对；
- 问题用 `issue_key` 去重，输出前移除内部键；
- 卡片只生成 GET 导航 URL；
- 内容块类型中文映射：

```php

    'process_step' => '过程步骤',
```
