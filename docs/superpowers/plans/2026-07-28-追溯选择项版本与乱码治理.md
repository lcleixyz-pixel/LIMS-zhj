# 追溯选择项版本与乱码治理实施计划

> 实施边界：只治理“新增追溯关系”选择器的展示与默认范围，不删除、不重命名、不改挂既有关系，不触碰 8010。

## 目标

让复核人员默认只看到本文件候选或当前治理版本，并能看清编号、版本和状态；历史或其他版本按需展开；含 Unicode 替换字符 `�` 的外部条款不得用于新增关系，但既有历史关系继续显示。

## 任务 1：建立纯规则层

**文件**

- 修改：`jewelry-qms/app/service/QmsTraceReviewOptionService.php`
- 新增：`jewelry-qms/tests/qms_trace_review_option_governance_smoke.php`

**步骤**

1. 先写失败测试，覆盖候选优先、非候选折叠、乱码隔离、状态中文化和重复程序版本选择。
2. 增加 `govern()`，输出治理后的选项与分组统计。
3. 保留 `prioritize()` 兼容既有调用。
4. 运行纯规则测试和原候选优先测试。

## 任务 2：接入数据库元数据

**文件**

- 修改：`jewelry-qms/app/service/QmsDocumentStructureService.php`
- 修改：`jewelry-qms/tests/qms_trace_review_search_runtime_smoke.php`

**步骤**

1. 先扩展运行时测试，要求选项带版本、状态和治理统计。
2. 查询外部依据、手册章节、程序文件、记录表格的来源版本与状态。
3. 用 `govern()` 生成默认/历史分层，并将统计交给页面。
4. 验证只读加载前后追溯关系数量不变，13 条乱码条款不进入新增选择器。

## 任务 3：实现中文友好的渐进展开

**文件**

- 修改：`jewelry-qms/app/view/planning_structure/link_review.html`
- 修改或新增：相关页面烟雾测试

**步骤**

1. 先写静态页面断言，约束中文入口、历史标记、乱码警示和已选历史项保留。
2. 默认隐藏 `is_secondary` 选项，提供“显示历史/其他版本（N）”。
3. 搜索只统计当前可见范围；展开后搜索全量可用项。
4. 已经被预选或正在编辑的历史项始终保留可见。
5. 显示“已隔离 N 条疑似乱码外部条款”的非破坏性提示。

## 任务 4：回归、合并与 8021 验收

1. 运行追溯相关测试、PHP 语法检查和全套定向回归。
2. 将隔离分支以 fast-forward 方式合并回当前项目分支。
3. 在 8021 真实页面验证默认范围、历史展开、搜索、预填和乱码隔离。
4. 再次核对活动追溯关系总数未变化。
5. 在 `.team/交接箱/2026-07-28-追溯选择项版本与乱码治理/` 写入实施验收记录。

## 完成判据

- 当前候选/版本默认可见，历史版本有明确入口和中文状态。
- 13 条含 `�` 的外部条款不再允许新增选择，但既有关系未删除。
- 18 组手册重复标签、2 组记录模板版本和 1 组程序文件重复能在界面上区分。
- 无 JavaScript 时，所有非乱码选项仍在 HTML 中可选择。
- 自动化测试与 8021 页面验收均通过，8010 未触碰。
