# 法规动态复核技能包实现计划

> **执行要求：** 本计划须在 LIMS 导出契约 schema_version 1.0 固定后实施；实施时先完整读取 writing-skills，再按测试先行方式创建技能。
>
> **版本：** v0.1
>
> **对应规格：** docs/superpowers/specs/2026-07-14-法规动态监测与受控变更-design.md
>
> **依赖计划：** docs/superpowers/plans/2026-07-14-法规动态监测LIMS实现计划.md
>
> **实施边界：** 技能包只读取 LIMS 导出的脱敏 JSON 和用户明确提供的官方材料，生成复核建议；不得连接 LIMS 数据库，不得回写候选状态，不得自动修订受控文件。

**目标：** 把“官方性核验、证据充分性检查、规则初判复核、影响范围解释、人工复核提示”封装为可重复使用的中文技能包。

**架构：** ~/.agents/skills 是技能源文件唯一真源；验证脚本先校验 JSON 契约和敏感字段，再由报告构建脚本生成结构化复核包；SKILL.md 负责路由、禁止项和人工闸门；AionUi 通过重新导入副本获得可见性，不把应用副本当作真源。

**技术栈：** Markdown、Python 3 标准库、unittest、JSON Schema 风格的显式校验、Codex/Claude 技能目录约定。

## 1. 固定输入输出契约

输入文件必须：

- schema_version 等于 1.0。
- 含 candidate、source、impact_assessment、review 字段。
- impact_assessment 固定含六个影响键：cma_scope_mark、qms_documents、personnel_authorization、equipment_calibration、lims_rules、training。
- 不含 password、cookie、authorization、dsn、mobile、id_card 等禁用键。
- source.canonical_url 必须是 HTTPS。
- evidence 不足时允许继续生成报告，但必须降级为“证据不足，需人工核实”，不得编造结论。

输出复核包固定包含：

1. 输入完整性。
2. 官方来源核验。
3. 规则初判复核。
4. 六类影响解释。
5. 初步影响范围。
6. 人工确认问题。
7. 禁止自动执行事项。
8. 证据与时间戳。

输出只能给出候选建议，不得声称已经完成 CMA/CNAS 合规判定，不得声称已经更新 LIMS。

**先写失败测试：**

    python3 -m unittest "$HOME/.agents/skills/qms-regulatory-change-monitor/tests/test_build_review_packet.py" -v

预期：FAIL。

**最小实现：**

命令接口：

    python3 scripts/build_review_packet.py INPUT_JSON --output OUTPUT_MD

行为：

- 先调用同目录 validate_candidate.py。
- 使用模板逐节渲染，不发起网络请求，不调用大模型 API。
- 官方来源核验只依据输入中的 URL、source_key 和 evidence；无法确认则降级。
- 六类影响逐项输出 conclusion、evidence、rule_ids、confidence 和人工问题。
- 成功退出 0；校验失败沿用校验器退出码；输出路径不可覆盖输入文件。
