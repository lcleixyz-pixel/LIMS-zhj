# 法规动态监测 LIMS 实现计划

> **执行要求：** 实施时使用 writing-plans 产出的本计划，并按 executing-plans 或 subagent-driven-development 逐任务执行；每项任务均先写失败测试，再写最小实现。
>
> **版本：** v0.1
>
> **对应规格：** docs/superpowers/specs/2026-07-14-法规动态监测与受控变更-design.md
>
> **实施边界：** 本计划只增强 jewelry-qms，不替换现有 LIMS；只把经人工确认的候选项晋升为现有 qms_external_change_events，不自动修订受控文件，不自动创建整改、培训或 CAPA，不部署到云端。

**目标：** 建立“官方来源月度检查 → 候选清单 → 规则初判 → 人工确认 → 受控变更事件”的可审计闭环，并提供脱敏 JSON 给复核技能包。

**架构：** 采集层只读取配置白名单中的官方来源；候选层以稳定指纹去重并保留版本；影响层使用确定性规则生成六类影响初判；审批层沿用现有外部变更事件；导出层只输出候选证据和初判，不携带凭据及内部敏感信息。所有测试使用本地夹具，禁止依赖实时网络。

**技术栈：** ThinkPHP 8、PHP 8、MySQL 8.4、cURL、DOMDocument、Docker Compose、现有 RBAC/审计/通知/命令框架。

## 1. 固定契约

### 1.1 状态枚举

- 运行状态：running、completed、partial_failed、failed。
- 候选复核状态：pending、confirmed_applicable、confirmed_not_applicable、deferred、promoted。
- 来源模式：html_list、manual_only。
- 人工确认前，候选不得写入 qms_external_change_events。
- promoted 候选必须记录唯一 promoted_event_id；重复晋升返回原事件，不重复建单。

### 1.2 六类影响键

RegulatoryImpactService 必须始终返回以下六个键：

1. cma_scope_mark
2. qms_documents
3. personnel_authorization
4. equipment_calibration
5. lims_rules
6. training

每个键包含 conclusion、evidence、rule_ids、confidence。conclusion 只能为 likely、possible、no_match。no_match 仅表示“规则未命中”，不得展示为“不适用”。

### 1.3 候选版本与去重

- source_item_key：优先取规范化文号；无文号时取规范化 canonical_url。
- content_hash：由标题、文号、发布日期、正文摘要、附件元数据组成，不含抓取时间。
- 唯一键：company_id + source_key + source_item_key + content_hash。
- 同一内容重复抓取只更新 last_seen_at。
- 同一 source_item_key 内容变化时新增候选，并用 supersedes_candidate_id 指向上一版本。

### 1.4 导出契约

- schema_version 固定为 1.0。
- 仅允许导出来源、证据、候选状态、六类影响、规则版本和人工复核结论。
- 禁止导出密码、Cookie、Authorization、数据库连接串、人员手机号、证件号。
- 技能包不可回写数据库。
