# 内容引擎↔运行平台 接口契约 v0.9(草案)

> 状态:**草案**。凡标【平台侧核对】处为内容引擎侧依据数据模型文档所做推断,需 Claude Code 侧对照实际表结构确认;双侧确认+青禾 v1.21a 产物 dry-run 零发现项后,本契约转正 v1.0。
> 存放:两仓各存一份,同步升版(契约是第三条版本线);任一侧改接口,契约先升版、双侧确认后实施——改接口不升契约=双侧金样应飘红。

## 〇、双方与交接物

- **甲方(供方)**:技能套装(内容引擎),基线版本 v1.21a;
- **乙方(需方)**:jewelry-qms 平台,消费入口 QmsPreimportPackage 命令(dry-run / apply);
- **交接物**:预导入包(一个目录/压缩包);**打包必须使用正斜杠路径分隔符**(历史教训:v1.8 反斜杠事故)。

## 一、字段映射表

| 套装对象(md 世界) | 平台对象(数据库世界)【平台侧核对表/字段名】 | 映射说明 |
|---|---|---|
| 书架条目(依据代号/全名/版本/效力等级/核对状态) | qms_sources | 代号为业务主键;版本年入版本字段;"待核"状态需平台有对应枚举 |
| K 卡(K-xx:来源条款/原子要求/改写级别/适用体系/效力) | qms_clauses | K 编号与"来源文件+条款号"双键;适用体系(CMA/CNAS/both)需字段承载 |
| 要素/主题(人机料法环测+通用管理) | qms_elements | 主题名为键;底稿版本号随行 |
| 手册章节(§5 产物,骨架 v1.1 章节树) | qms_manual_sections + documents | 章节号+标题+正文块 |
| 程序文件(§6 产物,CX-xx 编号) | documents(类型=程序文件) | CX 编号为业务主键 |
| 记录表格(QR-xx,7 列记录模板) | record_form_templates | QR 编号为业务主键;7 列结构→模板 schema【平台侧核对 RecordFormRebuildSchema 的列约定】 |
| 回链 [K-xx](句级出处) | qms_document_blocks + block_links | 正文按块拆分,每块携带其 K 引用集合;**发布展示层不显示回链,举证视图显示**(对应工作版/发布版双轨) |

## 二、预导入包格式规范

```
preimport-package-vX.Y/
├── manifest.json          # 包元数据(见下)
├── 手册/                  # 发布形态手册(骨架 v1.1 结构)md
├── 程序/                  # CX-xx 程序文件 md
├── 记录模板/              # QR-xx 模板 md(7 列)
├── 结构化块/              # 每文件的块拆分+块级K引用(json 或 md 表)【平台侧核对现行块格式】
├── 追溯矩阵.md            # K-xx ↔ 条款 ↔ 要素 ↔ 文件落点(29 要素全覆盖)
├── 事实对照表.md
├── F卡落位表.md
└── 底稿快照/              # 工作版底稿(带回链),平台存档作举证源,不进发布展示
```

manifest.json 必含:`suite_version`(如 1.21a)、`contract_version`、`package_version`、`要素清单及各自底稿版本`、`语义签字清单(主题|签字人|日期)`、`机判结果摘要`、`facts_hash`(事实对照表校验和)。**语义签字清单不全的主题,乙方 apply 必须阻断**(与平台 SIMULATED_COMPLETION 阻断同级)。

编码 UTF-8;文件名不含反斜杠与全角斜杠;包内禁止残留 {{ }}、⟦⟧、[K-(发布件)——甲方发包前必须通过:validate → 语义签 → 三闸 → skeleton_check;乙方收包必跑 dry-run,发现项>0 不得 apply。

## 三、事实源移交规则(铁律)

1. **构建期**(底稿→总装→发包前):套装总台账为唯一事实源;
2. **移交点**:QmsPreimportPackage **apply 成功返回**的时刻;
3. **运行期**(apply 后):平台数据库为唯一事实源;套装侧任何底稿升版**不生效**,直至新包重新过闸;
4. 移交事件双侧记账:甲方版本台账记"已移交至平台 rev-X",乙方 document_revisions 记来源包号——**两条账通过包号互认**;
5. 争议裁决:账不一致时,以最后一次 apply 成功的包内容为准,双侧回改台账。

## 四、信号双向协议

| 信号 | 方向 | 载体 | 乙方/甲方动作 |
|---|---|---|---|
| 依据换版/废止(冻结) | 甲→乙 | intake_check --json 输出 + known-revocations 更新 | 乙方将对应 qms_sources 置"换版待响应",关联文件标"现行有效存疑"【平台侧核对状态机】 |
| 候选修订包就绪(解冻) | 甲→乙 | 新预导入包(manifest 注明响应的换版事件) | 走 dry-run→人签→apply,解除存疑标记 |
| 运行异常(质控失败/投诉/记录缺失) | 乙→甲 | 导出 json(事件类型/关联要素/证据引用)【平台侧核对导出能力】 | 甲方开 CAPA 归因;涉文件缺陷→底稿升版→新包 |
| 运行证据(内审取数) | 乙→甲 | 记录实例导出(按要素/周期筛选) | 甲方内审核查表消费,出运行层结论 |

## 五、契约治理

- 版本线:v0.9 草案→双侧确认+青禾 dry-run 零发现→v1.0;此后任何字段/格式/规则变更走 v1.x,变更行写明"哪一侧发起、为何、双侧确认日期";
- 双侧金样:甲方金样第 9 道(待建):按本契约§二打一个青禾最小包并校验 manifest 完整性;乙方对应固定夹具包 dry-run 回归【平台侧建】;
- 本契约不含商业条款,只管技术交接。
