## 二、预导入包格式规范(按平台实际 CSV 格式重写)

预导入包 = 一个目录,含以下 **6 个必备 CSV + 1 个 manifest**(`QmsPreimportPackageService::REQUIRED_FILES`):

```
preimport-package-vX.Y/
├── preimport_manifest.json            # 包元数据(必含 counts,见下)
├── documents_preimport.csv            # 候选程序/手册文件
├── structured_documents_preimport.csv # 结构化文件主记录
├── record_form_templates_preimport.csv# 记录模板 + field_schema_json
├── traceability_matrix_preimport.csv  # 追溯矩阵(条款↔要素↔文件)
├── manual_blocks_preimport.csv        # 手册块拆分 + 块级链接
├── external_sources_preimport.csv     # 外部依据(书架)
└── draft_snapshot/                    # 可选:工作版 md(含 [K-xx] 回链),平台识别+归档接收不写库;发布件禁 [K-xx],此为工作版例外(G3)
```

可选附带(人工评审/发布演练等子包,各有独立 manifest,本契约不展开):`manual_clause_review_checklist.csv`、`record_template_review_checklist.csv`、`attachment_form_disposition.csv`、`preapply_gate_register.csv` 等,经命令对应 `--review-dir`/`--release-plan-dir` 等选项接入。

### 2.1 `preimport_manifest.json`

`checkManifestCounts` 只强校验 `counts`,但甲方应填全以下字段:

```json
{
  "package_type": "lims_preimport_package",
  "suite_version": "1.21a",
  "contract_version": "v1.0",
  "package_version": "<包版本>",
  "counts": {
    "documents": <整数,须=documents_preimport.csv 数据行数>,
    "structured_documents": <同上>,
    "record_form_templates": <同上>,
    "traceability_rows": <同上,对应 traceability_matrix>,
    "manual_blocks": <同上>,
    "external_sources": <同上>
  },
  "semantic_signatures": [ {"topic":"人员","signer":"<人>","date":"<YYYY-MM-DD>"} ],
  "machine_check_summary": "<机判结果摘要>",
  "facts_hash": "<事实对照表校验和>",
  "guardrails": ["..."]
}
```

**counts 与各 CSV 实际行数必须一致**(不一致→`count_mismatch_*` 高严重度发现项)。**语义签字清单不全的主题,乙方 apply 必须阻断**(与平台 `SIMULATED_COMPLETION` 阻断同级)。

### 2.2 各 CSV 列约定(导入强校验项)

- **documents_preimport.csv**:`doc_number`(非空,空→`blank_document_code`)、`action`(`create` 或 `reference_existing_current`;后者会查库反查既有文件)、`title`、`document_type`、`version`、`owner_position`、`scope`。
- **record_form_templates_preimport.csv**:`doc_number`、`name`、`module`、`field_schema_json`(**必须为合法 JSON 数组**,每元素 `{key,label,type,required,[options],[columns]}`;**必须含 7 个 `REQUIRED_SCHEMA_KEYS`**:`record_number/record_name/applicable_clause/related_procedure/responsible_position/trigger_time/correction_rule`;缺失→`invalid_record_schema`/`record_schema_missing_required_keys`)。
- **traceability_matrix_preimport.csv**:`clause`、`element`、`source_clause`、`human_review_required`(必须=`yes`)、`relation_confidence`(必须=`review_required`)。
- **manual_blocks_preimport.csv**:`stable_key`、`doc_number`、`block_type`、`link_confidence`(必须=`review_required`)。
- **structured_documents_preimport.csv**:`doc_number`、`title`、`document_role`、`version`、`markdown_path`(基础 dry-run 仅计数,深度校验在 stage2)。
- **external_sources_preimport.csv**:`source_code`、`name`、`version`、`status`、`freshness_status`。

> 包内禁止残留 `{{ }}`、`⟦⟧`、`[K-xx]`(发布件);甲方发包前必须通过套装侧 `:validate → 语义签 → 三闸 → skeleton_check`;乙方收包必跑 dry-run,发现项>0 不得 apply。

> v0.9→v1.0 变更:整段由"md 目录树 + manifest.json"重写为平台实际"6 CSV + manifest"。甲方套装产物发包前须经 `scripts/qms_lims_preimport_build.py` 或等价转换产出该 CSV 包。

## 三、事实源移交规则(铁律,未变)

1. **构建期**(底稿→总装→发包前):套装总台账为唯一事实源;
2. **移交点**:`qms:preimport-package --apply` 成功返回的时刻(`--apply-rehearsal` 不移交,仅演练);
3. **运行期**(apply 后):平台数据库为唯一事实源;套装侧任何底稿升版**不生效**,直至新包重新过闸;
4. 移交事件双侧记账:甲方版本台账记"已移交至平台 rev-X",乙方 `document_revisions` 记来源包号——**两条账通过包号互认**;
5. 争议裁决:账不一致时,以最后一次 apply 成功的包内容为准,双侧回改台账。

## 四、信号双向协议

| 信号 | 方向 | 载体 | 乙方/甲方动作 |
|---|---|---|---|
| 依据换版/废止(冻结) | 甲→乙 | `intake_check --json` 输出 + `known-revocations` 更新 | 乙方在 `qms_external_change_events` 建 `status=registered` 事件(old/new_source_id、effective_date),关联 `qms_sources.freshness_status` 置 `due`;关联块经 `qms_document_block_links.confidence=review_required` 标记复核 |
| 候选修订包就绪(解冻) | 甲→乙 | 新预导入包(manifest 注明响应的换版事件) | 走 dry-run→人签→apply,事件 `status` 转 `closed`、`freshness_status` 复核后回 `current` |
| 运行异常(质控失败/投诉/记录缺失) | 乙→甲 | **`qms:export-runtime-evidence --json`**(待平台侧补建,见下)导出:事件类型/关联要素(`element_id`)/证据引用 | 甲方开 CAPA 归因;涉文件缺陷→底稿升版→新包 |
| 运行证据(内审取数) | 乙→甲 | 记录实例导出(按要素/周期筛选) | 甲方内审核查表消费,出运行层结论 |

> v0.9→v1.0 变更:换版信号改用平台真实枚举(`qms_external_change_events.status`+`freshness_status=due`),弃用 v0.9 的"换版待响应/现行有效存疑"非枚举表述。

**⑥ 运行异常导出能力(平台侧已补建 2026-07-09)**:原仅有 `/capa/exportCsv`、`/audit_finding/exportCsv`(CSV)与 `compliance:assess` 命令,无契约所需 json 导出。**现已补建 `qms:export-runtime-evidence --json`**(`app/command/QmsExportRuntimeEvidence.php` + 注册 console.php):从 `nonconformities`/`customer_complaints`/`capas`/`compliance_check_results`/`audit_findings` 聚合,导出 `{事件类型, 关联要素(element_id/element_key), 证据引用}` JSON。要素关联按真实模型:`compliance_check_results` 经 `compliance_checks.element_key` 直挂、`audit_findings` 经 clause→`qms_clauses`→`qms_element_clause_links`→`qms_elements` 三跳;NC/投诉/CAPA 无要素列归 `_unlinked` 桶(人工归因)。导出 schema 单列于《运行证据导出规范》(`参考/G1运行证据导出/运行证据导出规范.md`),种子实测通过。
