# 运行证据导出规范(qms:export-runtime-evidence)

> 对应《接口契约 v1.0 正版》§四 ⑥ + 附录A 缺口 **G1(2026-07-09 已补建)**。
> 平台新增命令 `qms:export-runtime-evidence`,从运行期表按要素聚合导出 JSON,供甲方 CAPA 归因入口消费。

## 命令

```bash
php think qms:export-runtime-evidence [--element <key>] [--type <type>] [--company <id>] [--json-out <path>]
```

不给 `--json-out` 则 JSON 打印到 stdout。过滤项均可选。

- `--element`:按 `element_key` 过滤(只导该要素相关事件)。
- `--type`:事件类型过滤 `nonconformity | customer_complaint | capa | compliance_check_failure | audit_finding`。
- `--company`:按 `company_id` 过滤;不给则取 `config qms.company_id`,空则全量。
  - **audit_findings 无 company_id 列**,该类型不参与公司过滤(导出全部 soft_delete=0)。

## 数据源与要素关联(真实模型,非契约理想化)

| 事件类型 | 源表 | 要素关联路径 | element 可空 |
|---|---|---|---|
| compliance_check_failure | compliance_check_results → compliance_checks | `compliance_checks.element_key` → `qms_elements.key`(直挂) | 否(有则挂) |
| audit_finding | audit_findings | `audit_findings.clause` → `qms_clauses.clause_number` → `qms_element_clause_links.clause_id` → `qms_elements`(三跳 join) | 是(条款未挂要素则空) |
| nonconformity | nonconformities | 无要素列(经 `capa_id` 链可人工归因) | 是→`_unlinked` |
| customer_complaint | customer_complaints | 无要素列 | 是→`_unlinked` |
| capa | capas | 无要素列(`source_type`/`source_id` 指向来源事件) | 是→`_unlinked` |

> 契约§四原文"按 element_id 聚合"为理想化表述;实际仅 compliance_check_results(直挂)与 audit_findings(经条款三跳)能机判挂要素,NC/投诉/CAPA 无要素列,归入 `_unlinked` 桶由甲方人工归因。这是数据模型现状,非命令缺陷。

## JSON Schema

```json
{
  "status": "passed",
  "generated_at": "YYYY-MM-DD HH:MM:SS",
  "scope": {
    "company_id": "<string|null>",
    "element_filter": "<string|null>",
    "type_filter": "<string|null>"
  },
  "summary": {
    "total_events": <int>,
    "by_type": { "<event_type>": <int>, ... },
    "elements_with_events": <int>,
    "unlinked_events": <int>
  },
  "events": [
    {
      "event_type": "nonconformity|customer_complaint|capa|compliance_check_failure|audit_finding",
      "element_id": "<qms_elements.id | null>",
      "element_key": "<qms_elements.key | null>",
      "clause": "<clause_number | null>",
      "evidence": {
        "id": "<id>",
        "number": "<业务编号(nc_number/capa_number/...);compliance_check_failure 用 check_code>",
        "...": "类型相关证据字段(description/status/severity/capa_id/fail_items/checked_at 等)"
      }
    }
  ],
  "by_element": {
    "<element_key>": [ <event...> ],
    "_unlinked": [ <event...> ]
  }
}
```

## 实测(2026-07-09,seed-company 种子)

种子:1 要素(人员/6.2)+ 1 合规检查失败 + 1 NC + 1 投诉 + 1 CAPA + 1 审核发现。

| 测试 | 结果 |
|---|---|
| 全量导出 | 5 事件;人员桶 2(compliance_check_failure+audit_finding,均 element_id=el-ry/clause=6.2);_unlinked 3(NC/投诉/CAPA)✅ |
| audit_finding 要素解析 | 经 clause→qms_clauses→links→qms_elements 三跳命中"人员" ✅ |
| `--element 人员` | 2 事件,0 unlinked ✅ |
| `--type capa` | 1 事件,1 unlinked ✅ |

## 遗留/可选

- audit_findings 无 company_id,公司隔离不覆盖该类型(可经 audit_schedules 关联补,远期)。
- NC/投诉/CAPA 无要素列;若需机判挂要素,需平台给这些表加 element_key/clause 列(数据模型改动,非本命令范畴)。
- 导出 schema 可按甲方 CAPA 入口的实际字段需求微调(本版为通用最小集)。
