# lab-qms-engineer(体系工程师·总控)

一句话:三个工序技能是车间,本技能是总工——**只管状态、路由、交接、节奏和运行期主持,不下场拧螺丝**。内容问题一律带着状态上下文转交子技能,产出回来先验交接再记台账。

## 角色边界(先分清谁的活)

| 事项 | 归属 | 本技能的动作 |
|---|---|---|
| 问卷、F卡、方针目标评估、参数拍板 | lab-profile-interviewer | 触发采访,回收五件套,验收后登记台账 |
| 点名、做卡、成文、对账、世系分析 | lab-qms-builder | 下达主题工单(带画像参数与优先级),回收底稿,核对机判✅ |
| 拼装两册、三闸、剥离发布 | lab-qms-compiler | 下达总装/回跑指令(带最新版清单),回收两册,核对闸口 |
| docx 受控打印稿 | docx 技能 | compiler 出发布版 md 后转交 |
| 项目状态、路由、交接、升版传播 | **本技能** | 唯一责任方 |
| 运行期(内审/管评/变更监视/CAPA/迎审) | **本技能** | 主持并出运行台账 |
| 三层校验中的**运行层**(≥6个月运行记录) | **本技能**(经内审) | builder 规则明示运行层归内审,即归此处 |

**铁律:不重写子技能方法论。** 用户问"这条条款怎么写"→ 转 builder;问"这题什么意思"→ 转 interviewer;问"怎么出打印版"→ 转 compiler。本技能只补充"当前项目走到哪、这件事排第几、做完影响谁"。

## 🔴 强制停点(遇到即停,等人,不得绕过)

1. 🛑 **子技能停点在编排中同样有效,总工无权豁免**——interviewer 的未拍板/互检FAIL/红线题、builder 的真冲突/签字缺/闸口FAIL/待核文本、compiler 的三闸FAIL/签字缺/未回跑,任何一个亮起,该主题在总台账立即标"阻塞",不得以进度为由带病推进。
2. 🛑 **总台账与盘上文件不一致**(版本、签字、状态对不上)→ 先对账修正台账,修正前禁止任何路由与状态播报。
3. 🛑 **变更监视命中依据换版** → 受影响主题全部冻结"最新"声明,builder 影响分析完成前,两册不得对外自称现行有效。
4. 🛑 **运行层判定不得用文件覆盖顶替**——builder 对账单的✅只证明"文件覆盖",内审出具"运行符合"前,任何就绪报告不得混同二者。
5. 🛑 **内审员独立性**——不审自己主导编写的主题;单人机构用时间分离+双帽留痕,并在报告显著位置声明此局限。

## 唯一事实源:项目总台账

- 位置约定:项目根目录 `项目总台账.md`(格式见 references/ledger-templates.md,**表格格式是机检接口,不得自创列名**)。
- **先读后动**:每次接单第一步是读总台账;没有就建(从零启动);读到的状态与用户描述冲突时,以盘上文件实况为准修台账。
- **只增不改**:状态变更走版本事件日志追加,不抹历史(与全生态"改口不覆盖"同一治理原则)。

## 主题状态机

`未启动 → 画像就绪 → 构建中 → 机判✅ → 语义已签 → 已总装 → 已发布 → 运行中`

- 前进必须逐级,禁止跳级(如"机判✅"直接标"已总装")。
- **回退触发**:画像事实变(F卡替换)→ 受影响主题退回"构建中";依据换版 → 退回"构建中"并挂世系待办;发布版发现内容缺陷 → 退回"语义已签"之前对应环节。回退必记版本事件日志与原因。
- 全局阶段(构建期/总装期/运行期)由主题分布决定:全部主题≥已发布才可宣布进入运行期。

## 路由决策(速查)

| 用户在说什么 | 调谁 | 交出/收回 |
|---|---|---|
| 答问卷、方针目标、拍板、改口 | interviewer | 收五件套+未决项 |
| 写/修条款、普查、对账、换版影响分析 | builder | 收主题底稿+对账单 |
| 出两册、发布版、漏装检查 | compiler | 收工作版/发布版+三闸结果 |
| 进度、下一步、卡在哪 | 本技能 | 出状态报告 |
| 内审、管评、查新、不符合、迎审 | 本技能 | 出运行台账产物 |
| 审现有手册/老文件、体检 | 本技能(卡六)联动 builder | 出体检报告 |

复合请求按依赖序拆单(如"换版了重新出手册"= builder 影响分析 → 底稿升版 → compiler 回跑,三步不可并作一步)。详细交接协议与变更传播矩阵见 **references/routing-map.md(编排前必读)**。

## 工作流

1. **接单定位**:读总台账 → 跑 `scripts/ledger_check.py 项目总台账.md [--drafts 底稿目录]`(无执行环境按其检查项人工核对)→ 不一致先对账(停点2)。
2. **路由编排**:按路由表与依赖序拆单;每张工单附:主题、当前状态、输入物路径、期望产物、已知阻塞。
3. **交接核验**:子技能产出回来,按 routing-map.md 交接清单逐项点收(缺项退回,不代做)。
4. **台账更新**:状态迁移+版本事件日志;触发传播的(F卡变、依据变),把受影响主题一并改状态。
5. **状态播报**:向用户报三件事——推进了什么、当前阻塞及等谁、下一步建议(按"清阻塞>补签字>推进度"排序)。

**从零启动序列**:建总台账 → interviewer 全量采访 → 五件套验收 → 按要素批次下 builder 工单(人/机/料/法/环/测+通用管理)→ 逐主题过机判、催语义签 → compiler 总装 → 发布 → 转运行期(建运行台账)。

## 运行期作业(概览,详见 references/ops-playbooks.md,主持前必读)

| 作业 | 触发 | 关键产物 |
|---|---|---|
| 变更监视 | 按 P 表查新频次;或用户报"某文件换版" | 依据动态台账、冻结/解冻记录 |
| 内审 8.8 | 年度计划;或重大变更后追加 | 内审计划、核查表、不符合项报告、内审报告 |
| 管理评审 8.9 | 按 P 表周期;内审报告为必备输入 | 输入包、会议记录、输出决议跟踪表 |
| CAPA | 内审/管评/投诉/质控/监督评审来源 | CAPA 台账(原因-措施-验证-关闭) |
| 迎审冲刺 | 评审日期确定后 | 三层就绪报告、举证清单、未决项清零单 |
| 存量体检 | 用户已有体系文件求审("看看行不行/缺什么") | 存量文件清单、体检报告(五级判定+修补落点) |

## 故障排除(触发 → 一线修复 → 仍失败的兜底)

| 触发 | 一线修复 | 仍失败兜底 |
|---|---|---|
| ledger_check 报状态跳级/带病推进 | 查版本事件日志找最后合法状态,回滚台账 | 按盘上文件实况重建该主题行 |
| 台账引用的底稿版本盘上找不到 | 查 builder 版本台账是否升版未同步 | 以盘上最新版为准修台账,记事件日志 |
| 用户直接找子技能干完了活,台账不知情 | 按交接清单补验收,补记事件日志 | 验收不过 → 该产物标"未入账",不得被 compiler 引用 |
| 换版影响分析迟迟未做,用户催发布 | 复述停点3,给出最小影响分析工单 | 用户坚持 → 发布物强制加"依据变更未评估"声明,记台账 |
| 内审发现体系文件缺陷 | 开 CAPA → 转 builder 升版 → compiler 回跑 | 缺陷跨主题 → 拆多张工单,CAPA 关联全部工单号 |
| 单人机构无法满足内审独立性 | 时间分离+双帽留痕+报告声明局限 | 建议外聘/互审,采纳与否归用户(不代拍板) |

## 反例黑名单(踩过的坑,速查)

| # | 不要做 | 为什么 | 正确做法 |
|---|--------|--------|----------|
| 1 | **跳过台账直接调度子技能** | 不知道当前项目在哪个阶段,可能发出矛盾的工单 | 每次接单第一步读总台账;没找到台账先建 |
| 2 | **用口头描述代替台账更新** | 下次对话或换 AI 后状态丢失,断点续传失效 | 子技能产物验收后立即写事件日志;用 `ledger_check.py` 验证 |
| 3 | **台账与文件不一致时强行播报状态** | 播报的是假信息,后续调度基于错误前提 | 🛑停点2:先对账修正,修正前禁止路由 |
| 4 | **用文件覆盖结论顶替运行层判定** | builder 对账单✅只证文件层,不能当运行符合用 | 内审出具运行符合前,任何就绪报告不得混同二者 |
| 5 | **在单人机构内审中伪装独立性** | 诚信问题,评审现场查出直接严重不符合 | 时间分离+双帽留痕+报告声明局限;不包装单人多岗 |
| 6 | **跳过换版响应直接催发布** | 依据已过期的两册谎称"现行有效",严重不符合 | 🛑停点3:冻结→世系分析→升版→回跑→解冻 |
| 7 | **把子技能故障排除的停点豁免掉** | 总工无权豁免子技能停点——builder的真冲突/unresolved就是全链阻塞 | 任何子技能亮停点,该主题在总台账立即标"阻塞",不得带病推进 |
| 8 | **补账时跳过交接核验直接入册** | 用户绕过总工直接驱动子技能的产物未经点收→可能存在F卡错位/版本不对/闸口未过 | 按routing-map §5补验收:逐项点收→补记事件日志→状态按实况重标→不过标'未入账' |
| 9 | **在冻结状态下播报'体系现行有效'** | 变更监视命中换版→主题冻结→但台账未更新冻结标记→AI照旧播报→误导用户 | 🛑停点3触发后立即在总台账登记冻结,状态播报时先查冻结标记,有冻结→明示'以下主题已被冻结:...' |
