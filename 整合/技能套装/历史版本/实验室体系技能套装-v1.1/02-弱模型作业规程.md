# 弱模型作业规程(能力一般的模型,严格照此执行)

这份规程的目的:把"需要聪明才能做对的事"变成"照抄流程就能做对的事"。模型越弱,越要一步不落。

## 规程一:三读开工

每接一个新任务,按顺序读三样东西,读完才动手:

1. `项目总台账.md`——知道现在干到哪了;
2. 本次任务对应技能的 `SKILL.md`——知道方法和禁区;
3. 该技能 `references/` 里对应的模板——知道产出长什么样。

❌ 反例:用户说"写设备条款",直接开写。
✅ 正例:先读台账(发现设备主题状态是"未启动",但画像里设备清单已确认)→ 读 builder 的 SKILL.md → 读 templates.md 的底稿章节结构 → 再动笔。

## 规程二:复述确认

动手前,用三句话向用户复述并**等确认**:

> "我理解你要:____。我的输入是:____(列文件名和版本)。我将产出:____(文件名+大致结构)。对吗?"

理解错了,这一步就拦住了,省得白干。用户说"对"之后才开工。

## 规程三:小步快走

- 一次回复只做一道工序的一个主题。"把六个要素都写了"要拆成六次,每次做完给用户过目。
- 单个主题内容太长时,先出**目录和骨架**给用户确认,再逐节填肉。
- 绝不在一次回复里同时"写底稿+装手册"——那是两个技能的活,中间必须过交接点收。

## 规程四:模板即牢笼

产出必须严格套用 references/ 里的模板结构:**章节一个不少、列名一个不改、空值统一写 `-`**。模板没有的章节不要发明;觉得模板不够用,向用户提出,不擅自加。

为什么这么死板:模板结构是检查脚本的接口,自创格式=机器检查全部失效。

## 规程五:产出后自检(文末必附)

每次产出文件的末尾,附这张表(照抄表头,逐行如实填):

```markdown
## 自检表
| 检查项 | 结果 | 说明 |
|---|---|---|
| 对照本技能"🔴强制停点",是否触发任何一条 | 否/是(第x条) | 触发则本产出标"暂停待人" |
| 正文每句是否带出处编号 | 是/部分 | 没带的句子列在这里 |
| 是否存在我编造/推测的内容 | 无/有 | 有则逐条列出并标"待核" |
| 用户未回答处是否留空(而非填了默认值) | 是/否 | |
| 版本号是否升级、旧版是否保留 | 是/否 | |
| 检查脚本 | 已运行/人工核对/未做 | 人工核对时逐项列结果 |
```

## 规程六:遇到这五种情况,立刻停下问人

1. 两份标准对同一件事要求打架(疑似"真冲突");
2. 需要拍板的数字或方案(周期、频次、方针措辞);
3. 台账记录和文件实际情况对不上;
4. 用户的要求和技能铁律冲突(如"别管出处了直接写");
5. 找不到官方原文。

停下时的标准话术:"这里需要你决定/提供____,因为____。在此之前我先做____(不受影响的部分)。"

## 规程七:上下文省着用

- 不要一次把所有标准全文读进对话;按当前主题需要哪份读哪份。
- 对话太长感觉"记不清前面"时,主动提议:"建议把当前进度记入总台账后开新对话,新对话我会从台账续上。"——台账就是为断点续传设计的。
