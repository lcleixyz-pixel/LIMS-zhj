# 实验室体系智能生态 · 项目总体规划 v1.2(2026-07-21)

> 本规划是全局纲领文件,建议两个仓库各存一份、同步升版。修订走版本行,不覆盖。

## 一、一句话愿景

给中小检验检测实验室一套"从建体系到过评审再到日常运行"的智能系统:**AI 写章程、平台管执行、机器守闸口、人只做拍板和签字**。

## 三、全生命周期数据流(一个机构从进门到过评审)

```
画像采访 → 底稿构建 → 总装两册 → 【预导入闸】 → 平台受控发布 → 日常运行 → 迎审
(套装记账)………………………………↑事实源移交点↓………………(平台记账)…………
                                          运行证据回流:平台记录 → 内审核查/迎审举证
                                          变更信号双向:依据换版冻结 ⇄ 平台异常开CAPA
```

**唯一事实源移交规则(铁律)**:构建期以套装总台账为准;预导入 apply 过闸那一刻,记账权移交平台数据库;之后套装侧任何升版,必须重新过闸才能生效——**防止两本账各说各话**。

## 四、接口契约 v1.0(✅ 已交付,阶段 1 关闭)

正版文件:`整合/接口契约-v1.0正版.md`(双仓同版)。四块内容均已落地:

1. **字段映射表**:6 处平台侧核对已对照 jewelry-qms 实际表结构逐条坐实;
2. **预导入包格式规范**:已按平台实际格式重写为 **6 CSV + `preimport_manifest.json`**(v0.9 的 md 目录树方案作废);
3. **事实源移交规则**(写死,未变);
4. **信号双向协议**:依据换版冻结→`qms_sources` 状态;平台记录异常→套装 CAPA 归因入口。

契约治理:任何一侧改接口,契约先升版、双侧确认后实施——契约是第三条版本线。改接口不升契约=双侧金样应飘红。

## 六、跨项目治理(把已验证的纪律升格为生态规矩)

1. **版本三线**:套装线(v1.x)、平台线(CHANGELOG/变更台账/document_revisions,日常真值为 `docs/变更台账.md`)、契约线(v1.0 正版)——各自记账,烧号必留行;测试工装挂套装线附属。
2. **金样制度推广**:套装 8 道金样已证明价值;平台侧回归已建(预导入 dry-run 固定夹具包+wave 专项 smoke,现约 122 条、75 条可重复自动回归),契约变更必跑双侧金样。
3. **红线全生态通行**:不代拍板、机判≠人签、模拟完成不得冒充真实执行(平台已内建 SIMULATED_COMPLETION 阻断,与套装停点同源)、诚信零容忍(P4 画像每三轮必考);**新增:联调/演练一律走沙箱栈,现用 8010 未授权不写**(2026-07-21 G-1 违规已整改并留痕,教训升格为规矩)。
4. **数据安全**:机构真实数据只进平台(本地部署);喂给公网 AI 的内容脱敏;弱模型生产线优先本地模型;版权拆分已执行(标准原件移出主仓至 private 归档)。
5. **知识资产维护**:依据清单库每季度对官方清单核对一次,核实基准日留痕——已写进 v1.21 规则,升格为生态级。
6. **可选件接入模式**(新增,以 DocuSeal 为模板):外部组件一律 compose profile 可选、默认关、配置开关、自建汉化镜像钉版本、专项 smoke 护栏——后续 ONLYOFFICE、内嵌 Copilot 等照此办理。
